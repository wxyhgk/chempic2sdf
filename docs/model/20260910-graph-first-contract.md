# 2026-09-10 方向决定：以分子图为目标，文字和几何分别提供证据

状态：职责与依赖已明确；训练标签修订接口已实现；模型架构与默认生产流程未改。

## 决定

不采用“必须先把文字全部读对，才开始识别键”的硬串行前提。
不将逐笔画复刻 SVG 作为 chempic2sdf 的最终任务。SVG 仍可用于渲染、标注和可视化。
最终目标是原子身份、键类型与连接关系正确的分子图/SDF。

保留现有视觉、结构和 OCR 组件，不重新引入 MoE，不直接替换为已验证落后的历史
独立文字 checkpoint。是否共享骨干、使用独立检测头或现成 OCR，是后续实现选择。

## 当前代码实际做了什么

`chemvector/inference/infer_direct_atom_pair_bond.py:main` 的实际依赖为：

```text
原图 → 共享视觉特征 → 原子候选 + 键候选
                              ↓
                         set 原子筛选
                              ↓
                  ┌───────────┴───────────┐
                  ↓                       ↓
            AtomPair 连接预测       role → bbox → OCR
                  └───────────┬───────────┘
                              ↓
                        ChemScene / SDF
```

AtomPair 在 OCR 之前运行，结构预测并不依赖先读对文字；OCR 最后通过 `apply_atom_ocr`
写入 scene。当前真正的共同前置依赖是筛选后的 `atoms["atom_mask"]`：被 set 删除的
位置既不参与最终 AtomPair，也不会进入 role/bbox/OCR。

另有一个可选删除点：启用 `--structural-twin-suppression` 时，
`apply_structural_twin_suppression` 在 AtomPair 预测之后、OCR 之前收紧 mask 并过滤
关联 pairs；该选项默认关闭。分析启用该选项的运行时，不能把这部分损失算作 set 损失。
`apply_atom_ocr` 写入 scene 后还会按文字 bbox 重新计算 bond ports 与 incident ports，
但不会重新预测键或改变 bond 的原子端点引用。因此“连接不依赖先读对文字”不等于
“OCR 对最终 scene 几何完全没有影响”。

因此本轮不倒转现有流水线。后续要研究的是候选是否被过早不可逆地删除，而不是
单纯交换 OCR 与找键的执行顺序。文字分支独立于 set 是待验证的候选设计，不是已证实
优于现状的方案；也不能无保护地扩容 set 输入，忽略共享上下文造成的输出变化。

## 最小职责契约

| 部分 | 负责什么 | 不应该承担什么 |
|---|---|---|
| 可见文字证据 | 文字区域、实际可见字符串候选及来源 | 从隐式氢/价态反推字符并冒充 OCR 观测 |
| 结构几何证据 | 原子/连接位置候选、键的方向与几何证据 | 将每一条字形笔画直接确定为化学键 |
| 连接与化学解释 | 候选对象的关联、键类型、原子属性与化学约束 | 为使结构合法而静默改写原始可见文字证据 |

概念上的证据接口需要以下信息；这不是本轮新建的生产 DTO，也不要求重新实现已有结构：

- 文字：独立证据 ID、bbox、raw 字符串候选、来源。可选记录对应的几何候选 ID，
  但关联尚未确定时不能丢弃证据。
- 几何：候选 ID、连接 anchor、位置/存在性证据。**连接 anchor 不等于文字 bbox 中心**。
- 连接：端点候选 ID、键类型/存在性证据，以及与文字关联的决策记录。

允许计算顺序先后，也允许不确定候选最终被拒绝；不要求无限保留候选。
需要明确的是在哪个阶段提交不可逆决定、该决定损失了多少真对象，并同时检查保留
更多候选增加了多少假对象。

### 可见文字与化学字段的边界

图片画 `C` 时，文字字段为 `C`；结构字段中的 `implicit_h_count=2` 可以继续保留。
图片确实画 `CH2` 时，文字字段应保留 `CH2`，不能全局改成 `C`。
同理，实际画出的上下标/电荷属于文字证据；没有画出的化学属性不能凭空加入转写目标。
显示顺序与规范化字符串也须分开约定，不能从化学式拼接结果倒推“实际画了什么”。

OCR 错误本身不应删除已存在的几何证据；结构解释失败也不能静默将 raw OCR 候选改成
一个“更合理”的字符串。最终应用化学约束可以产生派生解释，但应保留观测和变更来源。

## 本轮实际落地

新增 `Data/sdf/visible_text_revision.py`：一个**纯函数、显式调用、train-only** 的版本化
文字修订入口。它不是自动 OCR，也不是默认生成器的替代品。

调用者必须提供：

- 原始 layers 与 PNG 的精确 SHA256 和 sample key；
- 具体 atom ID、预期旧文字与有证据的新可见文字；
- 同一次渲染的文字记录，或对原 PNG 的人工/审核记录引用。

接口检查身份与旧文字，返回新的 `chemvision-layers-visible-text-0.1` 文档，不写文件。
只修改指定原子的 `text` 并加入修订来源；原图、bbox、anchor、化学字段和 bonds 不变。
其余文字明确标记为 `legacy_unverified`，不会因一个修订就宣称整份标签已经审核。

接口拒绝：评测 split、无文字框的隐式原子、错图/旧版本、重复修订、化学属性推断，
以及把另一后端的 noFreetype 诊断输出直接当作原图权威文字。
哈希只能绑定证据与图片，不能代替对转写内容的审核。

**没有修改旧 `build_chemvision_layers.py` 的默认生成行为，也没有修订任何真实训练
或评测样本。** 旧生成器的化学文字回退仍存在；避免把“有安全修订接口”误称为
“数据生成问题已全面解决”。旧冻结实验的源文件和产物保持不变。

## 下一步只推进一个环节

先做受控 train-only 标签确认：从明确的训练 shard 取有代表性的可见碳样本，建立
原图文字证据，确定影响范围；再决定新版生成器与训练数据修订。修订产生独立版本和
manifest，不原地覆盖旧 shard，不顺便启动训练。

这一步完成之后，才针对 set 的 stress 正例损失与预测裁框稳定性设计小实验。
不要把模块单项召回的改善当作最终成功；主验收仍需分子图正确性，并保留文字、
候选覆盖与额外假对象等分项诊断。

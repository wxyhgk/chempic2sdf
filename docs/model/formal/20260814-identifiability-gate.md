# 第一性原理可辨识性协议

日期：2026-08-14

## 为什么先停训

E6-E8 已经分别否决候选边分类和全局 Bond query。继续扩数据不能回答一个更基础的问题：最终栅格图片是否包含唯一恢复化学图所需的信息。

对场景 `s` 定义：

```text
Render(s) : 最终模型实际读取的图片
Graph(s)  : 目标化学图
```

若存在 `s1`、`s2` 满足：

```text
Render(s1) = Render(s2)
Graph(s1) != Graph(s2)
```

则任何只读取图片的确定性模型都不可能在两者上同时正确。Lean 中的 `collision_forbids_exact_decoder` 已形式化这一命题。

键级也属于图语义。两条平行墨迹既可能是一根 order=2 的双键，也可能是两根不同的单键；如果观测只保留像素并集而丢掉笔画分组，两种场景仍可产生相同观测。`Multiplicity.lean` 单独检查了这个反例。

## 三类样本

1. 视觉可判定：相同最终输入对应唯一化学图。
2. 需要先验：原允许集合不可辨识，但施加可辩护的化学或绘图先验后可辨识；该先验还必须为原集合的每个观测保留至少一个代表，不能靠删掉所有困难观测“解决”。
3. 真正不可判定：在当前输入和允许先验下仍存在同图异图，只能输出多候选、歧义或排除 strict exact。

不能把第三类样本作为普通单标签监督，否则相同输入会被强迫学习互相矛盾的标签。

## 候选充分证据

当前只批准验证 Two-Port Ink Field，不批准训练：

- 一根语义 Bond 无论画成一、二、三条线或若干 dash，都只有一个无序端口对。
- crossing、junction 和文字重叠像素允许多归属，禁止 one-hot owner。
- 端口必须是最终图像中的可见 terminal，不得偷用文字内部的 SDF 原子坐标。
- 多个端口命中同一个 TextObject 时才合并成文字原子。
- crossing 位于两根 Bond 内部，不能自动生成 Atom。
- 聚合尺度由预测不确定度归一化，不能依赖固定 3px、4px 或某个分辨率专用 NMS。

这些只是候选恢复条件。必须先通过 Oracle decoder 和反例枚举，才能证明定义足够且没有隐藏标签泄漏。当前 `BondGroupingOracle` 直接来自 `scene.bonds`，只允许用于 Oracle 门；Lean 已额外证明它不能由发生 crossing/junction 碰撞后的粗 `Ink` 确定性导出，而且它本身会忘掉键级，并不足以恢复一般化学图。

## 稳定性条件

在 production tensor 上定义距离 `d`。对任何两个合法场景，只要它们的化学图不同，就要求：

```text
d(Render(s1), Render(s2)) > 2 * ε
```

其中 `ε` 是允许的字体、抗锯齿、量化、模糊和模型中间场误差半径。Lean 的 `robust_ball_has_unique_graph` 已证明：该条件成立时，距离观测不超过 `ε` 的所有候选场景具有同一图。若最小间隔为 0，则不可辨识；若间隔过小，则必须拒识，不能靠增加训练量消除。

## 冻结验证顺序

1. Lean：不透明渲染反例和左逆充分条件通过 `lake build`。
2. Generator：至少 10,000 个微场景可复现，strict 输入同 hash 异 graph 为 0。
3. Oracle：完美中间场到 production decoder 的 graph exact 为 100%。
4. 稳定性：0.25/0.5/1px 扰动、遮挡、缩放、旋转和端口交换有完整曲线。
5. Capacity64：GT ownership + learned ports，再到 full prediction，均为 64/64。
6. 盲审：另一个 agent 用未知 seed 连续两轮通过。
7. 只有以上全部通过，才允许生成大数据和正式训练，并使用新模型名和同名 tag。

## 停止条件

- Oracle decoder 不能在 strict 集达到 100%。
- 最终输入出现未登记的同图异 graph。
- 端口误差随 Bond 长度持续恶化，说明逐像素预测远端超出有效感受野。
- 只有训练模板通过，未知字体、长度、角度或组合因素失败。
- 解码器读取 SDF、Render JSON、GT count、对象顺序或固定风格阈值。

满足任一项时停止训练并回到定义层，不能用扩量掩盖。

# v0.8.21 Junction-Aware Bond Selector

> 状态：500 张 NO-GO，9k 泛化 GO  
> 日期：2026-07-20

## 目标

把 v0.8.20 视觉 Endpoint Grouper 接到真实 top-128 Bond candidate 流程，替换旧方案中
不可部署的 Oracle Junction pair 和泛化失败的 learned Bond count。

## 关键修正

旧 v0.8.13-v0.8.15 selector 存在两个问题：

1. candidate pair 和三个输入字段来自 GT 最近原子，不能用于真实图片；
2. line-band 真/假候选 AUC 已达 98.77%，但 learned count accuracy 只有 38.55%，
   导致 9k topology exact 只有 33.73%。

本版协议改为：

```text
top-128 Bond candidates
-> detector hidden + 完整 line-band + endpoint patch embedding
-> keep/drop threshold
-> 仅在已选 Bond 上运行冻结视觉 Endpoint Grouper
-> 按预测 Junction pair 去重
-> skeleton
```

- 删除 GT-nearest endpoint distance 和 Oracle self-loop 输入；
- selector 不再用 learned count 解码；
- Junction grouping 放在 keep selection 之后，避免假候选污染分组；
- MR-TADF、USPTO 不参与训练、阈值或 checkpoint 选择。

## 模型

- 冻结 v0.8.15 detector 与完整 line-band 特征；
- 冻结 v0.8.20 32px 方向对齐 endpoint CNN；
- 一层、64 维 Bond set Transformer；
- 只训练 keep/drop 与 set margin；
- train split 扫描 keep threshold，validation 只做冻结验收。

## 500 张容量实验

| 指标 | Train 500 | Validation 498 |
|---|---:|---:|
| Count accuracy | 78.80% | 68.67% |
| Topology exact | 75.80% | 64.66% |
| Candidate Oracle 利用率 | 83.66% | 72.85% |

validation 所有只读阈值的最佳 topology 也只有 65.06%，低于固定阈值内部基线
67.67%。因此不是阈值迁移问题，而是 500 张 keep/drop 泛化不足。

## 8,974 张训练

训练 20 epochs，阈值只在 train 8,974 上选择。最佳 threshold 为 0.90；额外补扫
0.92-0.99 后没有更高 train topology。

| 指标 | Train 8,974 | Validation 498 |
|---|---:|---:|
| Count accuracy | 77.16% | 74.10% |
| Vertex exact | 75.87% | 72.89% |
| Edge F1 | 95.71% | 95.72% |
| Topology exact | 74.70% | 70.88% |
| Candidate Oracle 利用率 | 82.72% | 79.86% |

validation topology 相比固定阈值基线 67.67% 提高 3.21pp，正式 GO。500 张到 9k
从 64.66% 提高到 70.88%，证明本阶段确实受 keep/drop 训练规模限制。

## 误差解释

validation Edge precision 为 98.75%，recall 为 92.87%。当前 selector 很少产生假连接，
主要损失来自保守阈值漏掉真键。Oracle-selected v0.8.20 上限为 77.91%，当前仍有约
7.03pp 可由候选排序和召回恢复。

## 性能工程复核

训练本身较快，但九档阈值扫描重复运行 selector 和 Junction grouping，明显慢于必要
成本。后续评估应缓存 selector logits，并只重跑阈值相关集合后处理；这不改变本轮模型
指标。

## 决策

- 无 GT 的 Junction-aware keep/drop：9k GO。
- 下一步接入独立实验推理 profile，先跑 internal validation 的正式 SDF/无效诊断输出；
  参数冻结后再跑 USPTO，不用 USPTO 调参。
- 稳定默认仍保持 v0.7.10。

# P–O 大字号漏连：连键输入分支与端点位置诊断

接续 [固定四结构样式全因子](20260923-po-style-factorial.md)。
本轮仍使用原 64 张、四个固定结构和 frozen initial；不生成新数据、不查询身份、
不训练、不使用 GPU、不改变正式模型、阈值或后处理。

## 事前固定的两个对照

代码路径：`continuation.structure_forward → DirectAtomPairBond`。
连键头使用三路拼接输入：

- **visual**：stride-4 视觉特征图中，端点连线 4%–96%、横向 ±12 px 的 32×9 采样，
  经过 ribbon encoder；正反向编码取平均。
- **atom**：两端原子隐藏特征的平均及绝对差，经 atom encoder。
- **score**：两端原始检测分数的平均、最小、最大值，经 score encoder。

不是原图像素的纯线条读取器；采样视觉特征可能包含文字及邻域信息。
三路经 shared 层输出存在性和键型。OCR 不参与这段判断。

### A. 仅校正端点坐标

先完成完全不注入真值的原预测，要求 64 张 prediction digest 和逐图指标精确复现。
随后才使用保存匹配和原 collator 的 q1023 目标端点，将三条 P–O 对照键涉及的
候选坐标替换为目标坐标；视觉特征图、候选集合、原子特征和分数保持不变。
这只干预 ribbon 的取样位置，不重提取原子特征，不是完整的上游定位修复。

每图两条 P–O 单键和一条 P=O 双键全部纳入，不能挑有效的样本。
若校正后仍有明显错误，只能说明坐标校正不足以解决问题，不能说端点偏移毫无影响。

### B. 同结构、同其他样式的三路编码交叉

固定 32 对字号 12/24 图片，共 64 对 P–O 单键、32 对 P=O 双键。
用真实预测时的 forward hook 记录进入 shared 的三路编码，按照同一目标键对应，
构造全部 2³ 组合。位序为 visual、atom、score；0 表示来自小字号，1 表示来自大字号。

`000` 和 `111` 必须分别重建原小／大字号原始 logits。
因为小批量重算线性层可能有浮点差异，事前固定容差为绝对值 2e-5、相对值 0。
所有组合都记录，不能只报告最好的组合；只统计原始键型，不将混合的局部键送进全图芳香后处理。

这是带真实键对应的内部 activation intervention。跨图编码可能不在正常联合分布中，
不能把“换入某分支后恢复”当成可部署修复、唯一神经因果解释或训练效果。

## 资源与验收

- CPU 墙钟最多 300 秒，无自动重试。
- 1 次模型加载；64 次结构前向、64 次完整 pair 前向、64 次三键 oracle pair 前向。
- 32 批 shared/head 混合编码读出，每批 8×3 条局部键；无梯度、优化器、OCR。
- 另有 64 次仅 shared/head 的三键重建检查，不重复运行上游或 ribbon encoder。
- 原图、源代码、旧报告、checkpoint 与新诊断实现均绑定 SHA。
- 不修改前一轮已哈希绑定的模块或历史输出，独立目录独占写入。
- 保存预测的编码、原始 logits、全部混合结果和对应关系。
  后核验只重算保存标量的汇总与哈希，不声称重新执行非线性层。

## 执行结果

已完成，64 张原预测摘要及指标全部精确复现。
这个结果需要收窄上一轮的解释：**端点在匹配范围内，不等于其位置精度足以支撑连键取样。**
此前排除了“候选不存在／被筛掉”，没有排除几像素偏移造成的视觉取样失效。

### 1. 不改变原图或模型，仅校正取样端点，恢复全部大字号 P–O 单键

| 对象 | 原预测正确 | 端点 oracle 正确 | 原错误变对 | 原正确变错 |
| --- | ---: | ---: | ---: | ---: |
| 12 px，P–O 单键 | 63/64 | 64/64 | 1 | 0 |
| 24 px，P–O 单键 | **10/64** | **64/64** | **54** | **0** |
| 12 px，P=O 双键 | 32/32 | 32/32 | 0 | 0 |
| 24 px，P=O 双键 | 27/32 | 29/32 | 3 | **1** |

大字号单键的平均存在概率由 0.456067 升到 0.986116，54 条漏连全部恢复，
键型也全部为 SINGLE。模型、原图、视觉特征图、原子隐藏特征、原子分数和阈值完全不变；
只有视觉 ribbon 的端点位置改成原目标适配器给出的坐标。

原图中单键端点相对源化学锚点的偏差（每条键的两个端点分别计数，每字号 128 次）：

| 字号 | 平均偏移 | 最大偏移 |
| --- | ---: | ---: |
| 12 px | 1.631 px | 3.015 px |
| 24 px | **3.427 px** | **4.727 px** |

其中 P 端点重复出现在两条单键中；按“图片、候选槽”去重，每字号 96 个端点，
平均分别为 1.715 / 3.587 px。偏差来自保存的原预测与源化学锚点，
oracle 实际使用的是 q1023 量化目标，二者不应混写为精确相同坐标。

实际视觉特征图是 96×192×192，对应输入 stride 4。
所以这些偏差虽未超出 6 px 匹配门限，已经接近一个特征格。
这个实验支持“当前视觉取样／编码对小位置偏差不稳健”，而不是证明网络完全看不懂大字号旁的键。
它没有单独分离平移、方向、长度三种坐标变化，也没有证明任何无真值的坐标修正算法有效。

### 2. 三路编码交叉将主要差异定位到 visual 路

下面完整报告八种组合，0=小字号编码、1=大字号编码；位序为 visual / atom / score。
每行都对应同一批 64 对 P–O 单键。它们是人工组合的内部状态，不是新的预测准确率。

| 组合 | 单键正确 | 漏连 | 键型错 | 平均存在概率 |
| --- | ---: | ---: | ---: | ---: |
| 000，小字号原输入 | 63/64 | 0 | 1 | 0.980231 |
| 001 | 63/64 | 0 | 1 | 0.980214 |
| 010 | 62/64 | 0 | 2 | 0.983176 |
| **011，仅换入小字号 visual** | **62/64** | **0** | **2** | **0.983073** |
| 100 | 11/64 | 53 | 0 | 0.452384 |
| 101，仅换入小字号 atom | 11/64 | 53 | 0 | 0.449275 |
| 110，仅换入小字号 score | 11/64 | 53 | 0 | 0.459690 |
| 111，大字号原输入 | 10/64 | 54 | 0 | 0.456067 |

换 visual 与只换 atom/score 的差异很大；结合 A 对照，下一步应优先处理
**化学锚点精度 → 沿键视觉取样**的接口，暂不改 OCR、全局阈值或整个架构。
不能把这一点解释成 atom 隐藏特征在所有分子上都无用，或把跨图拼接当作正式推理方法。

### 3. 不能省掉的回归反例

`curr_77be73d71f05ace7__po0100` 的 P=O（bond 0）：

- 原预测：存在概率 0.954549，原始键型 DOUBLE，正确。
- 端点 oracle：存在概率 0.890881，原始键型 SINGLE，错误。

大字号双键总数净改善 2，但实际是救回 3 条、损坏 1 条，不能只报净增掩盖退步。
这说明“更接近标签的端点”并不自动保证所有键型都更好；后续必须同时保护存在性和键型。
本轮只对 focus 真边执行 oracle，没有评估它对全图非边的影响，不能声称假连接不增加。

化学锚点也不等于文字墨迹框中心；不能看到可视化中的偏移就把目标全部改为字形中心。
相关历史接线检查见 [锚点契约核验](20260920-selector-anchor-contract7.md)，本轮没有修改标签。

## 后续修复顺序

1. 将本轮真值坐标 oracle 留作诊断上限，不接入正式推理。先设计**不读取真值的局部取样稳健性**对照，
   固定小范围坐标扰动，同时检查 P–O、P=O、旧正确键及确认非边；不能用多个位置最大概率直接加边。
2. 若需要训练，优先在已获训练准入的数据上对 pair 增加预测端点扰动监督与正确/错误连接回放。
   固定上游、OCR、selector，不把这四个已反复观察的诊断结构当作独立验收集。
3. 同时把原子“落在 6 px 内”的召回指标与连键所需的位置精度分开报告；
   是否进一步调整原子定位头，应有单独证据与预算，不能与 pair 修复同时混改。

本轮**定位了一个具体接口敏感性，尚未交付无真值的修复，也没有开始新的训练**。

# v0.9.17 Fit-only Pair-conditioned Residual

> 状态：协议、隔离式 split builder、2,841 参数模型、训练器和一次性 dev evaluator
> 正式实验已完成，结论为 `DEV900-PAIR-RESIDUAL-NO-GO`。24 项聚焦测试通过，
> 2,000-step final checkpoint 已封存，dev900 已且仅已消费一次。
> 本轮只使用原 `fit8100`，不读取或重新评估已经消费的原 calibration900；
> `CALIBRATION-TAU-PREDICTOR-NO-GO` 只作为切换路线的状态触发器，不用于选择本轮
> split、特征、网络宽度、loss、step 或门槛。生产推理继续保持 `v0.7.10`。

## 目标

v0.9.16 证明一个共享的图级标量 `tau(x)` 仍不能同时满足全部结构硬门禁。本轮不再预测
第二个 threshold，而是让每条 candidate pair 在同一张图的 target-free pair-set context 下
得到一个小 residual：

```text
corrected_gain[p] = frozen_raw_gain[p] + residual[p]
production_margin[p] = corrected_gain[p] - tau0
```

`tau0=0.7209501005709171`、candidate pool、P0、B scorer 和 production maximum-weight
matching 全部冻结。模型只改变 pair 之间的相对分数，因此可以表达“同一张图里某类 pair
应降低、另一类 pair 应保留”，这是单一 `tau(x)` 无法表达的自由度。

## 已继承的 fallback 承诺

下列方向来自 v0.9.16 NO-GO 后已经登记的 fallback，本轮不重新选择：

- 转向 pair-conditioned context scorer，不继续调标量 threshold；
- 输入以 frozen 20D normalized descriptor 和原始 FP32 raw gain 为核心；
- 只增加 target-free 图级上下文，不把 target ID、pair label、group type 或 oracle 状态送入
  forward；
- 固定 `tau0` 和现有 production matching；
- 使用约 2.8k 参数的小 residual 模型，不使用 graph Transformer、大图像 backbone 或 MoE；
- 原 calibration900、fresh_dev1、sealed、old validation500、`internal_test` 和 MR-TADF
  不得用于本轮训练、选择或门槛调整。

## 本轮新冻结的选择

本文件首次冻结以下实现细节：

- fit8100 内部的 7,200 / 900 identity-component split；

## Fit-only 组件切分

原 fit8100 含 2,025 个 identity component，每个 component 恰有四个 render variant。
component 仍按 molecule/source 的传递闭包定义：共享 `molecule_id` 或
`source_structure_id` 的记录必须处于同一侧。

对每个 component 构造：

```python

    {
        "molecule_ids": sorted(component_molecule_ids),
        "source_structure_ids": sorted(component_source_structure_ids),

    ensure_ascii=True,
    sort_keys=True,
    separators=(",", ":"),

    b"chemvector-v0.9.17-pair-residual-dev\n" + canonical.encode("utf-8")
```

### Fit/dev sidecar 隔离

顶层 `fit-dev` artifact 只保存 split/index/commitment 和两个 sidecar 的路径、SHA256，
不嵌入任何 pair token、pair label 或 evaluation target。fit 与 dev 记录必须分别写入
SHA-sealed sidecar：

```text
outputs/cache/chemvector-v0917-pair-residual-fit.pt
outputs/cache/chemvector-v0917-pair-residual-dev.pt
```

trainer 只允许打开 fit sidecar；它可以从顶层 index 读取 dev 的 count、commitment 和
declared SHA，但不得打开、hash 重放或反序列化 dev sidecar。dev evaluator 必须先使用
`O_CREAT|O_EXCL` 成功创建一次性 consumption marker，然后才能验证 SHA 并打开 dev
sidecar。marker 已存在时禁止再试。这是 holdout 隔离加固，不改变 split、模型、
loss 或门槛。

fit sidecar 的每条记录只在 `target_aware` 保存 canonical `pair_labels`；dev sidecar 额外在
`target_aware.evaluation_target` 保存五个 evaluator 必需的 anchor 字段：
`anchor_segments_pixels`、`anchor_target_line_ids`、`anchor_source_indices`、
`anchor_group_ids`、`anchor_group_types`。canonical `pair_indices` 仍只保存在
`target_free`。正式 evaluator 打开 dev sidecar 后，将这五个字段与 canonical
`pair_indices/pair_labels` 组合成评估 target，并让 baseline/candidate 使用同一 canonical
candidate 顺序；dev sidecar 不复制第二套 pair 顺序或分数。

## Target-free 输入

每个 candidate pair 使用 21D token，进入 pooling 前按
`(first_anchor_id, second_anchor_id)` 规范排序：

```text
20D frozen B normalized_pair_descriptor
+ 1D frozen raw_gain
```

每张图另计算四个只依赖 frozen candidate/score 的 count features：

```text
log1p(anchor_count)
log1p(candidate_pair_count)
log1p(count(raw_gain > tau0))
log1p(count(unique anchors incident to raw_gain > tau0))
```

严格使用 `raw_gain > tau0`。molecule/source identity 只用于 split 和审计，不进入模型。
pair label 只在 loss/evaluation 层读取，不能出现在 `target_free` 分支。
`pair_mask` 由 batch collator 根据每图 candidate 数量生成，只是 padding mask，不是 sidecar
中的模型语义特征，也不能承载 target-aware 信息。

## 固定模型

共享 context encoder：

```text
pair token 21 -> Linear(24) -> GELU -> Linear(12) -> GELU
```

对全部 pair 的 12D hidden 分别做 mean/max pooling，得到 24D；若 `P=0`，两种 pooling
都定义为全零。拼接四个 count features 得到 28D image context。每条 pair 的 residual head：

```text
[原始 pair token 21D, image context 28D] = 49D
49 -> Linear(30) -> GELU -> Linear(16) -> GELU -> Linear(1)
```

参数量固定为：

```text
21*24+24 + 24*12+12 + 49*30+30 + 30*16+16 + 16*1+1
= 828 + 2,013
= 2,841
```

最后一个 `Linear(16,1)` 的 weight/bias 全零初始化，使 step 0 严格等于 frozen B + `tau0`
baseline。residual 不做 tanh clipping；通过固定 L2 项约束幅度。模型不含 LayerNorm、attention、
graph Transformer、matching-in-the-loop、图像 crop 或第二个输出头。

## 固定 Loss

对 pair `p` 定义：

```text
r_p = residual[p]
m_p = raw_gain[p] + r_p - tau0
```

沿用现有 per-image balanced pair loss，但直接作用于固定 threshold 下的 margin `m_p`：

```text
L_cls  = per-image balanced mean(softplus(-m_pos), softplus(m_neg))
L_rank = mean softplus(1 + m_neg - m_pos)
         over positive/negative pairs sharing at least one anchor
L_hard = per-image mean softplus(top-4 highest negative margins)
L_res  = mean(r_p^2) over active pairs

L = L_cls + 0.5 * L_rank + 0.5 * L_hard + 0.01 * L_res
```

每张图先独立求均值，再跨 batch 求均值，避免 candidate 多的图支配训练。缺少某一类别时只对
存在的类别求 `L_cls`；没有 shared-anchor conflict 时该图不进入 `L_rank` 分母。禁止使用
v0.9.16 interval loss、dev 指标、production matching 的离散输出或任何 calibration 标签反传。

## Dev900 一次性门禁

final checkpoint 写入、SHA256 封存并重新加载后，使用固定 O_EXCL consumption marker
只消费 dev900 一次。同一次审计同时运行：

1. frozen raw gain + `tau0` baseline；
2. frozen raw gain + residual + `tau0` candidate。

两者使用完全相同的 candidate、production matching 和样本顺序。不得搜索 threshold、缩放
residual、挑 epoch 或删除 candidate-unreachable 样本。

candidate 必须通过全部绝对门槛：

| 指标 | GO 门槛 |
| --- | ---: |
| dev images consumed | 900 / 900 |
| selected cross-target pairs | 0 |
| selected pair precision | >=99.9% |
| multiplicity-2 recall | >=99.5% |
| pairable sample exact | >=95% |
| parallel-2 preservation | 100% |
| ordinary support loss | <=0.1pp |
| permutation determinism | 100% |
| matching optimal | 900 / 900 |
| checkpoint SHA before/after | 完全一致 |

此外 candidate 的结构 tuple 必须严格优于同次 frozen baseline：

```text
K = (
    -selected_cross_target_pairs,
    -parallel_2_violated_group_count,
    multiplicity_2_matched_count,
    pairable_sample_exact_count,
    -ordinary_support_lost_target_count,
    selected_pair_precision,
)
```

要求 `K_candidate > K_baseline`（lexicographic）。这防止一个完全输出零 residual 的 no-op
模型仅因 holdout 本身容易而被判为路线 GO。任一绝对门槛或相对改善条件失败，状态为
`DEV900-PAIR-RESIDUAL-NO-GO`；全部通过才是 `DEV900-PAIR-RESIDUAL-GO`。

dev900 一旦暴露，不得修改本文件中的任何数值后重用。GO 只说明 fit-domain development
成立，仍不能替代新的 molecule/scaffold/style-disjoint `fresh_dev2`。

两个 cross 诊断样本为：

- `000001678` / `chembl:CHEMBL409287` / stress：baseline 已有的错误 pair 保持不变。
  candidate index 0 的 anchor `(0, 12)` 分属 target line `(5, 43)`，raw gain 为
  `3.78601313`；两个端点均没有其他 incident candidate，因此 shared-anchor ranking loss
  完全覆盖不到它。删除该 pair 至少需要 residual `< -3.065063`，但该图 residual 最小仅为
  `-2.500020`；
- `000007047` / `coconut:CNP0211190.1` / stress：新增错误 candidate index 20，anchor
  `(9, 256)` 分属 target line `(72, 171)`；其 frozen raw gain 仅为 `0.54172903`，低于
  `tau0`，说明 residual 将原本未选择的错误 pair 抬入了 production matching。与它共享
  anchor 9 的真实 candidate index 18 raw gain 仅为 `-2.80704975`，原始排序落后
  `3.348779`；真实 pair 需要 residual `> +3.528000` 才能过阈值，而该图全部 residual 的
  最大值仅为 `+2.664792`。

127 张 selection 变化中，112 张只增加 pair、7 张只删除、8 张发生交换；总计新增 311、
删除 16。新增 pair 中 310 个为 same-target、1 个为 cross。12 张图从 non-exact 修复为
exact，0 张原 exact 图回退；但仍有 6 张图出现 M2 matched count 回退。stress variant 占
94 / 127 张变化和 265 / 311 个新增 pair，两处 cross 也都只出现在 stress；同时 stress
pairable exact 仍从 82 / 95 提升至 88 / 95，因此问题不是 stress 路线整体无效，而是极少数关键
pair 的 residual 分配与 production matching 不一致。

dev residual 分布为 `[-7.1658, 4.8209]`，fit 上最大绝对 residual 为 `8.4648`。这说明当前
`0.01 * L2` 与独立 pair loss 虽能提高召回，却没有直接保证 maximum-weight matching 的
零 cross 安全性。该判断只用于停止 v0.9.17；不得在已暴露 dev900 上修改 residual clipping、
loss 权重、网络宽度或训练步数后重跑。

只在 fit7200 上进行的 post-hoc production-matching 诊断进一步确认这不是单纯泛化或数据量
问题：selected negative 从 33 降至 15，说明模型确实学到大量正确修正；但它仍新制造 5 张
cross 图。15 条最终 selected negative 中有 6 条原 raw gain 低于阈值，是 `+1.24 ~ +1.93`
的 residual 将其抬过门槛；其中 3 条没有任何共享端点的 positive candidate，现有
shared-anchor ranking 对它们没有梯度覆盖。

更根本的表达缺口是：v0.9.17 forward 只接收 pair token、pair mask 和全图 count/context，
不接收 `pair_indices`，因此模型不知道候选之间的 endpoint incidence。两个样本即使拥有相同的
21D token multiset，只要 pair 共享端点的方式不同，production maximum-weight matching 就可能
不同，而当前模型仍会输出相同 residual。下一版不能只增加宽度、步数或同分布数据；必须先在
fit-only 条件下验证 endpoint-incidence context 与 matching-aware safety loss。

## CPU 成本

增量网络每条 pair 的线性层约为：

```text
context encoder: 21*24 + 24*12 = 792 MAC
residual head:   49*30 + 30*16 + 16 = 1,966 MAC
total: 2,758 MAC / pair
```

冻结 dev900 平均 `51.35` pair/image，因此约 `141,623 MAC/image`，即约 `0.283 MFLOP/image`
（一次 MAC 计两次 FLOP）。2,841 个 FP32 参数约 `11.1 KiB`，INT8 权重约 `2.8 KiB`。
复杂度是 `O(P)`，不增加 pair-pair 二次项；existing maximum-weight matching 成本保持不变。

正式审计应报告单线程 CPU residual forward 和完整 matching 的 mean/p50/p95/max。建议诊断目标为
residual forward p95 `<1ms/image`、完整 matching p95 `<20ms/image`，但延迟不进入 capability
GO/NO-GO，避免通过跳过结构计算获得虚假能力结论。

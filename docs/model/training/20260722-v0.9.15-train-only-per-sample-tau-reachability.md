# v0.9.15 Train-only 每图标量 Tau 可达性

> 状态：`CALIBRATION-SCALAR-ORACLE-GO`。完整 900 calibration 已做正式单遍
> target-aware oracle reachability；不训练新参数，不读取 fresh、sealed、old
> validation500、`internal_test` 或 MR-TADF。该结论是每图标量 `tau(x)` 的可达上限，
> 不是可部署模型结果。

## 背景

v0.9.14 的 exposed fresh score-frontier 显示：1,797 个“candidate 已存在但未选”的 m2 miss
全部不高于冻结 global threshold；其中 1,322 个没有 incident negative，449 个在存在 negative
时仍严格领先，只有 26 个属于局部排序失败。这个结果只用于提出“每图阈值可能有不同偏移”的
假设，不能用于选择 `tau(x)`、超参数或模型。

共享 global threshold 已在前序实验中评估过，本轮不重复该问题。固定 v0.9.11 的 P0、pair
scorer、candidate pool、score、maximum-weight matching 和指标实现，只读取原来已经暴露的
8,100 fit / 900 calibration 数据。

## Oracle Reachability

对每张图片单独枚举 frozen pair score 诱导出的 threshold 区间。target-aware oracle 可以查看
该图的 GT，只为理论上限选择一个 `tau(x)`；不同图片允许选择不同标量，但同一图片的所有 pair
仍共享这个标量。oracle 不可部署，也不能作为未来 predictor 的输入或标签以外的信息来源。

将每图 oracle 选择后的结果聚合，检查：

- selected cross-target pairs 为 0；
- multiplicity-2 recall 不低于 99.5%；
- pairable sample exact 不低于 95%；
- parallel-2 preservation 为 100%；
- ordinary support loss 不高于 0.1pp。

fit 与 calibration 必须分别报告，不能合并后只给一个有利汇总。

## Robust GO

每个 oracle 解必须记录使 matching 结果不变的 threshold 区间及其到相邻 score 边界的 margin。
只有位于非退化开放区间、在数值扰动下仍保持同一选择结果的解，才计入 robust 可达上限。

若某个目标结果只在 score 相等点、`nextafter` 边界或零宽区间成立，必须标为 `boundary_only`；
这类样本可以单独统计，但不能计入 robust GO，也不能据此声称 target-free predictor 可学习。

正式热路径使用 parametric upper hull。每个可表示的非退化开放区间必须取严格位于区间内部的
25%、50%、75% 三个 threshold，并用现有 production evaluator 重放；三点选择状态完全一致，
该状态才是 robust reachable。数学 hull 只负责提出候选区间，不替代 production 行为证明，也不
宣称覆盖浮点数域中的每一个可能状态。

若最大基数状态已经达到 candidate/scalar 可实现的完美状态，可以使用提前证书：构造一个完全
低于安全 low-threshold 的保守开放子区间，同样在其 25%、50%、75% 三个严格内部点重放，并做
permutation deterministic 检查。该证书只省略后续 hull 枚举，不降低 GO 条件。它没有计算真实
相邻 hull boundary，artifact 明确标记 `early_certificate_not_training_interval=true`；若 capability
GO，后续生成 `tau(x)` 训练 interval manifest 时必须关闭提前证书并重新计算真实相邻边界。

完整 candidate-score、fixed-cardinality envelope、exact boundary 和 `nextafter` 重放只用于失败
诊断。正式首遍一律不生成这些明细；首遍指标固定后，仅对前 128 个失败样本做第二遍完整诊断，
因此 boundary-only 状态不可能进入 formal oracle。

在精确算术下，正 temperature 只会把所有 pair gain 同除一个正数，不改变排序和
maximum-weight matching；但当前 production solver 使用 64-ulp objective tie tolerance，该容差
不具正缩放不变性。已构造反例：两条冲突边在整体乘 1000 前后会选择不同 canonical edge。因此
本轮明确冻结 `T=1` 和原始 pair-score scale，只审计每图 `tau(x)`；不声称覆盖 temperature 的
production 浮点效应。未来若要把 `T(x)` 纳入能力审计，应先修成 scale-normalized tie tolerance，
或单独预注册二维数值审计。

matching latency 继续完整报告，但不进入本轮 capability GO。原因是 oracle threshold 会改变 MILP
数值路径，提前证书使用的保守负 threshold 也不等同于未来 predictor 的运行点；把该计时混入
“结构是否可达”的结论会使纯提速捷径改变 GO/NO-GO。部署速度需要在可学习 predictor 和固定推理
路径确定后单独验收。

## 执行顺序

先只跑完整 900 calibration：

```bash
.venv-train/bin/python -m \
  chemvector.audit_evidence_carrier_sample_threshold_reachability \
  --partitions calibration \
  --device cpu \
  --workers 4
```

该 calibration-only 命令已正式输出 `CALIBRATION-SCALAR-ORACLE-GO`。CPU 多进程使用
`spawn`，每个 worker 限制为一个数值计算线程；主进程只保留一个有界任务窗口，
并按样本索引稳定输出。

原协议中的下一阶段是 fit + calibration capability 聚合。正式结果证明 846 / 900 张
calibration 图使用了提前证书，而该证书不含真实相邻 boundary。因此不再把常规
fit+cal audit 当作训练标签产物；后续由 v0.9.16 的独立 manifest mode 关闭 early
shortcut，对两个 partition 重算真实 hull boundary。

当前实现验收：相关 59 项测试全部通过。真实 frozen calibration 子集在 `workers=4`、无 failure
detail 下，cal1/cal8/cal32 wall time 分别为 7.73/8.82/9.02 秒，峰值 RSS 分别约
1.386/1.396/1.397 GB；当前 cal32 输出 298,060 bytes。32/32 样本都命中提前证书，共 96 个正式 probes、
32 个 reachable states。上述只是性能 smoke，不是 formal calibration 结论。

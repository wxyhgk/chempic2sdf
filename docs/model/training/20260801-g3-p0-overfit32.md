# G3 层级 Atom→Bond 集合图 P0 overfit32

> 日期：2026-08-01
> 状态：P0-B..P0-F 均为 `NO-GO`；P0-G AtomPair identity fixed-final 为 `GO`
> 性质：G3 structural v0.1 容量门，不创建正式模型版本或 tag

## 目标

验证 G3 的最小结构路线能否在固定 32 张训练图上同时记住：

1. Atom 数量和二维 anchor 集合；
2. Bond 数量；
3. 每根 Bond 的两个 Atom-slot endpoint pointer；
4. Bond display/chemical type；
5. 由以上对象组成的完整无向结构图。

本实验不训练 OCR，也不预测 Atom element、charge、H、文字、Bond direction 或
stereo。训练时只 teacher-force Atom/Bond count，不能注入 GT Atom 坐标、类型或邻接关系。

### 为什么 71.5% / 56.4% 仍是 0/32

`training_log.jsonl` 最后一行的 endpoint accuracy 71.5405% 和 Bond incidence
56.3555%，是 step 2381-2400 各训练 batch 的平均值。它们只在“按预测 Bond 几何做
Hungarian 后的正例 query”上统计：前者要求一个有序 endpoint pointer 正确，后者要求
同一 Bond 的两个 pointer 都正确。它们没有经过部署时的 presence top-count
`bond_mask`，也不是整图拓扑准确率。

对 final checkpoint 做只读 32 图前向审计后，因果分解如下：

| 条件指标 | 结果 |
|---|---:|
| Atom 6px micro | 1,324/1,424 = 92.98% |
| Atom 6px whole-set exact | 17/32 = 53.13% |
| 训练 L1 / 评测 L2 Atom 身份一致 | 1,330/1,424 = 93.40% |
| 部署 top-count Bond 与 Hungarian 正例重叠 | 665/1,508 = 44.10% |
| Hungarian 正例上的 endpoint exact | 2,210/3,016 = 73.28% |
| Hungarian 正例上的双 endpoint exact | 899/1,508 = 59.62% |
| Hungarian 正例上的 Bond type micro | 1,211/1,508 = 80.31% |

因此不是一个简单的独立概率幂乘问题。首先有 15 张图被 Atom whole-set 条件直接挡住；
更关键的是训练 pointer 的正例 query 与部署实际选择的 query 只重叠 44.10%，32 张图
没有一张完整重合。被选图中还存在大量 self-loop 和 duplicate edge。官方 `Bond type
exact = 0/32` 又以 topology exact 为前置条件，所以不能把它单独解释成键型分类器为零。

结论是三段因果同时存在：Atom whole-set 尚未过门；Bond proposal 的 Hungarian 身份与
presence 部署选择有明显断层；即便只看 matched query，pointer 双端点也只有约 60%。
其中 Atom 训练用 L1、评测用 L2 的身份差异存在，但不足以单独解释 topology 0/32。

## P0-B 预注册：GT Atom-slot oracle

下一轮只做这一个因果隔离，不并行尝试其他修复。目标是消掉预测 Atom 集合和动态 Atom
query 身份，让实验只回答：在 Atom anchor 与 slot 身份完全正确时，现有 Bond proposal
selection、type 和 endpoint pointer 是否具备记住 32 图的容量。

固定协议：

1. 新 CLI flag 为 `--gt-atom-slot-oracle`，默认关闭；关闭时 P0 forward 和默认输出路径
   逐分支保持不变。
2. oracle 模式直接使用 GT Atom anchor，slot `i` 恒等于 target slot `i`，padding 身份为
   -1；Atom feature 仍从对应图像空间 cell 的可训练 Atom dense feature 取得。
3. 训练 pointer target 和评测 Atom mapping 都使用显式 direct identity，不再做 Atom
   Hungarian；这避免同坐标、拥挤坐标以及 L1/L2 造成身份交换。
4. 不提供 GT Bond query identity。Bond dense proposal、Hungarian 训练配对、presence
   top-count 选择、Bond type 和 endpoint pointer 均继续由模型产生。
5. 数据、manifest、vision、模型参数、初始化 seed、batch、优化器、LR 和 2,400 steps
   全部不变；从相同 seed 重新初始化，不 resume P0 checkpoint，不追加 step。
6. 独立结果目录固定为
   `outputs/smoke/chemvector-g3-p0b-gt-atom-slot-oracle`，脚本会拒绝 oracle flag 与其他
   输出目录组合，避免覆盖或混淆 P0 artifact。
7. 仍只按 final step 判定，不使用 `best.pt`。原五项门槛不变；其中 Atom set 在 oracle
   下是协议校验项，真正的因果判定看 Bond count、topology、type 和 structural graph。

部署实际选择的 1,508 条 query 解码后包含 189 条 self-loop 和 279 条额外 duplicate；
去掉二者只剩 1,040 条唯一非自环边。其中 897 条命中 GT，143 条是错误唯一边，因而
缺失 611 条 GT edge；连同键型正确的只有 841 条。完整计数关系为：

```text
1,508 selected = 189 self-loop + 279 duplicate-extra + 1,040 unique edges
1,040 unique   = 897 correct edge + 143 wrong edge
1,508 GT       = 897 recovered + 611 missing
```

self-loop 涉及 28/32 张图；279 条 duplicate-extra 来自 218 个重复 pair group，涉及
32/32；missing 也涉及 32/32，143 条 unexpected unique pair 涉及 24/32。尤其是被
presence top-K 漏掉的 matched 正例，pointer exact 反而高于被选中的 matched query
`7.28pp`，说明当前 ranking 不只是随机漏选，还偏向了 pointer 质量较差的 query。

P0 到 P0-B 后，Atom set 从 17/32 变为 32/32，matched pointer/type 也大幅提高，说明
GT Atom-slot oracle 确实消除了一个重要变量。但 topology 仍为 0/32，且部署 top-K 与
训练正例仅重叠 54.77%。因此当前主因已经可以收敛为：Bond 训练使用纯几何 Hungarian
定义正例，部署却用 presence top-K 定义实际对象，两套 Bond 身份协议没有统一。

## P0-C 预注册：共享 confidence-aware Bond assignment

P0-C 只修改一件事：让训练 Bond matching 使用与部署 selection 相同的 presence 信号，
并让所有依赖 Bond query identity 的 loss 共享同一次 assignment。Dense Bond slot loss 与
Bond count loss 位于不同对象空间，不消费这份 assignment。P0-C 不修改 Atom oracle、
数据、模型规模、pointer 表示、键型类别或部署 top-K 解码。

预注册的唯一 matching cost 为：

```text
C(q, t) = 8 * unordered_endpoint_cost(q, t)
        + 2 * center_L1_cost(q, t)
        + 2 * softplus(-presence_logit(q))
```

其中 `presence_logit` 在 Hungarian 中 detach；系数固定为 2，不做权重网格搜索。匹配只
计算一次，同一组 `(Bond query, GT Bond)` identity 必须同时用于：

1. presence positive / negative target；
2. Bond endpoint geometry loss；
3. display / chemical type loss；
4. 两个 endpoint pointer target 与 incidence loss。

部署保持现状：Bond count head 给出 K，直接选择同一 presence logits 的 top-K query。
P0-C 仍启用 GT Atom-slot oracle，只隔离 Bond matching/selection；不会向模型提供 GT Bond
query identity，Hungarian 仍是标准集合监督而不是推理 oracle。

### P0-C 实现与验证

- `bond_group_query_assignments` 默认仍是原 geometry-only 分支；只有显式 P0-C flag 才加
  固定权重 2 的 detached positive-presence cost。
- P0-C 每个 forward 只生成一次 assignment，并原样共享给 presence、Bond endpoint
  geometry、display/chemical type 与 incidence pointer target。
- evaluator 新增 intersection、selected/matched/union、precision/recall/F1/Jaccard、
  query-set exact 和 presence cutoff tie 诊断；P0-C gate 使用 deploy recall `>=95%` 与
  query-set exact `>=30/32`。
- 默认 P0/P0-B 不计算 confidence cost，不传共享 assignment，也不输出新增 identity
  诊断字段；原输出目录约束保持不变。
- Bond Query、G3、data/train 聚焦回归为 `45 passed`；加入 Dense Bond 与 Spatial
  Incidence 相邻回归后为 `59 passed`。

## P0-D 预注册：GT Bond-slot identity oracle

允许把任何 GT 化学属性或坐标写进预测。

### 唯一改动

模型在 Bond decoder 前增加一个只用于 P0-D 的 `no_grad` router：

1. 输入仍是 dense Bond head 产生的 visual proposals；
2. GT Bond 先经 `build_g3_bond_targets` 规范化为稳定的 canonical prefix；
3. router 仅以 predicted proposal endpoint 和 GT endpoint 计算一次 Hungarian：

```text
C(q, t) = 8 * unordered_endpoint_cost(q, t)
        + 2 * center_L1_cost(q, t)
```

4. 按 GT target `0..K-1` 的顺序把匹配到的 predicted proposal gather 到前 K 个 slot；
5. 未匹配 proposal 按原 visual rank 接在后面；所有带 query 轴的 proposal 字段共享同一
   permutation，无 query 轴的审计 metadata 原样保留；
6. router 只输出离散 permutation、`bond_target_indices=[0..K-1,-1,...]`、positive mask
   和 coverage；gather 后的 endpoint、feature、logit 和类型初值全部仍是模型预测值。

以下信息严禁进入 decoder，也严禁写回 proposal：GT endpoint 数值、Atom refs、Bond
display/chemical type、direction、stereo 以及任何元素/OCR 语义。GT endpoint 只决定离散
proposal 排列；gather 保留预测张量的梯度路径。P0-D 必须同时启用 P0-B 的 GT Atom-slot
oracle，以免重新混入 Atom identity 变量。

### 固定 identity 与部署选择

P0-D 不再对 decoder 输出执行第二次 Hungarian。loss 侧严格验证 router 的前缀身份和
coverage 后，直接构造：

```text
queries = [0, 1, ..., K-1]
targets = [0, 1, ..., K-1]
```

同一个 assignment Python 对象必须同时交给 Bond presence/endpoint/type loss 和 endpoint
pointer/incidence target。Dense Bond slot loss 保持原 Hungarian，不消费这份身份。训练中
presence 仍计算监督，但只作诊断，不再决定 P0-D 的对象选择。

P0-D 的 Bond mask 固定取 prefix：GT-count 模式取前 K 个；deploy-count 模式由 Bond count
head 给出 `K'`，取前 `K'` 个。两种模式都禁止 presence top-K。因此 GT count 只提供对象
数量，GT Bond router 只提供 proposal identity；pointer、type 和 topology 仍全部由模型
预测。

## P0-F 预注册：固定 learned Bond query 的集合预测

```text
L = 0.1 * L_atom_count + 0.1 * L_bond_count
```

## P0-G 预注册：AtomPair 作为 Bond identity

P0-G 只验证一个假设：**在 GT Atom identity 已固定时，Bond 是否应直接建模为无序
`(Atom i, Atom j)`，而不再生成独立 Bond query 再学习 pointer？** 这不是回到 MolGrapher
的候选裁剪：每张图枚举全部有效 Atom 的无序对，不使用距离上限、最近邻、`1.75x` 键长、
空白中点或任何 hard candidate filter。

### 固定模型与损失

1. 保留 G3 Atom dense head和 P0-B GT Atom anchor/slot identity；
2. 复用已在 v0.10.3 验证过的 `DirectAtomPairBond`，配置固定为 stride-4 feature
   `96` channels、Atom feature `384`、`32x9` ribbon、半宽 `12px`、hidden `256`、
   pair chunk `512`；
3. 每个无序 AtomPair 的两端就是确定的 Atom refs，不训练 endpoint regression 或 pointer；
4. ribbon 正反 180 度编码平均，保证无序对表示不依赖端点顺序；
5. 每个 pair 输出 presence 与 `SINGLE/DOUBLE/TRIPLE/AROMATIC` chemical type；当前结构
   scope 的 display logits 与 chemical logits 共用，不引入 direction/stereo；
6. GT Bond 只在 forward 完成后映射为 pair presence/type target；forward 不接收任何 GT
   Bond count、endpoint、Atom refs、type、display、direction 或 stereo；
7. presence 使用全部正键和全部无序对负例，BCE `pos_weight` 固定为
   `clamp(negative/positive, 1, 16)`；chemical CE 只在正键计算；
8. 总 loss 固定为：

```text
L = 0.1 * L_atom_count + 0.1 * L_bond_count
  + L_pair_presence_bce + L_pair_chemical_ce
```

GT-count eval 在模型 forward **之后**按真实 Bond count 对 pair presence top-K；deploy eval 按
独立 count head 的预测对 pair presence top-K。GT Bond count 不进入 forward 或 pair feature。
由于 pair identity 已包含端点，不存在 Hungarian、canonical Bond order、learned query
identity 或 incidence pointer。

### 固定协议与 Gate

- manifest、vision checkpoint/SHA、seed、32 图顺序与 P0-B..P0-F 相同；
- BF16、batch 4、AdamW、LR `3e-4`、weight decay `0.01`、2,400 steps；
- CLI 固定为 `--gt-atom-slot-oracle --direct-gt-atom-pair-bonds`；
- 独立目录固定为 `outputs/smoke/chemvector-g3-p0g-gt-atom-pair-bond-capacity`；
- fixed-final only，不 resume、不追加 step、不换 seed、不搜索阈值/loss 权重；
- 不读取 MR-TADF、USPTO、fresh dev、sealed test 或 confirm400；
- protocol gate：32/32 pair universe 合法、`1,508/1,508` GT Bond coverage；
- capability gate：GT Atom 6px set 必须 `32/32`，GT-count 与 deploy-count 的 topology、
  typed graph exact 均须 `>=30/32`，deploy count-pair `>=30/32`，positive type micro
  `>=99%`；
- 任一失败即 `NO-GO`；NO-GO 不打 tag。

P0-G 的 pair universe 为 `O(V²)`。本轮只做 overfit32 容量与因果隔离；即使 PASS，也只能
证明稳定 AtomPair identity 能承载 Bond relation，不能冒充端到端能力或 CPU 部署结论。
后续稀疏化必须相对全 pair 报 recall，并继续禁止键长 hard cutoff。

# v0.8.13 Bond-first 分层审计与集合选择

> 状态：表示与容量 GO，9k 泛化 NO-GO  
> 日期：2026-07-20  
> 基础 Bond checkpoint：`chemvector-v082-multiscale-joint-9k-1epoch/best.pt`

## 目标

根据 Kimi 与 Fable5 对“Bond Object 为一等对象、Junction 由端点派生、整组键联合
解码”的建议，先核对项目已有实现，再验证当前 Bond-first 到底失败在哪一层。

项目已经在 v0.8.1 实现固定空间 Bond Object，在 v0.8.4 实现端点到 Junction 的
learned assignment，在 v0.8.5 实现节点-边消息传递。因此本轮没有重复实现另一个
Bond Query detector，而是新增可复现的五层审计：

```text
Bond candidate count
  -> endpoint geometry
  -> Oracle Junction topology
  -> chemical/display type
  -> SDF compile
```

## 分层审计

脚本：

```text
chemvector/audit_bond_first_decomposition.py
```

数据为 scaffold 独立的 ChemVision validation 498 张，未使用 MR-TADF、USPTO 或

### 阈值扫描

| Bond threshold | Count exact | 严格拓扑 exact | Candidate Oracle | SDF exact | 平均重复键 |
|---:|---:|---:|---:|---:|---:|

| 0.05 | 23.49% | 23.29% | 86.35% | 22.69% | 6.44 |
| 0.00 / top 128 | 0% | 0% | 88.76% | 0% | 大量 |

`Candidate Oracle` 的定义是：允许一个全局 selector 删除任意多余对象时，每条真键
是否至少有一个候选对象映射到正确的 Oracle Junction pair。

历史 v0.8.2 的 4.42% `oracle-junction SDF exact` 只有在计数、6px 几何和所有类型
先全部严格通过后才尝试编译，因此严重低估了表示的可恢复能力。直接把预测端点映射到
Oracle Junction 后，当前 checkpoint 实际可以得到 52.21% SDF exact。

## Whole-set Selector

新增：

```text
chemvector/bond_set_selector.py
chemvector/pretrain_bond_set_selector.py
```

模型对固定 128 个候选做集合 Transformer 编码，同时预测：

- 每个候选的 keep/drop；
- 整图 Bond count；
- display type 与 chemical type residual；
- set margin，使所有真对象的最低分高于假对象的最高分。

解码按预测 count 取全局最高分对象，并硬性禁止自环和重复 Junction pair。没有使用
键长阈值或最近邻删键。

| 指标 | 500 零调参 | 9k 训练 | 原始 threshold=0.25 |
|---|---:|---:|---:|

扩数据有效，但新的集合模型仍低于原始置信度阈值解码，正式 NO-GO。

## 决策

- Bond Object 表示：GO。旧 4.42% 指标不能继续作为该表示的真实上限。
- Candidate Oracle 审计：GO，成为后续所有 Bond selector 的必报指标。
- Whole-set loss 与 count-conditioned decode：容量 GO。
- 只使用冻结输出的二次集合 selector：9k NO-GO，不接入推理。
- 暂不扩到 18 万。下一步必须给 selector 提供真实 line-band 边证据，或允许集合损失
  联合更新 Bond detector；不能只增加同类元数据训练量。

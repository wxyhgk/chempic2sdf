# 干净连键专项：先补基础正例，保留真实难负例

本轮完成训练侧覆盖核对，以及隔离的 pair-only 损失入口。**62 个符合 2–7 重原子、无指定立体信息范围的课程训练分子中，N–N 单键和 N–S 单键均为零；跨中间原子的假边则已有覆盖。** 因此暂不启动拟议的干净连键专项训练，先补齐对应教材。

数据核对 CPU 用时 **8.273 秒**，零图片读取、零模型前向、零优化器步数、零 GPU、零外部身份查询。未修改默认训练、推理、OCR、阈值、发布清单或 checkpoint。原完整开发成绩仍为 170/800；上一轮 clean16 仍为 8/16，不产生新准确率。

## 一、缺的是小分子基础覆盖，不是全库没有这些键

本次清点已发布训练清单中的全部 13,151 条图像记录，按来源分别计数。图片变体与分子身份分开，下面“分子数”按来源内部 canonical SMILES 去重，跨来源不直接相加。

| 来源 | 图像记录 | 不同分子 | 含 N–N 单键的分子 | 含 N–S 单键的分子 |
| --- | ---: | ---: | ---: | ---: |
| curriculum | 657 | 73 | 0 | 1 |
| full_molecule | 1,668 | 193 | 6 | 4 |
| full_molecule_expansion | 10,826 | 1,907 | 58 | 95 |

课程中唯一的 N–N 是 `N=N`，属于双键，不能当作 N–N 单键的覆盖。唯一的 N–S 是 `NS(=O)(=O)c1ccccc1`，有 10 个重原子，不属于这次的小分子范围。两组完整分子来源没有 2–7 重原子的样本。

这些数字描述**当前可用发布数据**，不是 initial 的实际训练履历。initial 没有因为发布清单存在就自动学习这些图；既有续训也未遍历全部记录。因此不能据此断言 initial 从未见过 N–N/N–S，或已经证明缺少小图就是低准确率的唯一原因。

## 二、固定训练侧清单与必要对照

从课程训练部分取全部 73 个 `reference` 样式，各一个分子身份，不按模型结果挑图。原训练/验证身份和分组保持不变；其中 62 个符合本阶段的分子规模和立体范围，11 个范围外分子仍在完整记录中列出。

| 训练目标/对照 | 符合范围的分子数 | 对应边/非边数 |
| --- | ---: | ---: |
| N–N 单键正例 | 0 | 0 |
| N–S 单键正例 | 0 | 0 |
| C–N 单键正例 | 8 | 15 |
| 真实 O–O 单键正例 | 1 | 1 |
| 跨中间原子的非边 | 8 | 12 |
| 其中 O–S–O 两端的 O–O 非边 | 2 | 2 |

非边判据用于**目标覆盖审计**：目标化学图中两端不直接相连，但共享一个中间邻居，其锚点位于两端连线的 10%–90% 之间，垂距不超过 2 px。不是给模型加几何否决规则，也不据此推断预测候选已经匹配到这些节点。

两例 O–S–O 来自 `CS(C)(=O)=O` 与 `CCS(C)(=O)=O`；真实 O–O 对照来自 `OO`。所以不能总结成“训练集没有跨节点负例”，更不能写一条禁止 O–O 的硬规则：相同元素对，是否直接相连必须依据图像和连接上下文。

同一个分子的九种样式不能算九种连接环境。本轮只核对同源标签和已准入的 reference 样式 metadata（24 px 字号、2 px 线宽），不冒称重新人工检查了所有像素。

## 三、隔离的只训 pair 入口已实现，未运行真实训练

新增 `chemvector/training/curriculum/pair_stage.py` 的 `FrozenUpstreamPairStage`，由未来实验显式传入独立组件实例和原 atom 阈值使用，未接入旧 `continuation_losses()` 或 GPU launcher。

- 固定 vision、atom、bond、set、role、bbox 的参数及 eval 模式；重复 `train()` 也只让 pair 进入训练模式。OCR 不参与此损失。
- 复用原 `structure_forward()`，在 `no_grad` 下生成真实候选；不注入标注原子、不改筛选阈值。
- 复用原 selected 匹配及 6 px 半径，通过已有监督契约区分确认正边、确认非边、端点对应未知三类。
- 只有确认正/负样本参与原 pair loss，未知 pair 不当成负例。所有目标键、不可达键、未匹配候选和未知 pair 仍计数。
- 显式保留原负采样参数 `negative_ratio=6, minimum_negatives=48`；没有已知 pair 时返回 skip，不伪造零损失或更新步数。
- 没有优化器、学习率选择、checkpoint 保存、数据准入或部署逻辑；该类不能单独视为一份可开跑的训练协议。

合成测试确认只有 pair 收到梯度，上游特征/参数和输入图像不收梯度，未知 pair 不进入损失。另用随机初始化的微型**现有 DirectAtomPairBond 类**验证前反向兼容，不读取真实模型权重。

对于已知对应候选不超过 7 个的样本，总 pair 最多 21 个，原 `minimum_negatives=48` 会保留全部确认负例；2–7 候选的合成测试逐一验证。因此在这个条件下无需先新增一套难负例挖掘器。但这并不证明某个真实训练样本的上游匹配条件成立，也不复原历史采样和梯度。

## 四、下一步与停止条件

1. 先补不同训练身份的干净 N–N 单键、N–S 单键小分子，不能把上一轮 16 张验证图转为训练图。新增分子先隔离生成并验证同源图/标签；本轮未开展新的身份查询或授予准入。
2. 保留上述跨节点假边、真实 O–O，以及基础 C–N 等控制。不能只生成正键或仅增加同分子图片变体来制造覆盖充分的印象。
3. 覆盖补齐后，再固定一份训练侧小清单，对原 initial 做一次有预算的可达性检查；端点缺失/未知对应仍计入完整分母。候选筛选问题不在此次 pair 更新中同时修。
4. 只有数据准入、候选可达性、单组件冻结和验收条件成立，才申请新的定额真实训练。不沿用已消耗的旧 GPU 许可，不将当前 `panel.json` 当成正式训练 release。

这一步把“继续扩大图片数量”转成了可核验的教材缺项和单组件入口，不是换架构或宣布问题已修复。

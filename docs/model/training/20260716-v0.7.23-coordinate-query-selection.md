# 2026-07-16 v0.7.23 纯坐标分配与独立排序

## 目标

解释 Atom Query 明明生成了接近真实原子的候选，却在 top-k 中选错顶点的问题；
对照 MolGrapher 的密集 Gaussian 顶点检测，修复 query 正样本分配、最终坐标评分和
计数/排序耦合。MR-TADF 与 USPTO 未参与训练、调参或 checkpoint 选择。

## 数据与基线

- 训练：MolGrapher synthetic pilot 的 9,000 张 train 图片；
- 验证：scaffold 独立的 1,000 张 validation 图片；
- 基础视觉 checkpoint：`outputs/checkpoints/chemvector-v079-relation-all-pairs-9k/last.pt`；
- query 初始化：`outputs/checkpoints/chemvector-v0721-molgrapher9k-count-decoder2-12k/best.pt`；
- 旧基线：set-count 6px F1 `40.14%`，Count exact `23.9%`；
- 旧 coordinate Oracle：6px F1 `62.70%`，vertex exact `0.8%`。

## 根因隔离

旧 Hungarian 代价为：

```text
L1(final_center, target) - 0.2 * presence_probability
```

坐标位于 `[0, 1]`，`0.2` 在 768 图上相当于最多约 154px 的曼哈顿距离补偿。
高分但更远的 query 因而可能抢走更近 query 的正样本身份，并通过 presence BCE
继续强化自己。

同一 validation 1k 的零训练隔离结果：

| 匹配方式 | 6px F1 |
|---|---:|
| L1 - 0.2 × presence | 44.72% |
| 纯 L1 | 62.50% |
| 纯 L2 | 62.70% |

MolGrapher 使用 stride-4 密集热图、每原子尺度自适应 Gaussian、全像素 MSE 和区域
极大值，没有 query 身份竞争。v0.7.23 借鉴其局部连续监督思想，但不采用最近邻边、
估计键长、`1.75×` 长键删除或空白线段删边。

## 代码改动

1. Hungarian 正样本分配改为最终坐标的纯 L2 一对一匹配，presence 不再参与。
2. 最终中心附近的 stride-4 局部特征进入 selection 排序。
3. `presence` 只负责计数，`ranking_presence + local selection + context` 负责 top-k。
4. 计数校准不会再改变 ranking presence，避免修计数时破坏排序。
5. duplicate 几何的零距离开方增加下界，修复 `sqrt(0)` 导致的非有限梯度。
6. 增加 `--checkpoint-f1-first`，selector 实验可按原子级 F1 选择 checkpoint。

## 决策

- 纯坐标 assignment：GO；
- 最终坐标感知 selector：GO；
- presence、selection、ranking presence 解耦：GO；
- 继续把同一 selector 训练到 90k：NO-GO，20k 后过拟合；
- 计数问题：未解决，Count exact 仍低于旧基线；
- 稳定推理替换：NO-GO，尚未接 relation 和 SDF 端到端门控。

下一步增加 MolGrapher 式 stride-4 Gaussian dense 辅助监督，提高 coordinate Oracle
的 6px 精度；Atom Query 继续负责集合和一对一选择，relation 继续读取全部顶点点对的
真实线条，不增加任何键长阈值或候选边预删除。

## 独立复核修正

三路独立审查确认旧 Hungarian 自强化是真实问题，但不能把 v0.7.23 的全部收益归因
于 assignment。纯坐标训练只将 coordinate Oracle 从 62.70% 提高到 65.39%；主要
部署收益来自 selector 与计数/排序解耦的组合。当前 ranking presence 是从旧 presence
复制并冻结的 prior，不是独立训练的新 head；零训练消融已在 v0.7.24 继续验证。

同一 validation 1k 被用于多轮 checkpoint 选择，且只有一个训练 seed，因此 1-3pp
的小差异可能存在 winner's curse。后续结论以跨字体 internal test 和新公共集门控为
补充，不把 known-count 或 coordinate Oracle 当作端到端指标。

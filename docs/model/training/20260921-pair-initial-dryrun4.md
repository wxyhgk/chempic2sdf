# 真实initial：四图无参数更新检查

## 结果

新旧loss入口在真实initial的**4张图上均通过当前CPU对照**：

- 两个arm的完整raw候选、selector输入和输出逐值哈希相同，已选候选不变。
- 原子、键候选、selector、文字角色及bbox五项非pair loss完全相同，文字路径完全相同。
- 每个arm共有54条原有正例，全部保留；没有构造新正例。
- 旧arm实际送入键头的52个“任一端未匹配”pair，在新arm中为0。
  **这52个是归属不确定的采样pair，不等于52条真实化学键或52个确认错误。**
- 空监督pair分支不执行键头、无键头梯度，整体loss有限；其余7次pair反向梯度均有限。
- 所有模型参数和buffer的SHA保持原始initial状态不变；最终梯度已清空。

实际CPU耗时**10.236秒**，8次完整前向、7次仅键头的反向，零优化器、零更新、零GPU、零新权重。
相关测试 **139 passed / 2.26秒**。没有重新评估完整SDF，没有准确率提升结果。

## 运行方式与不变量

- 只加载自包含`initial.pt`一次，checkpoint SHA：
  `09d1661198bde9b80dc2a4398a9a6d7d856098a2af1cc4e05425fe5e3c88dbe1`。
- 全模型eval、FP32、CPU两线程；仅`pair`参数开启自动求导，其他组件均冻结。
  这是诊断配置，不是已经批准的新训练配方。
- 每张图各运行原入口及`matched-only-v1`一次，同图两arm使用同一固定随机种子。
- 实际loss函数自行运行图像前向。观察hooks只读取输出，不替换预测或标签，不向模型传入化学真值。
  每个atom输出额外解码一次用于观察grid ID，并与真实selector输入逐张逐值核对；没有新增图像前向。
- 单独对pair loss反向，检查有限梯度和冻结组件无梯度，不创建优化器或调用step。
- 每个arm前后检查全模型state哈希；旧、新arm之间先清除梯度。
- 上限240秒、8次完整前向、最多8次pair反向；无自动重试，未加载OCR或读取开发/封存测试逐图文件。

## 怎样解释loss变化

ddc的pair loss从2.829427变为0，是唯一pair被暂不监督后的空分支结果，不是模型学习进步。
00f和6de的pair loss分别从0.133900→0.046318、0.077385→0.032702；
由于监督样本组成改变，也不能把这种下降当成准确率改善。
04a的全部loss及键头梯度范数完全一致，是未触发掩码时的对照。

此检查没有证明：训练模式或GPU下同样稳定、共享视觉参数方向合理、缺失正例恢复、
实际分子图连接改善。它证明的是**真实初始权重下，当前CPU路径能执行新监督规则而不改变候选、
非pair损失或冻结状态**。

## 下一步建议

现有结果支持准备一次只动键头的小额试训协议，而非继续扩大模型或数据规模：

1. 明确记录`matched-only-v1`、初始权重、冻结范围、停止条件和资源上限，不能复用已消耗的旧试训授权。
2. 如果使用GPU，应在运行设备上重新生成并绑定候选/目标；不得把历史slot标签接到新设备候选上。
3. 先处理试训入口和checkpoint元数据对新监督策略的记录，再申请/确认执行；本轮未切换旧launcher。
4. 验收看实际节点与键连接、完整分子结果和基础能力回退，不按训练loss下降判成功。

新掩码只避免不确定pair被继续当作无键负例，仍未给原来缺失的连接补上正监督。

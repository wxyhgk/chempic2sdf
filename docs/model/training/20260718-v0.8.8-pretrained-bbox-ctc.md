# v0.8.8 预训练 bbox CTC

> 状态：OCR 组件路线 GO，端到端接入 NO-GO  
> 输出：`outputs/checkpoints/chemvector-v088-pretrained-bbox-ctc-10k`

## 目标

保留 v0.8.7 的 bbox ROI 和非自回归 CTC，但不再从零学习笔画。复用 v0.8.6 已训练
Pixel OCR 的三层卷积和 256 个 byte 分类向量，去掉 8×8 自适应池化，让 48×192 crop
保留 48 个横向时间步。视觉卷积冻结，只训练一层 Transformer 上下文和 CTC 输出头。

## 容量实验

1,000 个 train crop、1,000 个 validation crop、12 epoch：

- overall exact：48.90%；
- modifier exact：32.39%；
- simple exact：61.15%；
- 可训练参数：507,137。

只使用 v0.8.7 十分之一的数据就超过其 47.15%，因此进入 10k 实验。

## 10k 结果

10,000 个 train crop、2,000 个 validation crop、50% 黑白和 50% CPK 彩色：

| 指标 | v0.8.7 从零 CTC | v0.8.8 预训练 CTC |
|---|---:|---:|
| overall exact | 47.15% | 86.20% |
| modifier exact | 28.57% | 80.70% |
| simple exact | 62.88% | 90.86% |
| color exact | 未单列 | 86.23% |
| black/white exact | 未单列 | 86.18% |
| false modifier | 3.60% | 2.03% |

最佳 checkpoint 对 `N/O/F/NH/OH` 已有较高准确率，但 `NH2/N+/Cl/Br/I/Se`
仍受长尾样本影响，不能只看总体平均值。

## 部署协议门控

训练指标使用真值 bbox。为了避免训练和推理协议不一致，新增
`evaluate_detected_ctc_ocr.py`，分别测量预测顶点、预测 TextObject bbox 和真值 bbox。

约 500 图同分布结果：

| 协议 | 检测召回 | matched OCR exact | modifier exact |
|---|---:|---:|---:|
| 最终部署顶点 + 预测 bbox | 96.31% | 64.74% | 21.97% |
| TextObject 中心 + 预测 bbox | 98.86% | 64.12% | 22.38% |
| 真值中心 + 真值 bbox | 100% | 74.80% | 37.63% |

最终顶点和文字框关联不是主要损失来源。预测 extent 造成约 10.7 个百分点净损失，
而全部标签分布下真值框也只有 74.80%，说明 CTC 的长尾覆盖仍不足。

预测框统一放大网格中，1.25× 只把 200 图 exact 从 63.55% 提到 65.13%；2× 虽然
提高 modifier，却把 false modifier 推到 13.05%。统一放框判定 NO-GO。

## 真实彩色图

包含四个蓝色普通 N 的真实图：

- v0.8.6 原始 OCR：`NH/N+/N+/N+`；
- v0.8.8 原始 OCR：`NH/NH/N/NH`；
- 价态修复后的 ChemScene：四个均为 `N`。

CTC 消除了错误正电荷，但仍有显式 H 幻觉，因此真实图门控未通过。

## 决策

预训练视觉表征加非自回归字符头的路线保留；v0.8.8 不替换稳定默认。下一版应：

1. 用预测 bbox 的真实误差分布生成训练 crop，而不是只用真值框随机 context；
2. 按字符串结构和频次均衡 `NH2/N+/Cl/Br/I/Se` 等长尾组；
3. 同时报告真值 bbox、预测 bbox、真实论文图三层门控；
4. 不使用 MR-TADF 分子作为训练或调参数据。

# R5 text/line seam contract

The accepted identity-aligned panel already contains the required CPU-side
artifacts; a new renderer is not needed for a seam feasibility check.

Each accepted sample has:

- `.text-records.json`: glyph text, atom id, integer in-image bounding box,
  font/style metadata and source hashes;
- `.text.png`: same-render text raster mask;
- `.bond.png`: same-render bond raster mask;
- `.layers.json`: atom centres/visibility and exact bond `begin`/`end`
  coordinates;
- `.graph.json`: post-hoc chemistry labels only.

The read-only contract audit covers 1,170 images (696 train, 474 holdout):

| quantity | train | holdout |
| --- | ---: | ---: |
| visible glyph atoms | 2,148 | 1,530 |
| text pixels outside recorded glyph boxes | 0 | 0 |
| glyph-box overlaps | 0 | 0 |
| line-endpoint atom coverage | 100% | 100% |
| glyph/line union atom ceiling | 100% | 100% |
| bond geometry record ceiling | 100% | 100% |

Thus a minimal CPU manifest can be generated by joining the existing
`samples.jsonl` rows with these immutable artifact paths and source hashes. A
CPU renderer is only required when adding new identities/styles; it must emit
the same files and reject clipped/overlapping glyphs before admission. This
audit is an upper-bound contract check, not a training authorization.

# v0.7.37 渲染真值与候选等价组

## 问题复核

v0.7.34 的文字头使用 `layers.atoms[].visible_text`，但隐式顶点头和部分 OCR
加载器使用 `atom_display_text(ChemMol atom)` 推断图片是否显示字符。两套协议在
validation 498 张、16,922 个原子中有 710 个不一致：

```text
图片隐藏、语义函数判断可见    696
图片可见、语义函数判断隐藏     14
```

典型错误是图片中未画出的碳被语义函数写成 `CH`。OCR 和顶点角色现在统一使用每张
图片的 Render Layer 真值；ChemMol 中的元素和氢数继续作为结构语义保存，但不再
冒充视觉文字标签。

## 候选与解码

```text
TextObject 0.05 候选 + ImplicitVertex 0.05 候选
    -> 全点对冻结线条证据，不按距离或键长删边
    -> 同角色、同一真实顶点 6px 内候选组成等价组
    -> 每组至少一个 REAL，组外候选为 NULL
    -> 推理按同角色 6px 抑制重复峰
    -> REAL 概率阈值直接决定输出数量
```

6px 抑制只合并同一顶点的替代峰，不用于判断化学键，不设置最大键长。

## 结果

修正标签后的 498 张候选覆盖：

```text
Candidate recall                 98.71%
Candidate Oracle exact           86.75%
去重 Candidate Oracle exact      86.35%
```

9k 训练、498 张独立 validation，提供真实角色 Count 时：

```text
原始分数 + 去重 exact            61.24%
单候选 Hungarian selector        66.67%
候选等价组 selector               70.48%
候选等价组 F1                     97.78%
```

不提供 Count，直接对 REAL 概率扫描，最佳阈值为 `0.70`：

```text
Count exact                      62.45%
Vertex exact                     55.82%
Precision                        98.64%
Recall                           97.11%
F1                               97.87%
```

整数 Count 分类器在相同 9k/498 上判定 NO-GO：两个角色同时计数正确仅 7.43%，
预测 Count 后 vertex exact 为 7.23%。组级 REAL/NULL 阈值解码不再依赖该分类器。

## 决策

- Render Layer 作为 OCR/角色视觉真值：GO；
- 同顶点候选等价组监督：GO；
- 同角色 6px 重复峰抑制：GO；
- REAL/NULL 阈值 `0.70`：进入 shadow 端到端骨架评估；
- 独立整数 Count 分类器：NO-GO；
- 稳定推理继续使用 v0.7.10，本轮不打 tag、不替换默认模型。

## 端到端骨架接入

新增独立评测入口：

```bash
.venv-train/bin/python -m chemvector.evaluate_group_selector_bond \
  --selector-checkpoint outputs/checkpoints/chemvector-v0737-group-selector-9k-45k/best.pt \
  --bond-checkpoint outputs/checkpoints/chemvector-v0736-node-conditioned-bond-9k-45k/best.pt \
  --validation-shards Data/sdf/chemvision_layers_v0_1/pilot_10k/shards/validation-000000.tar \
  --output-dir outputs/evaluations/chemvector-v0737-group-selector-bond-validation498 \
  --samples 498 --batch-size 4
```

完整链路为：

```text
Text/Implicit 0.05 高召回候选
    -> Group selector REAL >= 0.70
    -> 同角色 6px 重复峰抑制
    -> 全部已选端点对
    -> v0.7.36 NodeConditionedBondObject
```

没有最近邻截断、键长阈值或长键预删除。`<=48px / 48-96px / >96px` 只用于
报告，不参与推理。

498 张结果：

| 指标 | v0.7.36 旧预测端点 | v0.7.37，bond=0.85 | v0.7.37，bond=0.80 |
|---|---:|---:|---:|
| 坐标 vertex exact | 9.84% | 56.83% | 56.83% |
| 角色严格 vertex exact | 未记录 | 56.02% | 56.02% |
| Edge F1 | 84.44% | 94.98% | 94.97% |
| 匹配端点条件 Edge recall | 98.70% | 98.36% | 98.60% |
| 顶点正确条件 Edge exact | 79.59% | 69.96% | 72.79% |
| Strict skeleton exact | 7.83% | 39.76% | 41.37% |
| DOUBLE edge recall | 82.42% | 92.87% | 93.24% |
| TRIPLE edge recall | 10.00% | 35.00% | 35.00% |

`bond=0.80` 在 validation 上比 checkpoint 原阈值 `0.85` 多 8 张严格骨架正确，
但只作为下一版 shadow 候选，不修改 v0.7.36 checkpoint，也不替换稳定推理。

长度诊断在 `bond=0.80` 下为：

```text
<=48px   端到端 recall 90.52%，匹配端点条件 recall 98.78%
48-96px  端到端 recall 95.61%，匹配端点条件 recall 98.81%
>96px    端到端 recall 80.62%，匹配端点条件 recall 92.84%
```

长键没有被候选协议删除，但键读取器对预测端点的小坐标偏差仍更敏感。旧评测没有
长度桶，因此本轮不能声称长键回归门控已通过。补做同图真实端点对照后，`bond=0.80`
的真实端点长键 recall 为 97.04%，预测端点条件 recall 为 92.84%，明确存在 4.20pp
端点分布偏移；该项转入 v0.7.38。

## 最终结论

- Group selector 接入 Bond Object：GO；
- 角色严格 vertex exact `>=50%`：通过；
- strict skeleton exact `>=35%`：通过；
- 匹配端点条件 Edge recall 相对旧链路回退不超过 1pp：通过；
- DOUBLE/TRIPLE 端到端 recall：均高于旧链路；
- `bond=0.80`：shadow 候选，不进入稳定默认；
- `>96px` 长键与芳香/Kekule 键型：下一轮问题；
- 稳定推理继续使用 v0.7.10，本轮不打 tag。

# 连键存在性小试验：训练 10/24 → 19/24，旧干净验证 8/16 → 11/16

一次获准的 CPU presence-readout 试验已完成：**66.001 秒、200 次更新、GPU=0**。仅更新现有 `pair.presence` 的 256 个权重和 1 个偏置，其他模型参数与 OCR 冻结，原 0.85 连键阈值不变。训练侧 12 根可达漏键全部补上、1 条确认误连消除；原干净验证 16 图新增救回 3 图，没有原来严格正确的图变错。

这是单组件可学习性和小范围回归的正向证据，**不是整体准确率已提高的结论**。24 图已参与拟合，16 图也是此前用于定位问题的旧干净验证切片，不是新的盲测；完整固定开发集未重跑。默认仍为 `initial`，历史完整分子结果仍为 **170/800**，没有部署或自动启动下一次训练。

准备和产物沿用 `20260918` 标识；实际试验完成于 **2026-09-19（Asia/Shanghai）**。

## 数据、训练设置与范围

用户对“检查通过后，CPU 最多 5 分钟、200 步，开一次定额试验”回复“开始”，后续“继续推进”继续同一次授权，不增加运行次数。

- 继承已有公开/私有核验回执，无新候选、无新身份查询、无封存内容访问。已排除的甲磺酰胺不回填，原 13 个全局公开身份覆盖缺口及旧验证内部组问题未被本次修复。
- 全量保留原 clean16 验证切片，训练身份、连接层身份和 core/group 与旧 release 的全部验证清单排重。16 图不进入训练缓存或损失。
- 发布采用专用 `chemvector-presence-probe-release-0.1` schema，不放宽普通混合训练入口；只允许本次局部 readout 拟合，不授权一般混合训练或部署。
- 从原 `initial.pt` 出发，固定种子 20260918；Adam、学习率 0.01、weight decay=0、梯度裁剪 1，一套设置、不搜索。
- 先对 24 张训练图缓存模型预测 pair 的冻结 hidden；共 **240 个已知 pair：89 正例、151 确认负例**。保留所有确认非边，3 个未知对应 pair 不进入损失。GT 只用于事后匹配、标签和评分，不注入模型输入或预测候选。
- presence 采用原正类加权 BCE；全量已知 pair 同批、200 步、保存最后一步，不按验证结果选 checkpoint。
- 基线和更新后各推理 24+16 图，共 **80 次上游前向**。40 个基线结果重现已保存记录，40 个前后预测的节点/hidden/原始 chemical logits/role/OCR 一致性检查通过。

外层 CPU 300 秒限制覆盖 worker 初始化、基线、更新、最终推理及保存；另有不加载模型、不保留试验次数的发布/运行前置检查。试验运行次数已消耗，无自动重试或恢复。

## 没有被这次训练修好的问题

训练剩余 5 图：

| 目标身份 | 更新后输出 | 保存轨迹支持的限制 |
| --- | --- | --- |
| `CCNN` | 无效 | N–N 从漏连变为已连，但冻结键型原本预测 DOUBLE；`NH2` 端点因此价态超限。同时原 `NHH` 解析失败仍在 |
| `CNNC` | `CCNC` | 原 `NH → NHH → 解析失败 → C 占位` 未修复 |
| `NNC=O` | `NCC=O` | 原文字解析失败及一个端点对应不足未修复 |
| `N=N` | `[NH][NH]` | 原键型/非环芳香处理问题不在 presence 更新范围内 |
| `C#C` | `C` | 原 selector 丢端点，唯一三键正例仍不可达 |

`CCNN` 更新前是**有效但错误**的 `CCC.[NH2]`，更新后变成无效：补连接暴露了原本隐藏的键型错误。另一个含硫控制从无效变为正确，两者相抵使训练有效率保持 23/24；不能只看总有效率便忽略前者。局部已连键型错误 3→4 也来源于此，**不是冻结 chemical 权重或原始 logits 被改变**。

验证仍失败的 5 个身份为 `C=CC`、`C=CC(=O)O`、`C[S-]`、`C[NH3+]`、`C[N+](=O)[O-]`。它们仍涉及上游节点缺失、文字/电荷或键型等限制，本轮未进一步干预这些路径。

## 能支持的判断和下一步

本次证明：**在这批固定样本上，已有冻结特征能被同一个线性 readout 分出真实连接与确认非边**。暂时没有必要以这些连键错误为由更换 MoE/循环架构或重训整个视觉模型。

但 readout 有 257 个可调参数，而已知训练 pair 只有 240 个，拟合成功不等于泛化；这次也没有证明旧训练退步的全部原因或最佳长期训练方法。

建议按以下顺序，不自动执行：

1. **先做完整固定开发集的无更新回归。** 固定此 delta、原 initial、原阈值和原评分，报告严格身份救回/改错及有效性，禁止边看结果边调参。按实际用时登记单次 CPU 推理预算，不开启新训练；封存测试仍不动。完整 800 图尚未执行，不能将当前 11/16 替代 170/800。
2. 同时优先处理已确认的文字解析失败状态契约：显式保留未知/失败，不能默默把解析失败当成已识别 C，也不硬编码 `NHH→NH`。先做合成契约测试及原保存案例核对。
3. 完整回归若无明显退步，再讨论下一次最小训练范围。全 pair/chemical 训练仍需要可达三键控制等前置条件；不因这次 presence 有效就自动解冻共享特征或增加 GPU 轮次。

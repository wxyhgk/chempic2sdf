# 2026-07-18 v0.8.0 ChemScene Bond-First

> 状态：协议与编译链完成，模型训练待 v0.8.1  
> 基础 checkpoint：v0.7.38 shadow，仅作为视觉编码器候选初始化  
> 输出目录：尚未产生新 checkpoint

## 目标

停止继续优化“先产生大量点候选，再判断哪些点是真的”这条已进入平台的路线。
v0.8 把整张化学结构图建模为对象场景：模型直接预测完整 Bond Object 和 Text
Object，再由对象端点汇聚出 Junction，最后确定性编译为 SDF。

本版本先完成可训练目标协议和无损编译边界，保证下一版网络预测的每一个字段都能
被严格验收。

## 第一性原理判断

v0.7.42 到 v0.7.46 一直在同一矛盾上折中：降低线内假点会增加漏点，扩大候选池只
带来极高点对成本。原因不是分类器还少一个局部特征，而是对象分解顺序不对：

```text
旧路线：像素 -> 大量点 -> 删除假点 -> 全点对找键
新路线：像素 -> 完整键对象/文字对象 -> 汇聚真实端点 -> SDF
```

双键、三键和楔形键是一个整体视觉对象。把内部平行线端点当成独立顶点候选，会让
模型承担一个原任务中不存在的组合爆炸。

## 数据

- 协议验证：ChemVision pilot validation 500 张。
- 扩展验证：首个 train shard 3,000 张。
- MR-TADF：未参与协议设计、阈值或 GO 决策。
- 数据无需重建，从 ChemMol/Render/Layers 动态生成 ChemScene。

## 本版实现

- `Junction`：真实化学顶点，角色为 `TEXT` 或 `IMPLICIT`。
- `TextObject`：开放字符串、中心和 bbox，与几何连接解耦。
- `BondObject`：两个端点、视觉键型、化学键型、方向、立体参考和 bbox。
- `ChemScene -> ChemSVG v0.4 -> RDKit -> SDF` 确定性编译。
- 原坐标无法无损编码 SDF 立体时，仅对 SDF conformer 做规范二维重排。
- 禁止最近邻、键长阈值、长键删除和隐藏 atom ID。

## v0.8.1 模型边界

下一版只做固定 100 图容量实验，暂不直接扩到 9k：

1. `Bond Query` 直接预测一个键对象的 presence、两个端点、bbox 和 display class。
2. `Text Query` 独立预测文字 bbox/anchor；OCR 复用现有 Pixel OCR，不让键分支学字符。
3. `Junction Assembler` 对 Bond 端点与 Text anchor 做集合式汇聚，禁止从键线中间生成点。
4. 训练使用对象级 Hungarian 匹配；双键无论有几条像素线都只匹配一个 query。
5. 第一门槛是 100 图 BondObject exact 和 Scene SDF exact，不用局部端点 F1 代替整图指标。

## 门控标准

- 固定 100 图训练内 Scene SDF exact 至少 95%，证明结构容量成立。
- 双键/三键对象 count exact 为 100%。
- 不允许任何按键长删除对象的逻辑。
- 通过容量门槛后再进入 scaffold 和字体独立的 9k/498 泛化实验。

## 决策

ChemScene v0.1 协议和确定性编译链 `GO`。尚未产生可替换 v0.7 稳定推理的新模型，
因此模型效果不宣称提升。下一步进入 v0.8.1 Bond Query 100 图容量实验。

# Selector 压分来源：负例计数与排序也会牵连正确端点

在固定 `C#C`、`C#[13CH]`、`C#CC`、`CCC#N` 四张旧诊断图上，
把现有 selector 损失的真实参数梯度拆开，结果支持更具体的解释：

**不是分类标签要求删除端点，而是多个候选共享参数；压低错误候选的梯度也会压低正确端点。**
在 `C#C` 中，原子计数项的负例部分对正确端点的压分，大于其正例部分；排序项的净作用也在压分。
这解释了上轮为什么仅隔离正例计数，两个端点仍然不能获得局部升分方向。

结论仅针对 initial、固定候选、eval 模式的局部 Euclidean 参数方向。
没有参数更新、没有新预测、没有得到新的准确率，也不是历史整分子回归的完整因果证明。

## 1. 怎么拆，如何保证可加

沿用原来 7 项加权损失：

```text
atom focal + 0.5 atom ranking + 0.1 atom count
+ bond focal + 0.5 bond ranking + 0.1 bond count
+ incidence
```

其中三项 atom 损失进一步按 raw 正例/负例的分数导数来源分开，共 10 个梯度分量。
分量是链式法则的记账，不是新增 10 个训练目标。
topology closure、graph-exact surrogate 保持原权重 0。

所有贡献统一除以**原完整损失的参数梯度范数**，不逐项归一化：

```text
某项对候选 i 的贡献 = - J_i · gradient(loss_component) / ||gradient(full_loss)||
各项相加 = 该候选沿原完整单位负梯度方向的一阶变化率
```

因此既能比较幅度，也能加回上轮的总方向。原完整目标和上轮计数隔离对照的方向都已复现。
为比较相对排序，使用 `J_positive - J_hard_negative`；负例来自旧缓存最高分 raw 负例，
同分取最小槽位，并在模型加载前固定。不换图片、不注入 GT 候选。

## 2. C#C 的具体分解

原来 candidate 0 是保留的错误候选，candidate 1、2 是被丢弃的正确端点。
下列数字为同一尺度下的一阶分数变化率，**不是训练一步之后的 logit 差**：

| 来源 | 正确 candidate 1 | 正确 candidate 2 |
| --- | ---: | ---: |
| 原子 focal 合计 | +3.0603 | +3.0007 |
| 原子 ranking 合计 | -5.4882 | -1.1219 |
| 原子 count：正例部分 | -1.7870 | -1.7244 |
| 原子 count：负例部分 | **-5.5942** | **-5.5957** |
| bond count | -3.3510 | -2.9248 |
| bond focal、bond ranking、incidence 合计 | +3.4229 | +3.0662 |
| 原完整目标 | **-9.7373** | **-5.2999** |

关键区别：原子 count 的负例分支对正例 logit 没有直接导数，
但它通过共享参数对正例分数产生明显负向作用。因此仅把正例概率在 count 内 detach，不能消除它。
这里的负例包括全部未匹配 raw 候选，不能把所有作用都归给那一个最高分错误候选。

候选分数的参数 Jacobian 也高度相关：

- 错误 candidate 0 与正确 candidate 1 的余弦约 **0.9123**。
- 错误 candidate 0 与正确 candidate 2 的余弦约 **0.8379**。

这是参数敏感方向相似，不等于证明输入特征完全不可分，也不是模型架构无效的证据。

## 3. 排序项为什么也会压低正确端点

`C#C` 中 atom ranking 对 candidate 1 的两个来源分别为：

- 提高最弱正例的部分：+18.8266。
- 压低最高分负例的部分：-24.3148。
- 合计：-5.4882。

candidate 2 同样是 +20.5556 与 -21.6775，相加为 -1.1219。
尽管正确候选也下降，错误候选下降更快，所以相对排序依然改善。

完整目标下，两个正确候选相对错误候选的分数差变化率分别为 +10.9726、+15.4100，
但它们自身的分数仍下降。**相对排序目标不等于固定门槛下的端点保留目标。**

对照图 `CCC#N` 的被丢弃正例 candidate 3 则获得 +5.6537 的总方向，
其排序提分部分大于负例压分部分。这也说明不能笼统断言现有损失对所有端点都无效。

## 4. 不跑模型，检查“统一调小 count”是否足够

另用保存的梯度分解做了一个闭式区间检查，没有模型前向、权重网格搜索或配置变更。
只讨论一个严格限定的族：同时将原本系数 0.1 的 atom count 与 bond count 乘以 `alpha ∈ [0,1]`，
其他项不动。

每个候选的一阶方向可写为：

```text
d(alpha) = 非计数部分 + alpha × 原计数部分
```

使用保守局部条件：11 个探查正例都不降分，4 个最高分 raw 负例都不升分。
方向分母仍取原范数；换成新梯度的正范数不改变符号。

两个限制已互相冲突：

- `C#C` 正确 candidate 1：`0.994930 - 10.732251 alpha >= 0`，要求 **alpha ≤ 0.092705**。
- `CCC#N` 负例 candidate 4：`2.035431 - 9.317627 alpha <= 0`，要求 **alpha ≥ 0.218450**。

因此这个族在上述局部验收条件下没有可行区间，不宜直接把“统一减小计数权重”包装成充分修复。

重要限制：`CCC#N` 的这个负例原 logit 为 -1.1005，本来就在 -0.25 阈值以下。
允许它短期升分，未必马上产生假原子；这里施加的是更保守的“继续抑制”条件。
这不是证明任何计数权重试训都会失败，更不排除独立调节 atom/bond、其他目标、
真实 AdamW、混合 batch 或有限训练后产生不同结果。

## 5. 下一步怎么收敛

目前不需要据此换 MoE/主干，也不能只删除 count 或重复扩大训练。
损失排查已经足以确定下一项最小验证的验收条件：

1. 被删的正确端点能向固定保留门槛靠近，而不只是相对背景排序提高。
2. 已保留正确端点不被同步压掉，同时检查重复/背景候选的分数和剩余门槛余量。
3. 两个端点必须一起验收，再看对应键是否可达；不能只看平均候选数或平均 loss。

下一步只验证一个显式考虑保留门槛的正例保留约束原型，与现有排序、负例抑制一起检查；
不直接接入正式损失、不搜索一组权重、不改 threshold，不用整图训练来猜它是否有效。
通过固定反例和原 32 图的约束检查后，才讨论明确预算的 selector 试训及旧完整分子回放。
该原型本轮尚未实现，本轮没有授予训练权限或发布 quarantine 数据。

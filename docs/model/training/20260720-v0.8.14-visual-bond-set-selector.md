# v0.8.14 冻结视觉 Bond Set Selector A/B

> 状态：容量 GO，9k 泛化 NO-GO  
> 日期：2026-07-20  
> 对照：v0.8.13 仅几何、分数和预测类型的集合 selector

## 假设

v0.8.13 在 500 张可以利用 96.25% Candidate Oracle，但 9k 泛化只有 43.21%。本轮
验证失败是否因为集合模型没有视觉证据。

`DenseBondObjectDetector` 新增只读 `object_features` 输出。每个候选从其预测中心取得
128 维 detector hidden，与原有 26 维几何、分数和类型特征拼接。视觉编码器和 Bond
detector 全部冻结，不改变候选集合，也不允许 MR-TADF 参与选择。

## 结果

### 固定 500 张容量

| 指标 | 无视觉 v0.8.13 | 冻结视觉 v0.8.14 |
|---|---:|---:|
| Count accuracy | 100% | 99.80% |
| 严格拓扑 exact | 87.20% | 87.40% |
| Oracle 利用率 | 96.25% | 96.47% |
| SDF exact | 75.20% | 75.00% |

视觉特征没有破坏容量，但也没有提供明显容量增益。

### 8,974 / 498 泛化

| 指标 | 无视觉 v0.8.13 | 冻结视觉 v0.8.14 | 原始 threshold=0.25 |
|---|---:|---:|---:|
| Count accuracy | 41.37% | 38.76% | 58.84% |
| 严格拓扑 exact | 38.35% | 34.34% | 56.02% |
| Oracle 利用率 | 43.21% | 38.69% | 不适用 |
| SDF exact | 35.74% | 31.12% | 52.21% |

冻结的中心 cell hidden 正式 NO-GO。它主要重复 detector 已经压缩进 score/type 的局部
信息，没有告诉集合模型“两个端点之间是否存在连续线条”，也没有让集合损失反向修正
detector。

## 决策

- 不继续扩大冻结 hidden selector 的数据量。
- 下一轮视觉证据必须沿完整 Bond line band 读取，而不是只采样中心 cell。
- 优先复用 v0.7.38 的 Node-conditioned BondObject edge reader，为每个低阈值 Bond
  candidate 提供 edge/display/chemical logits，再做相同集合 A/B。
- 如果 line-band 特征仍无收益，才进入 detector 与 set selector 的联合反向传播。

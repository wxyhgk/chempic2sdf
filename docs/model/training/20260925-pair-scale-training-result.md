# 万图连键训练：完整一遍结果

## 结论

本次万图级单遍训练已完整执行，GPU、吞吐门槛、数据覆盖和四次开发检查均正常。
但训练后的 pair head **没有通过整图开发验收**，因此保留 initial，不部署、不继续第二遍。

这次不是因为训练数据太少或只跑了前缀：实际覆盖了全部 **12,985 张不同训练图片**，
完成 **15,443 次访问 / 15,282 次优化更新**。结果显示当前瓶颈不是简单增加 pair 训练量就能解决：
课程图明显改善，而完整分子结构的 exact、valid 和 fallback 没有同步改善。

## 执行核验

- GPU：NVIDIA GeForce RTX 5090，CUDA 12.8，PyTorch 2.10.0+cu128，FP32。
- 单 GPU 0；预算 3,600 秒，实际外层耗时 **1,384.773 秒**，无重试、无续训。
- 64 张固定训练图吞吐测量通过：平均 0.0736 秒、p95 0.1044 秒；预计完整任务约 2,833 秒。
- 训练访问：15,443；冻结上游前向：15,443；开发集评估：4,720（初始 + 四个检查点）。
- 不同训练图片：12,985；其中 161 次没有可用配对监督，记录并跳过更新，没有伪造 loss。
- 开发集固定为 944 张：完整分子 800、课程图 144；没有读取封存测试，没有新增身份查询。
- 视觉、原子、键候选、selector、role、bbox、OCR 均冻结，仅更新 pair head。
- 旧数据发布和 initial 未修改，默认模型未替换。

## 判断

1. 数据覆盖问题已被排除：确实完成了 12,985 张不同图的一遍访问。
2. 单纯 pair-only 更新的学习信号偏向基础课程域，无法稳定改善复杂完整分子。
3. 完整分子的 fallback 增加，说明 pair logits 的局部改善会通过图编译／化学约束放大为整图风险。
4. 当前不应再追加第二遍、调低阈值或部署 `pair-015443.pt`；这些都会把一次失败的开发结果包装成进步。

## 下一步

下一步应做已保存结果的只读归因，不再直接加训练量：

- 对 9 张 broken 和 6 张 rescued 完整分子逐图比较 pair presence、键型、芳香提升、编译错误和 fallback；
- 区分“pair 键判错”与“pair 正确但角色／文字／整图编译失败”，因为本轮后者仍被冻结、不能靠 pair 单独修好；
- 统计 full-molecule 的复杂度、字号、线宽和键型分层退步，确认是否集中在大分子／压力样式；
- 再决定是否需要联合训练上游候选或图编译约束。新训练必须另定单一变量和授权，不能复用本次许可。

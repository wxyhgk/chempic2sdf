# v0.9.21 Conservative Pair Veto OOF

> 状态：正式 3-fold OOF 已完成，结论为 `FIT-OOF-PAIR-LOCAL-VETO-NO-GO`。
> 单向 veto 能安全降低 cross，但不能补回 baseline 漏 pair，因此 exact 门禁无法单独通过。

## 目标与约束

v0.9.19/v0.9.20 的双向 residual 会将 raw gain 很低的 OOF negative 大幅抬过 threshold。本轮
复用 v0.9.20 的 37,313 参数 spatial encoder，但输出改为单向 veto：

```text
if raw_gain > tau0 and veto_logit > 0:
    score = tau0 - 1
else:
    score = raw_gain
```

模型永远不能增加候选分数。最后层 weight=0、bias=-4，step 0 不删除任何 pair。

loss 分开监督：positive keep、worst positive、all negative、raw-active hard negative 和 logit L2。
数据、fold、crop cache、训练步数和 matching 与 v0.9.20 相同；未读取 validation、fresh、sealed、
internal test 或 MR-TADF。

## 正式结果

| 指标 | raw baseline | v0.9.21 veto |
| --- | ---: | ---: |
| selected cross | 33 | 22 |
| M2 recall | 99.55087% | 99.54954% |
| pairable exact | 94.58255% | 94.58255% |
| parallel-2 violations | 2 | 2 |
| support lost | 31 | 25 |

三个 fold 共 veto 16 个 negative、6 个 positive。cross 明显下降且 recall 只损失 4 个 matched
target，说明单向安全边界有效；但 pairable exact 完全停在 baseline 的 94.58%，低于 95% 门禁。
veto 只能删错，不能补漏，因此必须与受约束 rescue 组合。

## 固定组合诊断

使用 `consensus=min(v0.9.19,v0.9.20)` 作为双模型共识 rescue，再让 veto 删除活跃候选：

| score | cross | M2 recall | pairable exact | parallel bad |
| --- | ---: | ---: | ---: | ---: |
| raw | 33 | 99.55087% | 94.58255% | 2 |
| veto(raw) | 22 | 99.54954% | 94.58255% | 2 |
| consensus | 19 | 99.64116% | 96.38265% | 1 |
| consensus + veto@0 | 17 | 99.64016% | 96.38265% | 1 |

固定阈值前沿中，`consensus + veto@-3` 达到：

```text
cross 8
M2 recall 99.50655%
pairable exact 95.49117%
parallel violation 0
support lost 14
```

除 cross=0 外已满足主要门槛，但 M2 只高于 99.5% 约 0.0066pp，继续降低阈值会跌破 recall。
因此阈值校准不能解决最后 8 个错误。

## Hard 8 归因

8 个剩余 cross 中：

- 5 个为 `parallel_3 ↔ single_line` 边界误配；
- 3 个为密集区域 `single_line ↔ single_line` 误配；
- 多数位于双键、三键末端或多线交叉处。

当前 crop 的两次 max-pool 会抹掉 1–2 像素白缝，把多条物理 stroke 压成粗黑带。下一步应保留
normal cross-section 的逐像素 profile 和纵向 left/middle/right junction 位置，不应继续调 veto
阈值。

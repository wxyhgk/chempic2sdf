# 冻结 OCR 裁框对照：5 处 NH 修复，但有 2 处元素回归，维持默认

## 已得到的实际识别结果

在用户“继续推进”后，对上轮固定的像素候选运行一次 CPU 冻结 OCR 对照。
不是训练，也没有更换 OCR：使用原模型，仅改变输入裁框。

结论是 **裁框确实能修复这类漏 H，但不能无条件替换原输入**。

| --- | ---: | ---: |
| 唯一匹配可见文字的严格文本正确数 | 227/261 | 230/261 |
| 相同分母下解析后的显示原子状态正确数 | 227/261 | 230/261 |
| 纵排文字严格文本正确数 | 10/16 | 15/16 |
| 上轮补全覆盖的 7 个框中，文本正确数 | 2/7 | 7/7 |

5 个原先识别成 N 的位置正确读成了 NH；但 2 个原本正确文字退步，分别 P→O、S→B。
净增加 3 个正确文本不能掩盖这两个回归，因此正式结论是 `regression_keep_default`。
没有接入默认 OCR，也没有生成新的分子图或报告分子识别准确率。

## 对下一步的判断

1. **这类 N→NH 漏识别不需要先重新训练模型。** 原冻结 OCR 在提供更完整的输入后，
   已有 5 处实际恢复。先前“按高度池化可能不利于纵排”的风险不能被夸大成“模型不会识别纵排”。
2. **缺的是候选验收，而不是继续全面扩框。** 当前像素启发式会把键线当成扩展依据，
   两个元素回归恰好发生在上一轮已记录的键线误触发上。原默认行为必须保留。
3. **不能只选置信度更高的结果。** 五个新增正确 NH 中，ee88082/candidate 1 与
   27295a2/candidate 25 的正确 NH 分数低于原错误 N；跨裁框的自信程度不是正确性的证明。
4. 下一项可设计独立、保守的文字编辑验收：区分核心属性改写和局部补充，
   保持元素／电荷／同位素等核心属性的候选再接受像素及图化学检查；元素翻转先不自动采用。
   不能按这 5 个成功样本建立白名单，也不能把“能 sanitize”当作分子正确。
   这是后续设计建议，**本轮没有运行该选择器，也没有将 GT 选优后的结果包装成成绩**。

继续验证可复用本轮 292 份 logits 和候选证据，不必立即重跑 OCR 或开 GPU 训练。
若同批结果用于设计验收规则，后续同批成绩只能作为回归检查，不能称为独立泛化成绩。

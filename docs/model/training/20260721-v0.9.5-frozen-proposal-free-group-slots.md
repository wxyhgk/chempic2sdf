## 本轮目标

v0.9.4 已经证明 direct carrier coordinate regression 会丢掉 flat primitive-set 已解决的
坐标能力。v0.9.5 因此固定以下边界：

```text
Raster
  -> frozen flat primitive proposals + frozen coordinates
  -> learned proposal keep/type + group partition/type/count
  -> deterministic carrier fitting
  -> Visual SVG v0.2
```

本轮只验证第一种分组结构：用 192 个与 proposal 无绑定关系的自由 group query，预测每个
slot 的 group type、member count，以及该 slot 对所有 frozen proposals 的 membership。

模型不得输出新坐标，flat geometry、endpoint refiner 和 stroke geometry 全部冻结。GT 坐标
只用于构造监督标签和离线评估，不进入 membership 模型输入。

## 为什么 Free Slots 失败

capacity100 中平均只有约 34 个可用 group，却始终实例化 192 个无空间锚点的可交换 slot。
该表示引入了三层没有必要的身份问题：

1. Hungarian 每步必须重新决定哪个自由 slot 代表哪个 GT group；
2. group type/count score 决定 top-k slot，但 membership quality 由另一条独立路径决定；
3. proposal ownership 由多个独立 sigmoid 和软 exclusivity 近似，不能硬保证每个 proposal
   恰好属于一个 group。

结果是：

- formal top-k 选择了错误且同质化的 slot；
- membership 为降低冲突倾向于漏 member；
- 对称的 p2/p3 缺少稳定身份；
- 大型 hashed group 必须由一个无锚点 slot 同时召回大量 proposal，最终 exact 仅 8.11%。

继续增加训练步数可能继续提高 oracle top-k，但不能消除 free slot 与 proposal ownership
之间的结构错位。capacity100 已经提供足够强的 NO-GO 信号。

## 正式判定

v0.9.5 的正式结论：

```text
Frozen proposals
  -> 192 exchangeable free group slots
  -> independent sigmoid membership

NO-GO
```

NO-GO 只针对 free group slot partition。以下结论继续保留：

- flat primitive proposal 坐标冻结是正确方向；
- Visual SVG v0.2 和 typed carrier codec 继续使用；
- carrier fitting 和物理 member 展开继续保持确定性；
- proposal keep/type、group count 和 OCR 仍可作为独立模块训练。

## 下一步：Proposal-Anchored Latent Representative

下一版不再创建 192 个无身份 group query。每个 frozen proposal 自身成为潜在 group
representative：

```text
frozen proposal i
  -> representative/group score
  -> group type + member count
  -> pointer/membership to compatible frozen proposals j
```

GT group 的任意真实 member 都允许作为 representative。训练时通过受限 Hungarian 或
minimum-cost matching 在该 group 的 member 中选择 latent representative，不为对称 p2
硬编码固定 root。

匹配后使用 proposal-to-representative column softmax 或受容量约束的 assignment，使每个
oracle-kept proposal 恰好属于一个 group。这样：

- group 身份锚定在真实视觉对象上；
- singleton group 自动以自身为 representative；
- p2/p3 只需学习少量 pointer；
- hashed 的监督按 group 内平均，不再由成员数主导 loss；
- 推理可使用稀疏 compatible-neighbor pointer，满足 CPU 的 `O(PK)` 目标。

第一轮仍使用 capacity100、oracle proposal keep/type 和 known group count，禁止坐标回归。
只有 proposal-anchored 模型跨过 p2、hashed 和 sample-exact 门槛，才允许扩到 9k。

# v0.7.32 文字对象与键线顶点 Oracle

## 问题

共享局部视觉特征同时包含键线和字符笔画。大号 `N`、`M` 或多字符标签可能被拆成
多个局部顶点。本轮不训练模型，只使用 ChemVision Layers 的真值分层验证该假设。

## 协议

- 数据：validation 500 + internal_test 500，共 1,000 张未见字体图片；
- 顶点匹配半径：6px；
- `text object` 只使用文字实例中心，不读取字符串或元素含义；
- 隐式顶点仍由冻结 dense detector 预测；
- 文字框外扩 8px 内的 dense 候选被屏蔽，避免把字符笔画和截断键端计为隐式碳。

## 结果

| 模式 | F1 | vertex exact |
|---|---:|---:|
| 原图 dense | 75.69% | 0.2% |
| 原图隐式点 + 文字对象中心 | 85.19% | 2.6% |
| bond-only 隐式点 + 文字对象中心 | 85.01% | 2.4% |

大字号与极大字号 287 张：

| 模式 | F1 | vertex exact |
|---|---:|---:|
| 原图 dense | 76.77% | 0% |
| 原图隐式点 + 文字对象中心 | 85.15% | 3.14% |
| bond-only 隐式点 + 文字对象中心 | 84.97% | 2.79% |

只统计隐式顶点：

| 输入 | F1 | exact |
|---|---:|---:|
| 原图屏蔽文字框 | 79.18% | 2.6% |
| bond-only 层 | 78.94% | 2.4% |

## 结论

- 把一个完整文字实例作为一个顶点，整体 F1 提高约 9.5 个百分点，exact 提高 13 倍；
- 大字号 exact 从 0 提高到 3.14%，验证了字符笔画拆点问题；
- 去除全部文字像素没有改善隐式顶点，bond-only 甚至略低；
- 因此不应让同一个 dense vertex head 同时解析字符笔画和骨架折点；
- 下一步训练独立 `text object center` 分支，与隐式骨架顶点分支合并；OCR 只在文字
  对象之后识别开放字符串，不参与顶点几何判断。

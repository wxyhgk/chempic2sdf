# v0.9.10 Conditional Ordinary Pair 数据协议

> 状态：数据层完成；strict 候选池不适合训练；training_wide 仅允许显式启用

## 目标

本阶段只验证一个条件问题：假设 router 已经正确保留 ordinary LSD anchors，模型能否判断
两个 anchor 是同一条物理线的两侧边界，还是两个不同 ordinary target 的近邻线段。

数据流严格分成两段：

```text
raw raster -> raw LSD -> EvidenceCarrier association -> positive ordinary anchors
positive anchors + raster -> target-free compatible pairs -> GT pair labels
```

GT 只用于第一段 router oracle 和最后的标签赋值。pair candidate 函数不接收
`target_line_id`，不同 target 的所有兼容 pair 都保留为 hard negative。

## 样本字段

- `anchor_segments` / `anchor_segments_pixels`
- `anchor_source_indices` / `anchor_target_line_ids`
- `pair_indices` / `pair_labels` / `pair_target_line_ids`
- `pair_overlap_centerline` / `pair_overlap_centerline_pixels`
- `raw_keep_labels` / `raw_target_line_ids` / `raw_group_ids` / `raw_group_types`
- `pixel_values`、样本 identity、schema version 和 feature names

pair feature 固定为 8 维，顺序不可静默改变：

```text
angle_degrees
normal_separation_pixels
overlap_pixels
shorter_interval_overlap
interval_iou
interior_ink_occupancy
interior_mean_darkness
center_mean_darkness
```

这些特征对 pair 成员交换对称。singleton 不另设标签；后续 matching 将 all-singleton 的
gain 定为 0，pair scorer 输出的是相对拆成两个 singleton 的增益。

## Candidate Profiles

默认行为保持 `strict`，即 v0.9.9 审计参数：

```text
angle <= 3 degrees
normal separation 0.5..4 px
overlap >= 8 px
shorter overlap >= 0.70
interior occupancy >= 0.80
```

`training_wide` 必须显式选择：

```text
angle <= 8 degrees
normal separation 0.5..8 px
overlap >= 4 px
shorter overlap >= 0.35
interior occupancy >= 0.25
```

`training_wide` 仍然只读取 raster 和 anchor geometry，不使用 GT 调整单个样本。CLI 禁止把
命名 profile 与逐项 override 混用；需要逐项实验时必须选择 `custom`。

## Render 与 Split

- `render_variant="original"`：单风格 capacity 实验；
- `render_variant=None`：保留全部 render variants，供正式风格泛化训练；
- fit/calibration 按 molecule ID 与 source-structure ID 的连通分量拆分；
- 同一 molecule/source 的全部 variants 必须留在同一侧；
- train/validation 在 molecule 和 source 两个身份轴上的 overlap 都必须为 0；
- `internal_test` 路径、解析后路径和样本 metadata 均严格拒绝。

## Strict 审计

单 variant、256 个 train 样本稳定拆为 230 fit + 26 calibration；validation 125 只跑一次。

| split | positive | hard negative | multi-anchor pairable recall | oracle paired multi-anchor |
|---|---:|---:|---:|---:|
| fit | 9,991 | 3 | 99.910% | 99.775% |
| calibration | 1,233 | 0 | 99.595% | 99.515% |
| validation | 5,439 | 1 | 99.743% | 99.578% |

结论：strict 的候选覆盖上限很高，但 calibration 完全没有负类，不能训练或选择二分类
scorer。它只保留作 baseline/audit。训练必须使用显式 `training_wide`，并先在 train-only
fit/calibration 上检查类别分布；在 profile 和模型选择冻结前不得重复读取 validation。

## Training Wide Train-Only 审计

同一批 256 个 train 样本、相同的 230/26 identity partition，在不读取 validation 的条件下：

| split | positive | hard negative | multi-anchor pairable recall | oracle paired multi-anchor |
|---|---:|---:|---:|---:|
| fit | 10,010 | 1,359 | 99.970% | 99.855% |
| calibration | 1,238 | 193 | 100.000% | 99.919% |

`training_wide` 使 calibration 同时包含正负类，且没有牺牲候选覆盖上限。该结果只证明数据
协议具备训练条件，不等于模型已经通过；validation 仍保持未读取，等待 scorer 和 matching
规则在 train-only 阶段冻结。

审计结果：

```text
outputs/evaluations/
  chemvector-v0910-conditional-ordinary-pair-data-strict/summary.json
  chemvector-v0910-conditional-ordinary-pair-data-training-wide-train256/summary.json
```

train-only wide 审计命令：

```bash
.venv-train/bin/python -m chemvector.audit_evidence_carrier_conditional_pair_data \
  --pairing-profile training_wide \
  --render-variant original \
  --train-samples 256 \
  --skip-validation \
  --output outputs/evaluations/chemvector-v0910-conditional-ordinary-pair-data-training-wide-train256/summary.json
```

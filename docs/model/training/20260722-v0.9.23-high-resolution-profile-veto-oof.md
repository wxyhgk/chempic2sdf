# v0.9.23 High-Resolution Profile Veto OOF

> 状态：正式 3-fold OOF 已完成，结论为 `FIT-OOF-PAIR-PROFILE-VETO-NO-GO`。
> 不降采样 profile 能安全删除部分 negative，但逐 pair 表示仍无法消除多线组件歧义。

## 目标

v0.9.21 hard8 多位于双键、三键末端或密集多线 junction。v0.9.20 CNN 的 max-pool 会抹掉
1–2 像素白缝；v0.9.22 用 group label 加权又大量误删 positive。本轮删除局部 CNN，不使用
group type，直接保留 crop 的高分辨率 profile。

## Profile

从 `2×24×48` crop 构造四张 map：

```text
ink
candidate mask
ink * mask
ink * (1 - mask)
```

每张 map 提取：

- left / middle / right 三段各 24 行 normal profile；
- 完整 48 列 longitudinal profile。

总维度：

```text
4 * 3 * 24 + 4 * 48 = 480
```

`480 -> 96 -> 32` 后与 21D token、global context 和 endpoint incidence 融合。没有卷积、max-pool
或 adaptive pooling。模型参数 60,505，初始 veto bias=-4，模型只能删除 consensus-active pair。

训练仍使用 v0.9.21 普通安全 veto loss，不使用 group label 权重。评估输入为冻结的：

```text
consensus = min(v0.9.19, v0.9.20)
candidate = consensus + profile veto
```

## 正式结果

| 指标 | raw | consensus | profile veto |
| --- | ---: | ---: | ---: |
| selected cross | 33 | 19 | 16 |
| M2 recall | 99.55087% | 99.64149% | 99.64149% |
| pairable exact | 94.58255% | 96.38265% | 96.39979% |
| parallel-2 violations | 2 | 1 | 1 |
| support lost | 31 | 25 | 21 |

三折合计只删除 3 个 negative，误删 positive 为 0。相比 v0.9.22 同样的 cross16，本轮没有用
误删 positive 换指标，并额外正确 1 张 pairable sample，证明高分辨率 profile 表示有效。

降低阈值只能通过删除大量冗余 positive 将 cross 压到 6，且 recall/exact 明显崩溃；不存在零 cross
的安全阈值。因此问题不再是 profile 分辨率或阈值，而是逐 pair 决策缺少相邻多线组件的联合约束。

## 下一步

停止继续扩展独立 pair classifier。v0.9.24 应建立 target-free carrier neighborhood：

1. 对候选中心线附近的所有近共线 anchor 建立局部组件；
2. 按 normal offset 和 longitudinal support 排序；
3. 输入候选上/下方有多少物理线，以及这些线只出现在左端、右端还是贯穿；
4. 组件级模型或 exact-cover 同时选择整组 boundary pairing；
5. 重点解决 parallel2/parallel3 与 single-line junction，不把 group type 作为 forward 真值。

只有组件级 OOF 达到 cross=0 后，才接完整图片到 SDF shadow。

# v0.9.86 AtomPair 整图上下文

## 回归主线

v0.9.84-v0.9.85 已证明长度无关线段可以缓解极端长键，但 extreme-long 属于专项边界，不应继续
主导普通化学结构识别。本版默认关闭全部线段 rescue，版本门控重新使用 ChemVision/full-v0
普通结构双域。

固定 v0.9.83 AtomPair group 后，双域 validation 的 proposal recall 约 98.2%，单键 incidence
约 99%，但 presence 整图 exact 仅约 69%-71%。根因是每个 AtomPair 仍由独立 MLP 判断，
看不到同一原子附近的其他候选，也看不到整张图的集合状态。

## 模型

新增 `AtomPairGraphContextHead`，不修改视觉、Atom/Bond proposal、incidence 或键型头：

```text
冻结的 AtomPair group feature / base logit
  -> local embedding
  -> 两端 AtomObject 的 incident-group mean
  -> 整图 group mean / max / count
  -> zero-init residual presence logit
```

两端上下文使用均值与绝对差保持原子顺序不变。训练损失包含：

- 原有 group BCE 与整图最强假键/最弱真键 ranking；
- 预测键总数的软 count loss；
- 每个预测 AtomObject 的软 incident degree loss；
- 很小的 residual L2。

degree 只是从真值图学习的软监督，不是硬价态规则；模型不读取元素、绝对键长、MR-TADF
难度或分子类型。

实现：

```text

chemvector/train_atom_pair_graph_context.py
chemvector/evaluate_atom_pair_graph_context.py
```

## 可复现性修复

首轮实验发现同一 seed 的结果不一致，最终定位为两个问题：

1. WebDataset buffer shuffle 没有接收训练 seed；
2. endpoint 聚合使用 CUDA `index_add` 原子累加。

本版增加 `sample_shuffle_seed`，训练流显式传入 seed；endpoint/count/degree 改为逐样本 incidence
矩阵运算，并启用 deterministic algorithms。两个独立 smoke 的训练 loss、验证指标和全部 10 个
权重张量逐位一致。修复前的 checkpoint 只保留诊断用途，不进入正式结果。

## 判断

方向 GO，幅度仍小。它证明整图上下文能在未见普通结构上减少假键并增加完整正确图，且收益能
穿过 chemical type 门控。下一步不再扩长键数据；应继续改进图级选择，使降低假键时少牺牲真键，
优先研究带保守 residual 边界的图级 recall 恢复。

前端 profile 为 `structure-v0986-carbon`，默认不带 line rescue，`recommended=false`。OCR 未接入，
真实上传中的文字原子仍统一按 C 占位。

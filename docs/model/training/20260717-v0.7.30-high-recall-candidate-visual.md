# v0.7.30 高召回候选与坐标对齐视觉证据

## 目标

v0.7.29 在 128 个候选上受 Candidate Oracle 上限限制。本轮不使用键长阈值、
最近邻候选边或长键预删除，而是把 dense 解码扩到 256 个候选，并让全部
`32,640` 个无向点对读取真实图片线条。主指标仍为 6px `vertex exact`，F1 只作
辅助指标。

## 候选上限

固定 100 图的 dense 候选扫描结果：

| threshold / NMS / 上限 | Candidate Oracle exact |
|---|---:|
| 0.20 / 3 / 128 | 57% |
| 0.05 / 3 / 128 | 85% |
| 0.05 / 1 / 256 | 92% |

因此本轮固定使用 `threshold=0.05`、`NMS=1`、`maximum_candidates=256`。

## 数值与特征

- 坐标匹配继续使用稳定欧氏距离和 6px Hungarian；
- 每个候选保留 5x5 raw heatmap、3/5 邻域峰值和亚像素 offset；
- Structured Selector 使用全局 Transformer 和可见线 incident 特征；
- 新增候选坐标对齐视觉特征，直接从 stride-4 stroke feature map 采样；
- 最终采用 3x3x96 patch，保留线条进入、离开候选点的方向信息。

3x3 patch 只提供视觉证据，不包含键长、最近邻或化学价态硬规则。

## 固定 100 图检查

局部 heatmap 形状版在约 30k 曝光首次达到 Candidate Oracle：

```text
Candidate Oracle exact  92%
Selected vertex exact   92%
F1                      99.62%
```

这只证明结构可学习，不作为泛化结果。

## MolGrapher 9k/1k 对照

训练集为 9,000 张，validation 为 scaffold 独立的 1,000 张；未使用 MR-TADF 或
USPTO 选择 checkpoint。三组实验除候选视觉特征外参数相同：

| 候选视觉证据 | 最佳曝光 | F1 | vertex exact | Candidate Oracle exact |
|---|---:|---:|---:|---:|
| 5x5 heatmap 形状 | 140k | 82.23% | 2.7% | 88.7% |
| 中心单点 96 维特征 | 160k | 83.74% | 3.5% | 88.7% |
| 3x3x96 对齐 patch | 160k | 84.72% | 4.4% | 88.7% |

## 结论

- 256 高召回候选将 validation Oracle exact 提高到 88.7%，候选覆盖 GO；
- 候选坐标对齐视觉证据持续提高 F1 和 strict exact，3x3 patch GO；
- 最佳 strict exact 仍只有 4.4%，不能进入稳定推理；
- 训练 loss 持续下降而 validation 平台明显，继续增加 epoch NO-GO；
- 当前 16x16 boundary 平均损失会稀释最强假候选和最弱真候选。下一步直接优化
  每张图的极值排序边界，再判断是否需要更强的候选分组结构。

稳定推理继续使用 v0.7.10，MR-TADF 继续只作外部诊断。

# v0.9.44 空间 AtomObject 容量实验

> 状态：AtomObject geometry/role GO，count 暂缓  
> 数据：固定 100 张 ChemVision train 图片  
> 外部数据：未使用 USPTO 或 MR-TADF

## 目标

验证“不先找匿名顶点”能否落到空间检测器中。每个 stride-4 cell 直接预测一个完整
AtomObject：

- object heatmap；
- 亚像素 chemical anchor；
- `IMPLICIT/TEXT` role；
- 文字中心；
- 文字 bbox extent。

所有字段来自同一 object feature。模型不会先生成 vertex，再调用另一个模块按距离附着
文字。容量集 100 张中没有两个 AtomObject 落入同一个 stride-4 cell；训练器仍保留
显式冲突检查，发生碰撞会直接失败。

## 实现

- 模型与损失：`chemvector/spatial_atom_object.py`；
- 训练与评测：`chemvector/train_spatial_atom_object.py`；
- 测试：`tests/chemvector/test_spatial_atom_object.py`。

首轮发现全局 count loss 占据绝大多数梯度，而归一化文字中心损失小两个数量级。正式
对照将文字中心/extent 改为像素尺度 Huber，count 权重降为 0.1；checkpoint 按
anchor、role、文字中心、extent 的分层分数选择。

## 判断

相对 v0.9.43 的 5000-step free-query：

- atom 6px：18.93% -> 100%；
- role：70.64% -> 100%；
- 平均 anchor 误差：90.68px -> 0.345px。

因此主要障碍是对象身份的空间锚定，不是训练图片不足。文字中心也可以与 anchor 在同一
AtomObject 内联合学习，不需要最近邻附着。

count head 只对整幅 feature 做全局平均，11% 说明它没有可靠计数。该结果不影响空间
proposal 的 geometry/role 结论；下一阶段先让 BondObject 使用相同的空间对象原则，并在
已覆盖的 Atom/Bond proposal 之间训练 incidence。count 将由对象 heatmap、图级集合选择和
incidence 一致性共同决定，不继续单独放大全局平均 count head。

## 决策

- 空间完整 AtomObject proposal：GO；
- 文字与 anchor 同对象联合预测：GO；
- 当前全局平均 count head：NO-GO；
- 直接替换稳定推理：NO-GO，尚未接入 BondObject 和 SDF；
- 下一步：空间 BondObject proposal + endpoint-to-AtomObject incidence 容量实验。

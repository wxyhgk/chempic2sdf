## 排程修正

八个偏移顺序沿用旧 `OFFSETS[1:]`，不搜索顺序。每张图拥有从 0 开始的访问计数：
`view_index = 1 + visit_count(image) % 8`。每次访问先消耗一个位置，
不论原监督为空还是增强为空都推进；不因标签、资格、loss 或预测分数重抽。
固定原 manifest 图顺序。按全局 attempt%8 的旧提议只作为已知问题的只读对照。

事前固定四份**计数模拟**（不是训练运行或扩大 GPU 预算）：

| 计数范围 | 最大尝试 | 模拟非空更新上限 | 用途 |
| --- | ---: | ---: | --- |
| `bounded50` | 58 | 50 | 检查此前小额建议在有限预算内实际覆盖什么 |
| `one_sweep` | 58 | 54 | 显式区分全 58 图一遍与 50 次更新截断 |
| `cycle8` | 464 | 432 | 只用整数／保存行号证明每图最终遇到八方向 |
| `legacy_cycle8` | 464 | 432 | 复现全局 attempt 排程的永久遗漏；不采用 |

每份保存 attempt→图→偏移→原 row_id→sampled position；报告每键型正负次数、
每条原采样行的实际覆盖、P–O/P=O 的逐键次数、空分支和仍不可达的目标。
模拟上限不是新的 optimizer 授权。不能因为有限预算没覆盖八方向而自动补跑。

## 接线约束

新增 CPU opt-in objective 从**调用当时**的候选、原对应关系及目标构建契约；
不接受历史保存 plan 或 historical row_id 作为新设备缓存的替代。
上游输入 detach，pair 必须处于 eval；仅增强沿键视觉取样坐标，
feature map、atom features、scores、pair 候选及原匹配／标签保持不变。
全 pair 行号必须经显式 `sampled_positions(chosen, kept)` 转换，
用非连续、乱序、缺失、重复行号和部分视图的合成测试证明不会静默错标签。

原位置 loss 保留，新增最多一个非空偏移 loss。weight=0 不运行额外 forward，
核对连续 toy 更新的参数、梯度、优化器状态、RNG 与原单分支逐值一致。
这不保证 weight=1 的共享参数更新不会损坏旧正确键，仍需真实全量保护验收。
当前 CPU prototype 不是 GPU launcher；以后接入 GPU 需新设备缓存与单独验证。

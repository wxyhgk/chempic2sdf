# v0.9.91 Chemical RETYPE 整图修复

## 目标

v0.9.90 表明继续叠加 presence-only ADD/DELETE 会改善连接数量，却可能破坏键型完整一致。
本版冻结 v0.9.89 的 presence 决策，只允许把已经存在的一条键在 `SINGLE / DOUBLE /
TRIPLE / AROMATIC` 之间改型。任何 RETYPE 动作都不得增加或删除边。

数据边界保持不变：

- 只使用 ChemVision 与 full-v0 的 train 分区训练和选模；
- 以 `sha256(molecule_id) % 5` 固定切分，bucket 0 为 train-dev，其余为 train-fit；
- 同一分子的不同布局和跨域副本不得跨分区；
- MR-TADF、USPTO、official validation 和 locked internal 均未用于本轮调参；
- 不使用绝对键长、元素价态或特定分子类别规则。

## 可达上限

冻结 v0.9.89，在双域 train-only 共 4,500 张图片上审计：

| 指标 | 数量 |
|---|---:|
| 可表达样本 | 3,686 |
| 当前 typed exact | 2,466 |
| presence exact 但键型错误 | 915 |
| 一次 bounded typed edit 可达 | 2,915 |
| 一次 bounded RETYPE-only 可达 | 2,823 |
| 两次 bounded typed edit 可达 | 3,144 |

错误动作累计为 RETYPE 3,256、ADD 255、DELETE 286。一次 RETYPE 的 16 条低 chemical
margin 候选只漏 1 个可达样本，因此候选覆盖不是本轮主要问题；真正问题是能否高精度判断
哪一个 RETYPE 比 KEEP 更可靠。

## 失败方案一：通用 typed action

最初把 KEEP、ADD、DELETE 和 RETYPE 放进同一个动作空间。旧 presence 排序会优先学习
ADD/DELETE，压制数量更多但更难的 RETYPE；seed 20260725 的 train-dev chemical exact
保持 `551 -> 551`。另外两个预注册 seed 因同一机制停止。该方案 NO-GO。

## 失败方案二：分离 gate 与 RETYPE action

模型先判断是否需要改型，再在 16 条候选边和 3 个替代键型之间选择动作。edge encoder 从
v0.9.89 warm-start，gate/action 输出层零初始化。每个 seed 使用双域 train-fit 各 2,250 张，
train-dev 各 498 张固定不变。

三个模型 seed `20260725 / 20260726 / 20260727` 的最佳 train-dev 均为：

```text
baseline chemical exact 551 / 996
best chemical exact     551 / 996
rescue / break          0 / 0
presence                逐样本不变
```

诊断显示问题不是 action 完全没学到。80 个一步 RETYPE 正例中，action top-1 分别命中
27、26、29 个；oracle gate 条件下可把 exact 提到 578、577、580。但 gate 的正负分布重叠，
细化到 0.05 的阈值网格后仍没有净提升。

## 失败方案三：KEEP 与 RETYPE 联合 softmax

为消除训练/部署错位，把 KEEP 和所有具体 RETYPE 动作放进同一个列表损失。第一轮 4,500
张后仍为 `551 -> 551`。从该 checkpoint 继续同一 train-fit 第二轮，累计 9,000 张后：

| 指标 | 第一轮 | 累计第二轮 |
|---|---:|---:|
| RETYPE action top-1 | 32.50% | 43.75% |
| oracle gate 可达 exact | 577 | 586 |
| 实际最佳 exact | 551 | 551 |
| 最佳 rescue / break | 0 / 0 | 0 / 0 |

训练量确实改善 action 排序，但高分动作仍不能安全区分 rescue 与 break。

## 失败方案四：global safety gate

最后冻结 action 排序，只训练 global gate；正标签严格定义为“执行当前 top-1 RETYPE 后整图
从错误变为 exact”，负标签包含原本正确、动作选错和无法一次修复的样本。4,500 张中每 900
张只有约 22-29 个安全正例。gate 最终整体变得保守，最佳仍为 `551 -> 551`，说明只读整图
global summary 无法判断某个具体候选动作是否安全。

## 决策

v0.9.91 正式 NO-GO：

- 不进入 official validation，不运行 locked internal；
- 不接入推理，不替换默认前端 `structure-v0989-carbon`；
- 不根据 MR-TADF 或 USPTO 调阈值；
- 保留 train/dev 隔离、chemical reachability、RETYPE-only presence 不变协议和 checkpoint
  只读诊断入口；
- 下一版不再训练纯 global gate，而是训练候选级 verifier。verifier 必须直接读取被修改边的
  relation feature、当前键型、目标键型、action margin 和局部/整图上下文，监督目标仍是
  “该具体动作是否把整图修成 exact”。

本版结论同时说明：数据量不足确实限制 action top-1，但当前部署失败不能仅靠扩量解释；在
候选级安全特征接入前，继续增加同目标训练量没有可靠的 GO 依据。

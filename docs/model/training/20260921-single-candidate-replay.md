# 单候选补点回放：冻结模型恢复了腈基两条键，但整图仍未正确

## 结论

对固定 NH 训练失败图 `curr_08d02946e879406f__font_large`，只将上轮预测侧复查
排第一的原始候选 **P20** 加回 selected mask，现有冻结 initial 模型就自行预测出：

- P9–P20：SINGLE，对应目标 B4，存在分数 **0.991106**。
- P20–P11：TRIPLE，对应目标 B5，存在分数 **0.985855**。

两条键均超过原阈值 0.85；原始类型预测、原有后处理及最终场景类型一致。
没有手工指定元素、连接对象、键型或新坐标。
**该局部失败可以归因到候选未被保留；并不是当前 pair 模型完全不会识别这处三键。**
这只证明一个已知训练失败点的条件性恢复，不证明自动补点规则安全，也不代表整图精度提高。

## 固定实验与复现

前序：[预测侧候选复查](20260921-upstream-recheck2.md)。

1. 从 SHA 绑定的 `candidate-review-prediction-only.json` 中读取唯一请求的
   `first_review_slot`，不是根据目标坐标重新选候选，也没有尝试 P22。
2. 原图、initial、OCR、特征提取和 selector 全部冻结；一次 CPU 上游前向。
3. 原始 128 候选的 grid ID、激活状态和 selected 状态复现。
   与上次 CPU 快照的坐标、原始分数、selector logit 最大差均为 **0**。
4. 两个预测分支分别使用原 17 个候选、原候选加 P20 共 18 个候选。
   只复制并修改一个 mask bit，其他张量对象不变；不重新运行 selector。
5. 分别运行原 pair、文字角色、预测框、OCR 和编译器。两个纯预测文件保存后，
   才读取该训练图的 graph/layers/text-records，按原匹配器与原 6px 半径评分。
6. 基线的场景、OCR 文字、SDF 身份及全部已保存关键指标复现历史 initial。
   CPU 与历史 GPU 的 presence/chemical logit 最大差分别约 0.000244 / 0.000123，
   不宣称恢复历史 GPU 浮点缓存。

补入 P20 后，角色头给出的文字概率是 **0.037268**，低于原角色阈值 0.85，
按既有规则作为隐式碳处理。没有强制关闭 OCR，也没有从目标标签指定它为 C。
原有 5 个 OCR 文字保持不变。

## 结果与计数口径

| 指标 | 原始 initial | 仅补 P20 |
| --- | ---: | ---: |
| 入选候选数 | 17 | 18 |
| 原匹配器匹配到的目标原子数 | 16/18 | 17/18 |
| 严格匹配口径下可达目标键 | 14/18 | 16/18 |
| 严格匹配且原始键型正确 | 12/18 | 14/18 |
| 场景中的连接数 | 14 | 16 |
| 已确认假阳性键 | 0 | 0 |
| 匹配不确定但输出存在的键 | 2 | 2 |
| 图的连通分量 | 4 | 3 |
| SDF 有效 / fallback | 是 / 否 | 是 / 否 |
| 整图严格身份正确 | 否 | 否 |

原 17 个候选均保留，旧目标分配无变化；原 14 条场景连接均保留且类型不变。
原 136 对候选的 presence 和 chemical logits 在两个 CPU 分支间最大差均为 **0**。
新增的 17 对候选中，只有上述两对达到存在阈值，另外 15 对均未出边。
没有丢失任何已匹配目标或已正确原始键型。

这里的两条 unknown 是已有环 N（T12/P13）的关联边 B11、B12。
它们在预测场景中已经存在，本轮也保留；原严格位置匹配器没有接纳该节点，
所以没有进入严格正确键计数。**不能把它们说成两条真实漏键，也不能把 unknown 当错连。**
报告中的 `target_bonds` 是严格匹配口径：没有 `candidate_pair` 时，
`scene_typed_correct=false` 仅表示无法凭该口径认证，不是证明场景没有这条边。

SDF 的变化：

```text
原始：CC(N)C(C)(C)C.N.[NH]C[NH].c1ccncc1
补点：CC(N)C(C)(C)C.N#CNC[NH].c1ccncc1
目标：C[C@@H](/N=C(/NC#N)Nc1cccnc1)C(C)(C)C
```

新增连接会改变 RDKit 派生的氢数/自由基状态；“旧候选及旧键保留”
不意味着这些依赖连接关系的派生属性应全部不变。

## 仍未解决的问题，以及下一步优先级

本轮明确没有修好整图。两个端点已经存在、但仍未输出的真实目标键为：

| 目标键 | 候选对 | 应有类型 | 存在分数 | 原始类型预测 |
| --- | --- | --- | ---: | --- |
| B2 | P0–P3 | DOUBLE | 0.047286 | AROMATIC |
| B7 | P4–P10 | SINGLE | 0.008782 | SINGLE |

立体化学信息仍未恢复。不能靠补这一个点解决这些独立问题，也不应降低全局阈值来凑连通性。

建议下一步先验证**何时不能补点**：在现有训练侧固定范围中预先锁定无需补点、
真实多片段、非原子线条候选等负例，冻结本次队列与首选策略，不看结果改排序。
若没有可用负例，先报告覆盖缺口，不临时借用封存测试。
验收必须包括错误补点、额外假键、原正确连接退化和 SDF 有效性；
只有一个成功例，不足以接入正式推理。

随后单独分析 B2/B7 的局部视觉证据和 pair 输入，区分“存在判断错误”与“类型判断错误”。
这两项都是离线诊断建议，不是恢复已结束训练的授权；当前不扩大模型、不启动大规模训练。

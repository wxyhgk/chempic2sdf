# 化学节点与笔画候选：122 图离线审计

## 结论

已完成上一轮建议的错误分类：**122 张原有图全部审计，7 个反例生成原图放大叠加图**。
本轮仅解释已保存预测，没有模型前向、训练、checkpoint 加载或部署；默认仍为 initial。
CPU 工作进程耗时 **2.016 秒**，GPU 使用为 0。

在上一轮 retention-400 的 64 张开发图中，按原 selected 匹配规则统计的
**12 个多余点 = 8 个文字框内点 + 3 个多重键外侧线头点 + 1 个其他键笔画端头点**。
这支持把下一阶段重点放在“化学节点与笔画的区分”，而不是继续放大全部正例或压低全部负例。
这里是位置关联，不是对网络内部特征的因果归因，也不是新的准确率提升。

两个必须保留的反证：

- 同一阶段，文字框内还有 **139 个选中且空间匹配正确的候选**，不能屏蔽全部文字区域。
- 保留的 **20 个 raw 负例中，有 8 个在 selected 重匹配后正确代表目标原子**，不能把 raw 负例全部当成多余节点。

## 范围与固定口径

- 固定清单：26 张拟合反例 + 32 张旧整分子回放 + 64 张已观察开发图。
- 沿用已有两轮试训保存的坐标、分数、预测与同源 PNG/SVG/layers/text-records。
- 先核验两轮初始模型、候选/标签缓存、冻结部分及 OCR 摘要一致，再跨轮对应候选槽号。
- 选择阈值仍为 -0.25；匹配仍为原 Hungarian 后施加 6 px 门限，不修改半径或匹配方法。
- CPU 共回放 546 次匹配：122 次 raw 匹配 + 424 次图像/阶段的 selected 匹配。
- 对 initial/control 阶段，还逐槽核对上一轮已经保存的 selected 匹配记录。
- 无新身份查询、封存测试读取、训练样本扩充、额外 GPU 推理或全量 944 图回归。

只有训练/回放图保存了 retention-200。64 张开发图没有该阶段预测，
因此下表的 control-200 与 retention-400 不是等步因果对照。
这 64 张也已经用于诊断，不是未触碰的独立测试集。

“有效替代”仅指按原空间匹配契约代表了目标；不代表其元素、键类型或最终 SDF 正确。
拟合26的 initial/retention-200 各有 1 个 raw 正例选中后未匹配，
对应此前发现的 `C#[13CH]` 原匹配契约问题；本轮保留原结果，不修匹配。
因此未匹配数不一定等于 raw 负例数减去替代点数，还须加上这类 raw 正例未匹配点。

retention-400 的多余点位置细分：

| 图组 | 文字框内且离所有目标超过6px | 多重键外侧线头 | 目标附近未分配 | 其他键笔画端头 | 其他/未决 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 拟合26 | 2 | 3 | 4 | 0 | 0 | 9 |
| 旧32 | 17 | 1 | 0 | 0 | 1 | 19 |
| 开发64 | 8 | 3 | 0 | 1 | 0 | 12 |

桶按固定优先级划分；逐候选记录仍保留文字框命中、最近笔画和距离等附加证据。
“目标附近未分配”不自动等于错误标签，其含义需结合 selected 匹配看是有效替代还是重复输出。

## 直观反例

1. `C#C`：正确槽1/2距目标约 1.55/1.76 px，已经存在于原始候选。
   错误槽0/3距目标约 10.21/10.40 px，位于三键上方外侧笔画端头附近。
   三条平行笔画仍然只对应两个化学节点。仅原 loss 的控制试训虽去掉坏点，也拒绝了真端点。

   原有 Br 正确代表点仍保留，不能把该字形片段额外算成原子。
3. `CCC(C)C(N)=O` 的新增错误槽距目标约6.86 px，接近现有6px边界。
   必须保留该距离信息，不应夸大成明显远离节点的错误，也不据此放宽验收。

## 下一步：先验证监督表达，不自动追加训练

本轮不发布新训练标签。下一项建议是只在原58张训练/回放图上做一个
**化学节点归属与笔画反例的离线监督原型**，开发64仅保留诊断用途：

1. 建立“目标节点 → 可代表它的候选集合”，保留近邻替代关系；
   有多重归属或原匹配冲突的候选单列，不强行指定唯一正例。
2. 利用同源标注提出待复核配对：多重键外侧线头对应哪个键端节点，
   字形片段对应哪个文字原子。仅纳入归属明确且有可用正确代表的配对，未知项不猜测。
3. 在不更新参数的条件下检查监督约束：同一节点保留有效代表、避免重复计数；
   排除笔画伪点时不能连带删除正确文字原子，也不能减少真实键的端点覆盖。

先给出覆盖率、冲突清单和可人工核查的配对，再决定是否需要修改 selector 的训练目标或输入表征。
这不是新的串行“先找原子再找线框”路线，也不要求换 MoE、改用 MolGrapher 或重训 OCR。
当前证据不足以认定整个自研架构失败；核心反例的正确候选已经存在。
任何后续试训都需要独立的单变量方案、数据用途确认及预算，不能自动继承已消耗的两次试训授权。

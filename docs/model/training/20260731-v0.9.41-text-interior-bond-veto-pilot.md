# 2026-07-31 v0.9.41 文字框内部 Bond Veto Pilot

> 状态：NO-GO，不建立新模型版本  
> 基础模型：v0.9.41 BondObject utility router  
> 新训练：无  
> 输出：`outputs/evaluations/uspto-clean-100-text-interior-bond-veto-pilot/`

## 目标

验证“文字笔画被识别为 BondObject，继而产生伪 Junction”是否仍是 v0.9.41 语义
BondObject 主线的主要公开错误来源。该实验只验证表示假设，不调 OCR、Bond 阈值或公开集参数。

## 规则

复用 v0.9.41 已有 Text Object bbox。在 Bond 端点聚合 Junction 之前，仅删除两个语义端点
都严格位于同一个文字 bbox 内部的 BondObject，bbox 边界向内保留 2px 安全边距。

一个端点位于文字框内、另一个端点位于框外的对象必须保留，因此文字原子连接到外部骨架的
真实键不受规则影响。规则默认关闭，通过 `--text-interior-bond-veto` 显式启用，并记录每个
删除对象的文字框索引、端点和置信度。

## 数据与协议

- 固定 USPTO clean 1k manifest 的前 100 张；
- baseline 为已有 v0.9.41 前 100 输出；
- candidate 使用完全相同 checkpoint、阈值、OCR、Junction 和 ChemScene 配置；
- 唯一变量为 `--text-interior-bond-veto`；
- USPTO 结果不用于修改 2px 规则或选择阈值；
- MR-TADF 未参与。

完整运行配置保存在输出目录的 `benchmark_config.json`。

## 测试

- `py_compile` 通过；
- `tests.chemvector.test_infer_chemscene_hybrid` 共 16 项通过；
- 单测覆盖“框内完整伪键删除”和“文字框到外部骨架真实键保留”。

## 结果

| 指标 | v0.9.41 | Text-interior veto | rescue | break |
|---|---:|---:|---:|---:|
| SDF valid | 71/100 | 71/100 | 0 | 0 |
| Skeleton exact | 78/100 | 78/100 | 0 | 0 |
| Atom-typed skeleton | 32/100 | 32/100 | 0 | 0 |
| Bond-typed skeleton | 66/100 | 66/100 | 0 | 0 |
| Chemical exact | 22/100 | 22/100 | 0 | 0 |

规则只在 `uspto_clean_0066` 触发，删除 2 个 Bond 候选；但这两个候选原本没有进入最终
Junction/关系图，所以 Atom、Bond、SDF 和所有 exact 指标完全不变。触发覆盖率为 1%。

## 决策

`NO-GO`。不扩展到 1k，不建立 v0.10.17，也不切换默认模型。

该结果没有否定“无语义点线恢复会混淆文字笔画”的判断；它证明 v0.9.41 的语义 BondObject
检测、集合选择和 Junction 关系链已经基本压制了这一问题。v0.9.41 在完整 1k 上的主要缺口
仍是 Skeleton `72.7%` 到 Atom-typed `29.3%`、Bond-typed `59.1%` 的语义差距，不应继续
优化低覆盖率文字框内 Bond veto。

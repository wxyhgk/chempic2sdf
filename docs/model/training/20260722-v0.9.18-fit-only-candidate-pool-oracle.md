# v0.9.18 P0 Fit-only Candidate-Pool Oracle

> 状态：正式审计已完成，结论为 `FIT-CANDIDATE-POOL-ORACLE-GO`。只读取 v0.9.17 的
> fit7200 与冻结 train-only source cache；
> 不读取、hash、打开或反序列化已经暴露的 v0.9.17 dev900 sidecar，也不使用原 calibration、
> fresh、sealed、internal test 或 MR-TADF。

## 目的

v0.9.17 证明 pair residual 能提高召回，但 forward 不知道 endpoint incidence，平均 pair loss
也没有直接约束 production maximum-weight matching。进入 endpoint-aware 模型之前，先回答更基础
的问题：当前 candidate pool 在 pair label 完全正确时，是否存在满足结构门禁的 matching。

本轮不是可部署模型，也不训练参数。它只测 candidate/matching 理论上限。

## Oracle 定义

对每个 source-order candidate pair：

```text
pair_label == 1: oracle_score = tau0 + 1
pair_label == 0: oracle_score = tau0 - 1
```

因此传入 production matching 的 relative gain 精确为 `+1 / -1`。所有 negative 在优化前被
排除；所有 positive 具有相同权重，matching 求得 candidate pool 内最大基数的互斥正 pair。
不得按 target group 直接构造新 pair，不得改变 candidate、anchor、tie-break 或 solver。

同次审计也计算 frozen raw gain + `tau0` baseline，仅用于报告 candidate-pool oracle 相对当前
输入的上限；不得搜索 threshold 或 residual bound。

Oracle 必须同时满足：

| 指标 | 门槛 |

| fit images | 7,200 / 7,200 |
| selected cross-target pairs | 0 |
| selected pair precision | 100% |
| multiplicity-2 recall | >=99.5% |
| pairable sample exact | >=95% |
| parallel-2 preservation | 100% |
| ordinary support loss | <=0.1pp |
| matching optimal | 7,200 / 7,200 |
| permutation deterministic | 100% |

全部通过为 `FIT-CANDIDATE-POOL-ORACLE-GO`。失败则为
`FIT-CANDIDATE-POOL-ORACLE-NO-GO`，停止 scorer/residual 路线，返回 candidate generation。

GO 只允许进入 v0.9.18 endpoint-incidence、matching-aware 的 fit-only OOF 实验，不允许直接申请
fresh holdout。旧 v0.9.17 dev900 永久禁止用于 v0.9.18 选模或门槛选择。

# v0.9.12 Fresh Paired Smoke

> 状态：`SMOKE-PASS`；只证明数据与 paired evaluator 的执行契约成立；数据来自已暴露的
> pilot train，不是独立泛化、不是公开 benchmark，也不是图片到 SDF 的端到端准确率

## 目标

v0.9.11 已在 calibration900 上得到 post-hoc `DEV-GO`，但正式 fresh 对照需要先证明两件事：

1. 新数据可以从同一次带语义 ID 的 SVG 确定性生成完整 12-member sample；
2. B 与 B+coverage 必须在同一次数据遍历中共享 target、frozen P0 前向和 pair score，避免
   两次独立运行造成输入、候选或数值差异。

本轮只建设并验证该执行闭环，不评价 coverage 在未见数据上的机制收益。

## 数据闭环

数据构建入口：

- 单次 SVG 12-member assembler：`Data/sdf/visual_svg_layers_c.py`；
- train-only smoke 生成器：`Data/sdf/build_visual_svg_layers_c_smoke.py`；
- 独立验证器：`Data/sdf/validate_visual_svg_layers_c.py`。

输出目录：

`Data/sdf/visual_svg_layers_c_v0_1/smoke_train_32/`

smoke 固定包含：

| 项目 | 数值 |
| --- | ---: |
| 分子 | 8 |
| 每分子布局 | 4 |
| 图片 sample | 32 |
| 每 sample 成员 | 12 |
| tar 成员 | 384 |

每个 sample 的 combined、text、bond、semantic、primitives、Visual SVG v0.1/v0.2、layers、
render、ChemMol、SDF 和 meta 均由一次语义 SVG 组装。构建器不读取 pilot 的全局样本表，
而是只遍历显式命名的 `shards/train-*.tar`，从其中的 `.layers.json` 构造安全 manifest；
发现 validation、internal、sealed 或 MR-TADF 引用时直接拒绝。

正式 loader 只接受 commitment 明确列出的 manifest 和 shard，不扫描数据目录，不跟随
symlink，并拒绝路径穿越以及数据/source/shard/sidecar 中的
validation/internal/sealed/reserve/MR-TADF 引用。正式 dev 还
不能仅凭 commitment 自报 `role=dev` 或 `fresh_audit_eligible=true` 获得泛化资格：evaluator
必须先在固定 registry 中找到相同路径和预登记的精确 commitment SHA256，随后 loader 才会
验证已登记的 Phase A freeze、独立 isolation report、manifest、validation 和 shard 字节。

当前 registry 中 dev commitment SHA256 有意保持为空，因此正式 `fresh_dev` 入口尚未开放；
未登记或 hash 不符时，会在选择设备和加载模型前直接终止，不能产生 `FRESH-DEV-GO`。

## 协议事件

早期路径探查曾误执行：

```bash
head -n2 Data/sdf/webdataset_full_v0/samples.csv
head -n2 Data/sdf/webdataset_full_v0/molecules.csv
```

两条命令各暴露了首条 `internal_test` 元数据；它们属于同一记录，只包含该记录在 manifest
中的 sample、molecule、scaffold 和 `structure_ref` 等元数据。没有打开对应 tar、SDF、PNG
或其他样本成员，也没有把该记录用于样本选择、模型前向、阈值、coverage 参数或任何指标。

事件发现后立即废弃混合 manifest 入口。smoke 构建器改为只枚举显式命名的
`shards/train-*.tar`，并在 shard 内验证每条 `.layers.json` 的 split；commitment loader 只
允许打开 commitment 逐项列出的 train/dev 输入。旧 `internal_test` 继续不运行，并永久
排除为未来 fresh 或 sealed 数据来源。

因此本轮不能表述为“从未看到过任何 internal_test 内容”；准确边界是：曾意外暴露一条
manifest 级元数据，但未读取样本内容，未执行该 split，也未影响本轮数据或指标。

冻结 Phase A 协议时还发生过第二次元数据级事件：一次范围过宽的 `rg` 路径探查命中了
preview 中少量 `split`/`sample_key` 文本。该命令没有打开 tar、SDF、PNG 或其他样本成员，
这些字符串没有用于身份选择、训练、阈值、coverage 参数、checkpoint 或任何指标。事件后
所有正式入口均改为显式 allowlist、固定路径和 commitment 引用，不再以递归搜索结果作为
数据来源。

两次事件均登记为协议元数据误暴露，而不是样本内容读取。它们不改变本次 smoke 的数值，
但必须保留在审计记录中，不能用“从未接触任何受限元数据”描述本轮过程。

## 单遍 Paired Evaluator

新增：

- commitment loader：`chemvector/evidence_carrier_fresh_dev_data.py`；
- 单遍 paired evaluator：
  `chemvector/evaluate_evidence_carrier_pair_coverage_fresh.py`。

evaluator 对每个 sample 只执行：

1. 一次 target 构建；
2. 一次 frozen P0 + pair scorer 前向；
3. 一份共享 pair score；
4. 在相同初始 matching 上分别计算 B 与 B+coverage。

Phase A 是零训练对照，运行报告固定写入 `training_steps=0` 和 `parameter_updates=0`，同时
记录 B/B+coverage route config SHA256、两侧 sample count、checkpoint/阈值/config 与关键
实现 SHA256。这里沿用 route B/C 的字段名，但 Phase A 的 route C 只是“同一个冻结 B 加
coverage veto”，不是重新训练的 C 模型。

门禁不再只比较聚合指标。每个 sample 都必须证明 B/C 的 input、target 和 pair score hash
相同，并逐样本检查：cross 不增加、m2 matched 不减少、P2 violation 不增加、ordinary
support loss 不增加、pairable exact 不得从 true 变 false；任何一项不完整或回退都会使运行
失败。

加固后的 run5 为 `SMOKE-PASS`，与最早 run1 的 32/32 个 sample 在功能结果上完全一致；
变化只来自运行计时和新增的审计元数据。报告位于：

- `outputs/evaluations/chemvector-v0911-synergistic-pair-coverage-smoke32/paired-run1.json`；
- `outputs/evaluations/chemvector-v0911-synergistic-pair-coverage-smoke32/paired-run5.json`。

run5 的 paired mismatch count 全为 0，B/C 各消费 32 个 sample，且每张图都只有一次 target
build 和一次 frozen P0/pair scorer forward。

## 正式 Fresh Dev 门禁

正式 `fresh_dev` commitment 必须同时满足：

1. 精确路径和最终 commitment SHA256 已预登记到 evaluator 的 formal registry；
2. commitment 引用已登记 SHA256 的 Phase A freeze，冻结 `training_steps=0`、
   `parameter_updates=0`、容量、checkpoint、阈值和 route；
3. commitment 引用独立审计器先生成的 `isolation_report.json` 及其 SHA256；
4. isolation report 与 paired manifest hash 绑定，并对 frozen B/P0 train exposure 和
   `smoke_train_32` 分别确认 molecule、完整 InChIKey、scaffold、source record、style、字体
   文件 hash 与 render profile overlap 全为 0；
5. manifest 行和 sidecar 的 split/source/style 身份一致，解析后的 commitment 父目录以及
   数据/source/shard/sidecar 引用均不得指向
   validation/internal/sealed/reserve/MR-TADF；validation report 只能通过专用引用及 hash
   进入验收；
6. evaluator 逐样本通过 B/C input-target-score 一致性和全部安全门禁。

只有上述证据真实存在，报告才可写 `independent_generalization=true`。commitment 内部的角色
或布尔字段不能替代独立隔离证据；正式 hash 尚未产生和预登记前，dev GO 入口保持禁用。

## 判定边界

本轮结论严格限定为：

- 12-member 数据协议可确定性生成并独立验收；
- split-specific commitment loader 可以只打开被承诺的输入；
- paired evaluator 确实做到单遍数据、一次 target、一次 P0 前向和共享 score；
- B 与 B+coverage 的比较没有被两次独立推理或不同输入污染；
- 正式 dev 在 commitment SHA、Phase A freeze 和独立 isolation report 未齐备时无法启动；
- run5 加固没有改变 run1 的 32/32 个 sample 功能结果。

本轮不能证明：

- coverage 在未见分子、scaffold 或 style 上泛化；
- B+coverage 比 B 更准确，因为 smoke 中两侧原本都是 cross=0；
- 图片到 ChemScene、SDF 或完整分子结构的端到端准确率；
- USPTO、MR-TADF 或其他公开/外部分布上的收益。

`smoke_train_32` 来自 train-exposed 数据，`fresh_audit_eligible=false`，永久不得参与训练、
阈值或 checkpoint 选择，也不得进入正式 fresh split、replacement pool 或 reserve。

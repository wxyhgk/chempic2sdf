# v0.9.84 全图线段 AtomPair Rescue

## 判断

v0.9.83 的 AtomPair group 只能选择已经进入 Bond proposal 集合的候选。旧 BondObject 前端在
`dense_bond_object.py` 中从一个中心 cell 回归方向和半长度，因此仍受训练键长分布影响，并不是
真正的 SVG 线段解析。MR-TADF 极端长键 228 张中，旧 Bond proposal 整图完整率只有 30.70%-
32.02%；后端再强也无法恢复从未进入候选集合的键。

本版将清晰 raster 线条视为长度无关的几何对象：

```text
full raster
  -> OpenCV LSD line segments
  -> 两端吸附到预测 AtomObject
  -> 同一无序 AtomPair 聚合
  -> learned AtomPair group presence / chemical type
  -> ChemScene / SDF
```

没有最大键长、最近邻数量或分子类型路由。双键和三键仍各是一个语义 BondObject，只包含两个
语义端点；多条 physical stroke 只成为同一 AtomPair 的视觉支持。

## 实现

- `chemvector/line_segment_rescue.py`：全图 LSD 与端点到 AtomPair 映射；
- `chemvector/audit_line_segment_rescue.py`：内部域和 MR-TADF 只读 coverage 审计；
- `chemvector/line_segment_group_rescue.py`：图级保守 presence rescue；
- `chemvector.infer_joint_object_structure`：正式单图入口；
- `chemvector.benchmark_joint_mr_tadf`：固定外部 benchmark 入口。

线段端点最大局部吸附误差为 16px、方向误差为 12 度。这两个值只描述端点和线条的局部定位误差，
不会限制两个 AtomObject 之间的距离。正式 presence rescue 还要求：

1. 至少两条 LSD boundary 支持同一 AtomPair；
2. AtomPair 已存在于 learned group 候选中；
3. 两个 AtomObject 均被当前模型选择；
4. 两端当前位于不同预测连通分量；
5. rescue 只提高 presence，不修改 display/chemical type。

推理顺序为 line-rescue group、无 rescue 的 v0.9.83 group、v0.9.72。只有前一路径 SDF invalid
时才进入下一路径。

## Coverage 审计

固定配置先在 ChemVision validation 498 张上运行，再原样用于 MR-TADF；MR-TADF 不参与阈值
选择。

| 数据 | 旧 dense 整图完整率 | line 并集整图完整率 | 旧逐键 recall | line 并集 recall |
|---|---:|---:|---:|---:|

| MR-TADF 全量 | 80.82% | 95.18% | 99.63% | 99.92% |
| 标准键 | 94.96% | 96.26% | 99.91% | 99.94% |
| 长键 | 88.14% | 92.09% | 99.87% | 99.91% |

MR-TADF selected-Atom 模式的 line pair 映射精度为 99.82%。该指标仍不足以允许无条件补边，
因为每图偶发一个 FP 就会破坏整图 exact；因此正式接入使用不同连通分量约束。

## 边界

- 当前只救已有 AtomPair group，尚未为没有 group 的线段创建全新 learned proposal；
- coverage 审计中极端长键 310 根 dense 漏键有 285 根获得线段支持，其中 248 根已有 group；
- OCR、原子类型和 C 占位问题没有在本版处理；
- MR-TADF 结果使用 Oracle 原子化学状态，不能称为完整 OCR 端到端准确率；
- 前端 profile 为 `structure-v0984-carbon`，仍标记 `recommended=false`。

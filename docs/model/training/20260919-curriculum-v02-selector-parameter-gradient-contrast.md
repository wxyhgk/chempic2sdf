# Selector 参数梯度对照：计数压力有影响，但单独隔离还不够

沿用此前固定 32 张干净图和 initial，进行了一个 CPU、无优化器的参数梯度对照。
结论是：**计数压力确实影响真实 selector 参数的局部方向，但它不是全部问题。**
隔离计数项对正例的梯度后，倾向降分的正例从 91/112 减少到 54/112；
典型的 `C#C` 两个正确端点仍倾向降分。不能把这个诊断原型直接当修复推广或开大规模训练。

这里的“升分/降分”全部表示：**沿当前每张图的 selector 参数单位负梯度方向，logit 的一阶导数符号**。
没有实际更新参数、没有改变预测、更没有得到新的识别准确率。

## 固定实验，不搜索配置

- 原 32 张图、原样式、原顺序、原 checkpoint，不替换失败案例。
- 前端视觉与 atom/bond proposal 固定；OCR 不加载，pair/role/bbox 冻结且不调用。
- 对 selector 全部 **178,565 个参数**计算梯度，保持 eval 模式；不是全模型联合训练梯度。
- 每张先做图像侧结构预测，与上轮保存的全部候选逐项精确一致；之后才引入 GT 构造监督。
- 在同一组冻结候选上重放可求导 selector，atom/bond logits 与无梯度结果逐项相同。
- 正式 selector 阈值仍为 -0.25，匹配半径仍为 6 px。没有改匹配或阈值。

主对照只有两个目标：

```text
原目标：现有完整 proposal_object_set_loss
对照：原目标 + 0.1 × (隔离后的 atom_count - 原 atom_count)

隔离后的计数概率：
  raw 正例 → sigmoid(logit).detach()
  raw 负例 → sigmoid(logit)
```

两者的前向损失数值完全相同，只隔离 atom count 这一分支对正例分数的梯度。
focal、ranking、bond presence/count、incidence 均保留。
topology closure 与 graph-exact surrogate 仍保持原调用的权重 0，没有启用新任务。
额外记录原来的 atom partial loss 参数方向，用于衔接上轮分数导数结论，不是第三种待推广的改法。

真实 bond proposals 和 incidence 监督已包含在这次完整 set loss 中。
仍未包含前端、pair、文本等多任务损失；不能将此结果称为全部历史训练机制的归因。

## 结果：部分缓解，尚未通过修复验证

下表统计“沿对应参数方向倾向降分”的正例数，而非误识别数或更新后的预测数：

| 固定候选组 | 分母 | 原完整 set 目标 | 隔离正例 count 梯度 |
| --- | ---: | ---: | ---: |
| 全部 raw 正例 | 112 | 91 | 54 |
| 原已保留正例 | 98 | 83 | 48 |
| 原被丢弃正例 | 14 | 8 | 6 |
| 上轮已指出的 7 个边界附近正例 | 7 | 7 | 4 |

37 个正例从倾向降分变为倾向升分，包括 35 个已保留正例和 2 个已丢弃正例。
本面板没有原本升分、对照后变为降分的正例。

负例约束没有在组均值上整体反转：

- 全量背景负例的平均分数在两种目标下均为 31 张下降、1 张上升。
- 有近邻重复负例的 10 张图，重复负例的平均分数在两种目标下均下降。
- 具体记录的 14 个近邻重复负例中，两种目标均为 13 个降分、1 个升分。

这些只是符号统计，不能称负例抑制完全不受影响：梯度幅度不同，组均值也可能掩盖单个负例的变化。
并未对全部 3,984 个负例逐个提取 Jacobian；全部负例只参与分组均值检查。
逐候选检查为固定的 130 个相关候选，其中含全部 112 个 raw 正例。

## 一个重要修正：分数导数不能直接替代参数方向

上轮 atom partial loss 对 14 个被丢弃正例的独立 logit 导数都指向升分。
但在真实共享参数下，即使只用原 atom partial loss，也有其中 7 个倾向降分；
加入完整 set 目标后则有 8 个。不同候选共享特征和参数，压低某个负例的更新也可能同时压低正例。

因此“标签是正的、直接分类梯度要升分”不等于“训练一步以后这个端点一定升分”。
本轮用显式 Jacobian 与参数梯度的内积核对方向：

```text
单位方向 d = -gradient_theta(loss) / ||gradient_theta(loss)||
候选分数的一阶变化率 = gradient_theta(logit) · d
```

这是每图独立的 Euclidean/SGD 参考方向，不是 AdamW、带动量历史状态、混合 batch 或有限步长的实际更新。

## C#C：排序可以变好，但绝对保留分数仍下降

该图原来保留错误 candidate 0，丢弃正确 candidate 1、2。
一阶分数变化率如下；单位是每单位参数 L2 位移，不是实际更新的 logit 差：

| 候选 | 原 logit | 原目标方向 | 对照方向 |
| --- | ---: | ---: | ---: |
| 0：背景负例 | -0.0892 | -20.7099 | -18.9765 |
| 1：正确端点 | -0.6242 | -9.7373 | -8.0727 |
| 2：正确端点 | -0.8304 | -5.2999 | -3.6305 |

错误候选下降得更快，所以正确端点相对它的排序间隔正在改善：
原目标下分别约 +10.9726、+15.4100；对照下约 +10.9037、+15.3459。
但两个正确端点的绝对分数仍下降，离固定保留阈值更远。

这说明下一步要同时核对“相对排序”和“绝对保留”，不能只看 ranking loss 或候选总数下降。
也不能反过来仅凭第一步正例压分就断言长期训练一定失败：背景压分可能有必要，后续梯度也会变化。

## 决策与下一步

本轮对照证明隔离该分支能缓解部分局部冲突，但不满足完整修复要求。
**暂不把它接入生产损失，不更换模型，不启动新的大训练。**

下一步收窄到 `C#C` 等仍失败的小样本，分解各损失项对两类指标的贡献：

1. 正确端点相对固定保留门槛的方向，尤其两个端点能否同时保留。
2. 正端点相对错误线头/重复候选的排序间隔，以及背景抑制方向。

只有能同时支持这两类指标的单一小改动，再做明确预算的 selector 试训和旧完整分子回放。
不能用这批 targeted 图或梯度符号替代独立开发集效果，也不能将诊断用途自动变成训练授权。

## 执行和证据

- 外部硬截止 300 秒；实际进程总耗时 **28.460 秒**，worker 检查耗时 27.355 秒，正常退出。
- **32 次结构前向、64 次 selector 前向**（其中 32 次包含在结构前向中），pair/OCR 前向 0。
- GPU 使用 0、优化器创建 0、优化器更新 0、私有身份查询 0。
- initial 模型 state 前后相同；没有写入新 checkpoint，没有修改历史 SHA 绑定文件。
- 参数梯度差的重构最大相对误差为 **1.101e-6**，小于预设 1e-3 容差。
- 独立复核 494 个输入绑定、32 个结果 SHA、112 个正例分母、逐类符号统计和相等的前向损失，全部通过。
- 相关合并回归 **174 passed / 2.60 秒**，包含新增 9 项合成测试，不是全仓测试。

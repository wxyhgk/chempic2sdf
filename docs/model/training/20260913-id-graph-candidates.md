# ID 图有限候选模块：首版实现与 200 图验证

## 完成情况

已实现独立的 `chemvector/experiments/id_graph_candidates/`，接入保存的模型输出和
同裁剪 CTC top-8，不重新推理、训练、读取新图片或修改生产代码。
候选生成不接收真值；全部候选与 receipt 保存后，才由单独评分模块读取真值。

原有效的 96 张图保持不动。对原无效的 104 张图生成有限的一步编辑候选：

| 项目 | 结果 |
|---|---:|
| 原无效图中，有合法候选 | 31/104 |
| 原无效图中，候选包含正确非立体分子图 | 12/104 |

候选中新增的正确图按编辑来源分别为属性 3 张、删键 3 张、键类型替换 7 张；
这些分类有重叠，不可相加。总计执行 4,863 个候选编译尝试，得到 60 个去重后的合法候选图。
候选生成计算耗时约 4.30 秒（本机本次总和，不含输入哈希校验与评分，不是稳定延迟基准）。

原正确图 53 张，加上候选中存在正确答案的 12 张，为 **65/200 的候选覆盖**。
这不是选择后的准确率：本版没有自动选择器，实际保留基线的非立体整图正确数仍为 53/200，
立体图仍为 34/200。原有效图中有 43 张非立体图不正确，本版 KEEP 门控没有尝试修它们。

**“唯一合法候选就采用”的规则在这里会选错 11/15，不能上线。**
原正确图零伤害来自 KEEP 门控，不是候选选择器安全性已经得到验证。

## 实现边界

### 文字证据

`evidence.py` 通过 object key 与 crop SHA 同时校验，接回现有 CTC top-8；
本批没有缺失的 beam 记录。保留 raw greedy text、候选 rank、模型、crop SHA、score_kind。
`text_role_score` 与真正的 `ctc_log_probability` 分开存储，二者不混用。

只允许候选文本解释为**同元素、同同位素、同自由基数**下的电荷/氢替代。
解释沿用冻结 parser；每次属性编辑最多改变 formal_charge、explicit_h_count、no_implicit，
记录原始候选字符串及完整来源，不凭真值或“使分子合法”的愿望生成新字符串。
尚未引入通用的属性 unknown 状态，也没有声称文本未出现某字段就证明该化学属性为零。

### 候选预算

每个候选只做一项操作，绝不把“属性＋删键”混成一步：

- ATTRIBUTE：按 beam rank 广度优先、候选原子 ID 排序，最多 64 项属性替代。
- DELETE：已选边中 presence logit 最低的 4 条，各尝试删除一次。
- RETYPE：已选边中 chemical top-2 margin 最小的 4 条，各尝试其他 3 种键类型。

最多 80 次编译尝试/无效图；不添加键、不交换多条键、不补删原子、不修改坐标。
两个样本因属性预算分别截断 3、6 项，完整记录于逐样本结果，没有事后扩大预算。
不同裁剪的 CTC 分数、键分数没有强行相加；这些排序只是候选枚举预算，不是校准后的化学排序器。

RETYPE 同时更新键 type 与 bond.aromatic，不顺手改原子氢、电荷或芳香标志。
只用严格 SDF 编译和回读验证，不使用 sanitize=False、全碳回退或静默芳香修补。
不强制所有分子连通，也不要求每个原子都有边，以保留盐与孤立离子的合法性。

### 输出与歧义

合法候选按保留电荷、同位素、立体信息的规范化 SDF 身份去重。
等价编辑路径归入同一组，保留全部 action provenance，不按重复路径数投票。
代表性 candidate graph 的 observations 是原始证据快照；实际修改及依据在对应 actions 中，
不是把候选解释冒充新的 OCR 观测。

状态为 KEEP_VALID_BASELINE、ABSTAIN_NO_VALID_CANDIDATE、
REVIEW_SINGLE_UNPROVEN_CANDIDATE 或 REVIEW_MULTIPLE_CHEMICAL_GRAPHS。
有一个或多个合法候选都只供影子分析，绝不自动替换。

  但给另一个节点 ID 16 加正电荷也能形成合法的不同分子。最终是两个图，不是唯一答案。
- `fresh_dev_000444_coordgen`：得到四个不同合法图，包括正确 NH、N- 和在另一个 N 上
  改氢/电荷的解释。ID 15 的 NH 替代与把键 89 改为 SINGLE，经过编译后得到**同一正确分子图**，
  已合并并保留两项来源。因此不能只凭操作类别断言后一操作一定修错。
- `fresh_dev_001376_coordgen`：删除误三键 ID 292 得到唯一且正确的候选；
  仍保留 REVIEW_SINGLE_UNPROVEN_CANDIDATE，不因为已知案例的真值而自动采用。

## 下一步范围

现在有了可复用的候选接口与明确的失败记录，但还没有安全的自动纠错器。
正确答案未进入候选的无效图仍有 92 张，单纯训练排序器不可能解决这些样本；
下一版应先区分固定节点/单步预算的限制与文字候选不足，再限定扩展编辑范围。
已覆盖的 12 张则可用于研究候选排序和拒绝，但需分开评估“找得到”和“选得对”，
不能从本轮数据挑规则后直接声称泛化有效，也不据此重新开启 MoE/循环深度训练。

# v0.10.1 Set-First Style 10k

## 目标

v0.10.0 直接联合更新 Bond 与 set/incidence 后，Bond proposal recall 基本不变，但 Bond exact
和 Full exact 崩溃。本轮只验证一个因果假设：固定 Bond proposal 分布，单独让 set/incidence
适配新 style 数据，是否可以避免崩溃并产生足够的 fresh 增益。

## 协议

- 源 checkpoint：`v0.9.72` Bond presence calibration best；
- vision、Atom、Bond 全部冻结；
- 只更新 set presence 与 incidence，共 178,565 参数；
- Bond loss 权重为 0；
- style train 6,668 张，ChemVision replay 1,666 张，expanded-font replay 1,666 张；
- 总计 10,000 张，batch 比例仍为 4:1:1；
- 完整 fresh-dev 8,000 张用于最终评测；
- sealed-test 权限保持 `000`，未读取。

工程 smoke 验证训练前后 50 个 Bond state tensor 全部 `torch.equal`，因此这不是低学习率 Bond
训练，而是严格 set-first。

## 结果

完整 8,000 张 fresh-dev：

| 指标 | 初始 | 10k | 变化 |
|---|---:|---:|---:|
| Atom deployed exact | 48.0000% | 48.8375% | +0.8375pp |
| Bond deployed exact | 28.7125% | 28.9000% | +0.1875pp |
| Incidence exact | 53.8000% | 53.9375% | +0.1375pp |
| Full object exact | 20.9500% | 21.1875% | +0.2375pp |

旧域最差 Full exact 从 32.1285% 提高到 32.7309%，没有遗忘。训练过程稳定，未重现 v0.10.0
的崩溃，但预先固定的 fresh Bond exact `+2pp` 门槛未通过。

## 决策

稳定性 GO，能力/部署 NO-GO；不切换前端，不解封 sealed-test。

本轮证明了两件事：

1. v0.10.0 的灾难性回退来自 Bond 与 set 同时移动，而不是新数据本身；
2. 固定 Bond 后，set/incidence 单独扩量已接近平台，不能贡献需要的主要提升。

下一步从本 checkpoint 热启动，仅将 Bond 学习率降为 v0.10.0 的十分之一，在已适配的 set
边界附近做 10k 小步联合训练。若仍回退或提升不足，停止参数时间尺度调节，转向显式的
proposal feature anchoring/distillation。

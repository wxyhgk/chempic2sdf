# v0.9.48 Proposal 集合选择扩量到 1k

> 状态：1k 数据扩量 GO，完整分子/SDF 仍为 NO-GO  
> 训练：ChemVision train 1000  
> 选择：ChemVision validation 100  
> 固定门控：ChemVision internal_test 100  
> 外部数据：未使用 USPTO 或 MR-TADF

## 目标

回答 v0.9.47 的 train100 -> validation100 大幅回落究竟来自架构错误还是数据覆盖不足。
本轮保持以下内容不变：

- 冻结视觉、空间 AtomObject 和空间 BondObject；
- 每图 128/128 target-independent proposal；
- 178,565 参数联合 presence/incidence 头；
- 不提供真实 count；
- 不使用键长阈值和最近邻附着。

唯一主要变量是将训练图片从 100 扩到 1000。

## 训练过程

首轮从 v0.9.47 warm start，并错误沿用了 `Atom=-2.5` 的旧校准阈值作为 checkpoint
选择阈值。继续训练后 Atom logit 整体漂移，平均选择数升到 68.9，整图指标失效，因此在
step 400 主动停止。该次训练权重本身并未失效：对 step400 重新做阈值审计，零附近的
`Atom=0.25/Bond=-0.25` 已达到 validation full exact 21%。

正式 continuation 从该 step400 开始，降低学习率：

```bash
.venv-train/bin/python -m chemvector.train_proposal_object_set \
  --train-shard Data/sdf/chemvision_layers_v0_1/pilot_10k/shards/train-000000.tar \
  --train-samples 1000 \
  --validation-samples 100 \
  --train-evaluation-samples 100 \
  --warmstart-set-checkpoint \
    outputs/checkpoints/chemvector-v0948-proposal-object-set-train1000-val100-step2000/step-000400.pt \
  --atom-decision-threshold 0.25 \
  --bond-decision-threshold -0.25 \
  --output-dir outputs/checkpoints/chemvector-v0948-proposal-object-set-train1000-cont1200 \
  --max-steps 1200 \
  --batch-size 8 \
  --presence-learning-rate 5e-5 \
  --incidence-learning-rate 5e-6
```

最佳 checkpoint 位于 continuation step 1000。

## 判断

数据覆盖是 v0.9.47 presence 泛化的真实瓶颈之一。唯一训练图从 100 扩到 1000，在架构
不变的条件下将 validation full exact 从 8% 提到 24%，未见 internal test 仍有 19%。

这不代表已经能输出完整分子：当前 full object exact 只检查 Atom/Bond proposal 集合与
incidence，不包含 OCR 字符串、完整化学状态、ChemScene v0.2 编译和 SDF 往返。约 1%–2%
的单对象 proposal 漏检也会直接限制整图上限。

## 决策

- train1k 扩量：GO；
- 联合 proposal set + incidence：继续作为新主线；
- v0.9.48 替换稳定推理：NO-GO；
- 下一步：保持固定 internal-test 协议，将训练扩到 pilot 全 9k；训练完成后再接
  ChemScene v0.2/SDF shadow，不先用 USPTO 或 MR-TADF 调参。

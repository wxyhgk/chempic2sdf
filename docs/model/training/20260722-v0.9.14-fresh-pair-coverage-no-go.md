## 目标

v0.9.11 在 train/calibration900 上用 target-free whole-set coverage 删除了低阈值 B 的最后
一个 cross-target pair，但那是观察 calibration 残差后的 post-hoc `DEV-GO`。本轮只回答：

```text
同一 fresh 图像、同一 target、同一 frozen P0/pair score、同一初始 matching
                 |                         |
                 B                 B + frozen coverage veto
```

coverage 是否能在 molecule、scaffold、source record 和 style 均隔离的 fresh 数据上继续删除
cross-target pair，并保持 recall、P2、support 和延迟门禁。

这仍是 oracle-routed ordinary-anchor pair stage，不是端到端 OCSR、骨架 exact 或 SDF 准确率。

## Loader 实包修复

正式 commitment 第一次迭代暴露了两个 fixture 未覆盖的协议错误。两次都在不修改数据、模型、
checkpoint、阈值或 coverage 规则的前提下修复，并以 smoke 功能等价回归确认。

### Layers 与 Meta 的 Dataset 语义

真实 sidecar 中：

- `.layers.json.source.dataset` 是渲染输入根：`webdataset_full_v0`；
- `.meta.json.source.dataset` 是 split-qualified provenance：`webdataset_full_v0/train`。

旧 loader 错误要求两者字符串相同。现改为分别校验 dataset root 与 provenance，并继续强制
`source_sample_key/source_shard` 一致。

### 重建 SMILES 文本不作为结构等价门禁

`fresh_dev_000072_coordgen` 的 SDF/ChemMol 原子、键、chiral tag 和完整 InChIKey 全部一致；
但 RDKit 重建时 bond/neighbour insertion order 改变，使同一绝对手性的 canonical SMILES
中 `@/@@` 文本翻转。现协议改为：

- declared canonical SMILES 只与源 SDF 的 canonical SMILES 比较；
- ChemMol 重建正确性由精确 atom/bond 字段和完整 InChIKey 验证；
- 不再要求重建 SMILES 字符串逐字相等。

## 根因分解

candidate pool 不是主瓶颈：

```text
m2 targets              318,199
pairable m2 targets     318,006  (candidate ceiling 99.9394%)
matched m2 targets      316,209  (current recall 99.3746%)
```

1,990 个漏配中：

- 193 个缺 candidate，占 9.70%；
- 1,797 个 candidate 已存在但未选，占 90.30%。

达到 99.5% recall 只需额外救回 400 个，candidate ceiling 足够。437 个 pairable exact 失败中，
432 个是纯漏选；共有 714 个 expected pair 漏选，仅有 10 个 extra pair。即使把每个 extra
视为最多冲突两个 expected，至少 694/714 的漏选仍是无冲突 pair 没有过全局 gain threshold。

matching 不是主因：8,000/8,000 个样本均为 optimal，candidate permutation 全部确定。

分布偏移明显：

- `stress` 承担 834/1,797 个 selection miss，m2 recall 为 98.6726%；
- COCONUT 只占 16.8% 图片，却承担 842/1,797 个 selection miss，recall 为 98.3621%；
- ChEMBL recall 为 99.5902%；
- 642 个 selection 失败分子中，443 个只坏一个 variant，仅 29 个四 variant 全坏。

这更符合 frozen pair scorer 与单一全局阈值在 fresh 视觉/结构域上的可达性问题，不是分子
真值、candidate 或 matching solver 系统性错误；但 fresh 诊断本身不能直接证明应该训练
sample-adaptive offset/temperature。

1,771/1,797（98.5531%）按 artifact 定义严格领先所有 incident cross-target negative。该 1,771
由 1,322 个没有 incident negative 的 miss 和 449 个在存在 negative 时仍严格领先的 miss 组成；
其余 26 个才是局部排序失败。证据说明主要损失发生在标量 threshold 前沿，而不是被局部负 pair
普遍压过；每张图独立选择一个标量 `tau(x)` 时是否能稳健满足全部门禁，仍必须回到 train-only
数据做 target-aware oracle 上限验证。

对 47 个 selected cross，artifact 可直接复核：47/47 在两个端点上都是 incident top-1；
29/47 至少一侧 target 只有一个 carrier，11/47 两侧都是 singleton，仅 1/47 两侧都存在
same-target 正候选。这里不再使用含义和分母不明确的“global normalized rank p50”表述。
这些 cross 更像局部证据被高估的 orphan bridge，而不是低分 pair 被 matching 随机捡起。

coverage 对 47 个 cross 的首个失败分支为：22 个离散 upper-bound 不足、9 个 exact union
不足、11 个 contributor 少于 2、5 个被单一 contributor 覆盖。即使允许所有其他 selected
pair 参与覆盖，而不只使用更强 pair，命中仍为 0/47。相反，被 veto 的 58 个真 same-target
pair 来自 carrier multiplicity 4--15、中位数 8 的密集重复 target。coverage 假设的“多个
更强 carrier 已经解释两条线”与 fresh cross 不是同一种机制。

## 决策

v0.9.11 coverage 路线停止作为主修复方向。它在 calibration900 命中的唯一 leftover-bridge
机制没有泛化到 fresh8k 的 cross，继续调整 tube、角度或 coverage 阈值会直接使用 fresh
残差调参，并且没有证据能修复 m2 recall 与 pairable exact。

当前 fresh_dev 已经暴露，后续修改模型、阈值、coverage 或数据协议后，不得再把本数据称为
独立泛化审计，也不得申请本轮 sealed audit。sealed、internal test 和 MR-TADF 继续不读。

score-frontier 诊断已经完成。下一步不是直接训练 offset/temperature，也不使用 fresh 残差选择
新阈值；先执行 [v0.9.15 train-only 每图标量 Tau 可达性](20260722-v0.9.15-train-only-per-sample-tau-reachability.md)，
只在原 fit/calibration 暴露上计算每张图一个 `tau(x)` 的 target-aware oracle 理论上限。只有非退化
threshold 区间上的 robust oracle 通过才训练 target-free `tau(x)` predictor；boundary-only 解不算
可学习上限。若 robust oracle 不可达，再转向能观察 pair 周边上下文的新 scorer。

新模型、阈值和实现冻结后，必须建立新的 molecule/scaffold/style-disjoint `fresh_dev2` 做一次性
审计。生产推理保持 `v0.7.10`。

# 第一轮键头试训：50步触发保护早停，局部有收益但不部署

用户明确提出“持续推进，开始第一轮的训练”，中断后再次确认“继续”。
本轮已实际执行一次自研 ChemVector **完整 pair head** 试训，不是又一次无更新检查。
RTX 5090单卡的受监督进程总耗时 **13.330秒**，完成 **50次参数更新**，在首次50步检查
发现回退后停止，没有用满600秒/200步，也没有重试、续训或切换默认模型。

## 1. 结果：有学习信号，但未通过预先规定的保护门槛

以下全部是同一58张训练/回放图上的固定阈值结果，**不是独立测试准确率**。

| 指标 | 本轮initial | 50步 |
| --- | ---: | ---: |
| 严格完整分子SDF正确 | 19 / 58 | 21 / 58 |
| 存在且原始化学类型正确的可达键 | 1024 | 1049 |
| 严格匹配可达键 / 全部目标键 | 1103 / 1150 | 1103 / 1150 |
| 确认假边 | 1 | 3 |
| 未知对应pair中的预测有键数 | 18 | 26 |
| 可编译有效SDF | 53 / 58 | 52 / 58 |
| 使用编译fallback | 3 | 4 |

新增27条原始类型正确的键，同时丢失2条原本正确键，净增25条。
“未知对应pair预测有键数增加8”不等于新增8条假边，未知对应没有被擅自当作非边。
仍有47条目标键缺少严格匹配下的正监督；冻结上游不会自动补齐这个缺口。

两张新修好的完整分子来自基础26图：

- `curr_d41392dc19a768b4__reference`：`CC=NC`。
- `curr_23794d91c53ae875__reference`：`NO`。

原先19张严格完整分子正确的图全部保持正确。基础26图正确数 **11→13**，
旧完整分子32图 **8→8**。因此这不是全面退步，但局部收益不能掩盖下面的安全回退。

## 2. 为什么50步就停

原协议规定，任一旧正确类型键丢失、确认假边增加、有效SDF丢失或新增fallback都要停止。
本轮有4张旧完整分子触发，不能看总量净增就继续训练：

| 样本（省略curr_） | 触发项 |
| --- | --- |
| cb5b7da426023d14__font_large | 丢失原正确类型键21；新增fallback |
| 4ef506af64e8f0b8__bond_short | 确认假边增加 |
| 420203be8470416f__line_thick | 丢失原正确类型键26 |
| 08d02946e879406f__font_large | 确认假边增加；由有效SDF变成编译失败 |

最后一张的保存错误为 `Explicit valence for atom # 4 C, 5, is greater than permitted`。
这是一条预测图的化学有效性错误，不是CUDA或训练进程故障。
进程正常退出，资源回执 `status=completed`；实验验收为 `stop_regression`。

## 3. 实际执行范围

- 同一已绑定 initial；原固定58图的metadata、348份payload先核验，未新增分子或身份查询。
- 新增独立单次授权，同时记录该58图从定位器用途向本轮键头用途的扩展；
  原数据准入、旧授权、历史代码和报告没有改写。
- 只更新现有pair的 **2,266,565个参数**，不是只调最后的presence线性层。
  视觉、原子、键候选、selector、role、bbox、OCR冻结，全模型eval、FP32、TF32关闭。
- AdamW，LR `2e-5`，weight decay 0，clip 1；`matched-only-v1`，不补新正例。
- 在本轮GPU上58次上游前向，重新构造候选/匹配/标签；不复用历史CPU/GPU槽位标签。
  缓存冻结的上游特征，训练步骤仍重新计算pair自己的ribbon encoder和hidden。
- 原清单顺序尝试54张，其中4张空监督图跳过更新：22张基础见证、28张完整分子实际更新一次。
  最后4张完整分子在早停前未轮到更新，但完整58图都参与initial和50步检查，未被删出分母。
- 总计116张次完整评估；每次预测只接收像素和冻结预测，GT只用于loss与评分。
- 未读取64张开发图、旧944图回归或封存测试逐图文件。当前结果只能说明训练侧可学性与回退。

## 4. 实现与核验

新增模块与现有逻辑分开：

- `pair_cached_trial.py`：冻结缓存、仅键头单步更新、完整pair评分。
- `pair_only_trial.py`：独立授权核验、不可复用的调用预留、外部600秒预算。
- `pair_only_worker.py`：58图缓存、完整分子检查、早停、独立pair delta保存。
- `test_pair_only_trial.py`：20项新增合成CPU用例；相关合并回归 **249 passed / 2.81秒**。
- `tools/audit_pair_only_trial_result.py`：只读保存结果后核验，没有再次模型推理或训练。

后核验通过：406项数据输入哈希、24项实现哈希、50次更新意图/完成日志一一对应、
54次尝试顺序和4次跳过、116份保存MolBlock重新规范化评分、完整58图汇总与早停重算。
独立读取initial和pair delta：pair的32个状态张量均改变且有限，策略/初始权重/缓存/授权绑定正确。
worker的冻结部分和OCR初末哈希相同，冻结部分初始哈希另与initial文件重新计算一致。

核验边界：冻结特征张量只保存在运行内存，磁盘保存的是其哈希回执；本轮没有额外重跑模型
重建整个缓存。原始pair指标做保存逐图指标的汇总重算，严格SDF则由保存MolBlock重新评分。
非pair最终状态未单独保存完整checkpoint，其不变性依据worker内的前后状态哈希，
而不是声称从pair delta能恢复独立的全模型最终快照。

## 5. 结论与下一步

第一轮已经开始并结束，回答了一个实际问题：**冻结上游后，现有键头能学到部分连接，
但本配方也会带来假边/有效性回退，暂不具备安全替换initial的条件。**
这不是证明掩码本身带来全部收益，也不是证明架构必须推倒重来。

本次单次许可已消耗，停止在50步，不自动降低学习率重跑、不扩大样本、不改阈值。
下一步适合先利用保存logits与编译trace，定位这4张回退图的新增边/丢失边，
区分“已有正确键被破坏”和“未知pair变活跃”等来源；无需立即再消耗GPU。

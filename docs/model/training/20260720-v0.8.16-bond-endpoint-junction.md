# v0.8.16 语义 Bond Endpoint 生成 Junction

> 状态：结构 GO，端到端 NO-GO，shadow 仅供诊断  
> 日期：2026-07-20

## 问题修正

之前的 ChemScene 推理虽然检测完整 Bond Object，但仍先由旧顶点模型生成 Junction，
再把 Bond endpoints 分配过去。因此双键副线、三键平行线、字符笔画仍可能产生额外
结构点，尚不是真正的 Bond-first。

本轮规定不可破坏的表示不变量：

```text
SINGLE  = 1 Bond Object + 2 semantic endpoints + order 1
DOUBLE  = 1 Bond Object + 2 semantic endpoints + order 2
TRIPLE  = 1 Bond Object + 2 semantic endpoints + order 3
```

平行 stroke 数量不进入顶点数量。Junction 只由完整 Bond Object 的语义端点聚合产生；
OCR 只能把文字附着到已有 Junction，不能创建结构点。

## 实现

新增：

- `chemvector/bond_endpoint_junction.py`
- `chemvector/audit_bond_endpoint_junction.py`
- `--junction-source bond_endpoints` shadow 推理模式
- 前端实验 profile `development-v0816`

聚合不使用键长上限或最近邻删边。每个 Bond candidate 固定贡献两个端点假设；不同
Bond 对象端点在像素空间聚合，共享端点成为 Junction；自环被拒绝，相同 Junction
pair 只保留最高分 Bond Object。

OCR 仍可使用文字检测，但只进行一对一标签附着。未匹配文字不会新增 Junction，未被
文字覆盖的 Junction 固定回退为隐式 `C`。

Bond-first 不会自动修复 detector 的假键或漏键。交叉和近邻切片仍必须在 Bond
candidate detector/selector 层解决，不能通过重新引入 stroke 顶点补丁处理。

## 外部诊断

`test1.png` shadow 推理成功生成 17 原子、18 键的有效 SDF，视觉拓扑与输入一致，
双键没有制造额外顶点。

`GD906.png` 仅作 MR-TADF 外部诊断，不参与参数选择。预测 88 原子、108 键，真值
84 原子、104 键，多出的假 Bond candidates 造成一个五价碳并使 SDF sanitize 失败。
这属于 detector 假键问题，不是多重键端点表示回退。

## 决策

- 语义 Bond endpoint -> Junction：GO。
- shadow 推理：仅供诊断，不替换稳定 v0.7.10。
- 旧隐式顶点模型：退出结构骨架路径，只保留文字检测/OCR 标签附着。
- 下一步首先重做 TextObject 到 Bond Junction 的监督式 assignment；随后针对交叉和
  near-nonbonded 训练 Bond candidate 集合拒绝机制。两者都必须保持“一个化学键
  对象固定两个端点”的表示不变量。

## 删除动作究竟带来了什么

v0.10.16 使用既有冻结 ranking 与 structural-twin 条件，每图最多删一个节点，
共 19 张执行。没有新增候选编辑、按真值选择节点或重排动作。

4 张非立体救回图：

- `fresh_dev_000093_coordgen`，删除候选 19。
- `fresh_dev_001049_coordgen`，删除候选 36。
- `fresh_dev_001102_coordgen`，删除候选 35。
- `fresh_dev_001179_coordgen`，删除候选 39。

其余动作中，4 张从无效变成合法但仍错误，4 张原本合法且仍错误，7 张仍无效。
19 张动作图在基线均非整图正确，因此这里的“0 整图损失”不能当作对正确图执行删除的
充分安全证据，更不等于所有删除都经真值证明无害。

没有执行动作的 181 张，两个 profile 的 core/stereo 签名、OCR labels 与 decode path
逐张一致。这个检查只比较预测输出，不使用真值决定动作。

## 修补、回退与历史基线的解释边界

v0.10.10 有 73 张进入旧编译回退，其中 14 张最终得到合法 SDF，**14 张均未达到
非立体整图正确**。v0.10.16 对应为 63 张尝试、12 张合法、0 张非立体正确。
这些数字只描述本批，不能推断所有数据上的回退必定无效。

需要纠正先前的术语：`compile_carbon_placeholder` 虽名为 carbon fallback，
实际代码主要清除原子芳香标志、调整芳香键并重建端口；不会把 OCR 已写入的 N/O 等
全部重置成 C。初始无文字节点默认碳，是另一项策略。新增单元测试明确保护此区别。

历史严格 ID 图与本轮前端不是单变量编译 A/B：旧基线采用 batch 6 检测及冻结的
CPU FP32 OCR 字符串；前端按原入口 batch 1、CUDA BF16 重新执行 OCR，且使用旧
坐标/场景编译、环融合、芳香处理和回退。因此历史基线只作同评分器下的参考。

历史严格图 → v0.10.10：合法结果新增 45 张、无损失；非立体正确救回 3 张、损失 1 张。
不能将这个净增直接归因于某一项修补。

事后核对这 4 张变化图，原子数量与对应 OCR 字符串未变化；损失图
`fresh_dev_000885_original` 启用环融合后有 3 条键类型变化，最终进入回退。
这是排查线索，尚未以同一原始前向结果逐项消融证明因果，不据此调整环阈值。

## 实现与可信度检查

新增隔离包 `chemvector/experiments/profile_comparison/`：

- `protocol.py`：绑定动态前端 registry、模型链、固定图片与评分输入。
- `runtime.py`：直接调用原 `infer_direct_atom_pair_bond.main()`；只缓存 checkpoint
  加载，不缓存图片、前向特征、决策或结果。每图交替两臂顺序。
- `scoring.py`：预测收据完成后才读取真值签名；统一评分、完整分母和配对 rescue/harm。
- `__main__.py`：GPU 独占锁、冻结、推理、评分；拒绝覆盖既有输出。

没有复制模型 forward 或重写生产编译器。输入是原 PNG 字节，不重新编码或丢弃 alpha。
全部权重保持不变。四种布局各取首张、再取首个实际删除样本，两个 profile 各做独立
冷启动 CLI 对照，共 10 次：除耗时外 metrics、场景 JSON、SDF、预处理 PNG 均严格一致。
这验证选定样例的常驻/冷启动一致性，不声称对所有 400 次都另跑过冷启动。

验证结果：

- 新增 23 项测试通过；相关推理、删除、ID 图和文字入口回归共 **271 passed**。
- 200 张真值 SDF 通过统一评分器控制；历史严格基线 200/200 精确重现。
- 独立从磁盘重新读取三臂 SDF，600 行评分及三个配对表全部重算一致。
- 200 份输入 PNG 与原 manifest SHA 全部一致。
- 810 份绑定源码、10 份 checkpoint、2 个 shard、904 份输入、3,485 份输出工件
  哈希检查通过；另核对三个历史诊断/候选协议的源码绑定，保持不变。

本轮只解码原 200 张图，未读取新训练样本、sealed test、MR-TADF 或 USPTO 评测内容。

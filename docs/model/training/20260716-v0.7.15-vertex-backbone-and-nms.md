# 2026-07-16 v0.7.15 顶点主干适配与峰值抑制

> 状态：视觉主干小幅解冻 GO；固定宽 NMS 仅作机制验证，不作为生产默认  
> 数据：MolGrapher pilot train 9,000 / validation 1,000  
> 权重候选：`outputs/checkpoints/chemvector-v0715-dense-unfreeze1-9k-45k/best.pt`

## 目标

v0.7.14 的 dense heatmap 在 6px 已有约 89.5% F1，但整图 vertex exact 只有 6.3%。
本轮检验瓶颈来自视觉特征、目标表示还是解码方式。relation、OCR 和 MR-TADF 均未
参与 checkpoint 选择。

统一基线为 MolGrapher validation 1,000，768×768 输入、6px 容差。训练候选仍保留
全点对 relation 原则，不增加任何键长候选删除规则。

## 解冻一个 stride-4 block

初始化 v0.7.14 dense 最佳权重，只解冻共享视觉编码器最后一个 stride-4 block，并
继续训练 dense vertex head：

```bash
.venv-train/bin/python -m chemvector.pretrain_vertex \
  --init-checkpoint outputs/checkpoints/chemvector-v0714-dense-vertex-long-90k/checkpoint-0005000.pt \
  --train-shards 'Data/sdf/molgrapher_synthetic_v0_1/pilot_10k/shards/train-*.tar' \
  --validation-shards Data/sdf/molgrapher_synthetic_v0_1/pilot_10k/shards/validation-000000.tar \
  --output-dir outputs/checkpoints/chemvector-v0715-dense-unfreeze1-9k-45k \
  --train-samples 45000 --epochs 5 --batch-size 8 \
  --learning-rate 1e-5 --weight-decay 0 \
  --unfreeze-stroke-blocks 1 --threshold 0.35
```

可训练参数为 171,748。最佳 checkpoint 在旧 `3×3` NMS 下得到：

| 指标 | v0.7.14 | v0.7.15 unfreeze-1 |
|---|---:|---:|
| 6px F1 | 89.48% | 90.72% |
| Count exact | 约 20.0% | 23.8% |
| 6px vertex exact | 6.3% | 9.5% |
| 16px vertex exact | - | 11.1% |

只解冻约 79k 个视觉参数即获得稳定提升，证明冻结主干确实限制了新渲染域的局部
特征适配。再解冻两个 block 后可训练参数增至 250,948，但 6px vertex exact 仍为
9.5%，没有继续收益，因此停止扩大解冻范围。

## 否决支线

### 适配主干后的 Atom Query

使用已经适配的 stride-4 backbone 重训 Atom Query。16px F1 约 58%，Count exact
19.4%，仍明显低于 dense head，判定 NO-GO。

### 顶点角色 heatmap

增加 `implicit_junction` 与 `visible_text` 两通道监督：

- 直接按角色通道解码，最高 vertex exact 7.4%；
- 角色辅助损失、仍用原 heatmap 解码，最高 8.8%。

角色标签没有解决整图漏峰和多峰，代码保留作分析接口，不进入当前最佳路线。

### CenterNet 式高斯中心

为 heatmap 增加半径 1 和 2 cell 的高斯软标签，offset 仍只在真实中心监督：

| 半径 | 最佳阈值 | 6px F1 | Count exact | Vertex exact |
|---:|---:|---:|---:|---:|
| 0，原基线 | 0.35 | 90.72% | 23.8% | 9.5% |
| 1 | 0.35 | 90.72% | 24.4% | 9.2% |
| 2 | 0.40 | 91.12% | 24.0% | 9.5% |

半径 2 只提高局部 F1，整图 exact 仅追平；半径 1 更低。高斯监督判定 NO-GO，
不继续增加 epoch。

## NMS 机制诊断

原解码器只用 `3×3` 局部极大值。固定权重扫描更宽窗口后，同源 validation 出现
显著提升：

| 解码 | checkpoint | 6px vertex exact | Count exact | 6px F1 |
|---|---|---:|---:|---:|
| `3×3`, t=0.35 | 5k | 9.5% | 23.8% | 90.72% |
| `19×19`, t=0.175 | 4k | 23.1% | 38.8% | 88.46% |

真实顶点中最近邻小于 36px 的比例只有 1.28%，因此在该 768px 合成分布上，宽 NMS
能删除大量线条响应产生的次峰。它证明当前主要问题之一是候选峰缺少一对一竞争，
而不是模型完全看不到顶点。

但 USPTO clean 前 200 张的端到端 A/B 表明固定窗口不能直接部署：

| 指标 | `3×3`, t=0.35 | `19×19`, t=0.175 |
|---|---:|---:|
| 原子数一致 | 2.0% | 4.5% |
| 有效 SDF | 11 | 11 |
| 有效预测平均指纹相似度 | 0.138 | 0.216 |
| disconnected | 76 | 127 |
| valence | 111 | 60 |

宽 NMS 的去重收益能够迁移，但 USPTO 绘图尺度不同，固定半径会吞掉相邻真顶点并
增加断图。因此 `nms_kernel_size` 已贯通训练验证、顶点评估和并行 SDF benchmark，
默认值仍保持 `3`；`19` 只用于本轮机制诊断。

## 决策

- 解冻一个 stride-4 block：GO，作为 v0.7.15 权重候选；
- 解冻更多 block：NO-GO；
- Atom Query、角色 heatmap、高斯中心：NO-GO；
- 固定宽 NMS：同源诊断 GO，跨域生产 NO-GO；
- relation 9k 扩量仍暂缓，第一瓶颈仍是顶点集合。

下一版不再训练另一个全局 count head。使用现有 dense peaks 作为高召回 proposals，
增加轻量候选保留分类器；训练时按真实顶点做一对一匹配，同一真实点附近只允许一个
proposal 为正，其余稳定次峰作为困难负样本。该分类器必须使用归一化相对距离或局部
视觉特征，不能把 768px 下的固定 NMS 半径写死到模型中。

## 工程与验证

- `decode_vertices` 新增正奇数 `nms_kernel_size`；
- 训练验证、独立阈值评估、并行推理、USPTO/MR benchmark 均可显式传入该参数；
- 通用 checkpoint 加载器兼容旧权重缺失的影子角色 heatmap；

- MR-TADF 未进入训练、调参或本轮 checkpoint 选择。

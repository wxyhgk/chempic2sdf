# 2026-07-18 v0.8.1 空间线对象 Bond-First

> 状态：组件 GO，端到端不可部署  
> 基础 checkpoint：v0.7.38 视觉编码器路径  
> 最佳容量 checkpoint：`outputs/checkpoints/chemvector-v082-line-object-set-smoke100/best.pt`  
> 最佳泛化 checkpoint：`outputs/checkpoints/chemvector-v082-line-object-9k-5epoch/best.pt`

## 目标

验证 ChemScene v0.1 之后的第一种真正 Bond-First 模型：不先检测原子点，也不枚举
点对，而是直接从图片检测完整的键对象。

门槛分两级：

1. 固定 100 图达到至少 95% Oracle-Junction SDF exact，证明表示和损失有容量。
2. 进入 9k/498 scaffold、字体独立验证，确认对象身份可以跨图泛化。

MR-TADF 和 USPTO 均未用于训练、阈值或 GO 决策。

## 实验一：自由 Bond Query

沿用 v0.7.35 的 128 个 learned queries，增加超过 4px 的端点屏障损失。平均端点
损失改为整图最坏键的极值损失时，query 身份频繁交换，100 图 exact 从约 55% 降到
9%，明确 NO-GO。

改为对每个超界端点施加平滑屏障后，固定 100 图达到：

- BondObject exact：98%。
- predicted count：100%。
- Oracle-Junction SDF exact：97%。
- 双键、三键等四类 display count exact：100%。

但相同模型进入 9k 一轮后完全失去视觉身份：

- object accuracy：0.0546%。
- endpoint pair recall：0.1637%。
- 整图 exact：0%。

结论：自由 query 可以记忆 100 图，但不能作为 v0.8 主线。

## 实验二：空间 BondObject

将 query 身份固定在 stride-4 的 192x192 画布位置。数据统计显示：

- 99% 的键短于 143px。
- 同一 stride-4 中心格的额外碰撞只占 0.196%。
- 每格最多 3 根键，因此使用 3 个对象 slot。

第一版直接回归四个端点，在 100 图训练 5,000 次后 exact 仍为 0%，NO-GO。原因是
端点顺序任意，模型同时承担中心、方向、长度和排列的不稳定目标。

正式版按直线对象参数化：

```text
BondObject = 中心 + (cos 2θ, sin 2θ) + 半长度 + 键型
两个端点 = 中心 ± 半长度 × (cos θ, sin θ)
```

双角表示让直线方向无正反号歧义。四层扩张卷积提供约 176px 的有效感受野，再用
确定性几何还原端点。

## 100 图容量结果

加入空间稳定的“最弱真中心 vs 最强远处假中心”间隔损失后：

| 指标 | 结果 |
|---|---:|
| BondObject exact | 98% |
| predicted count accuracy | 98% |
| Oracle-Junction SDF exact | 98% |
| object accuracy | 99.85% |
| p95 图级最大端点误差 | 1.37px |

失败只剩 `000000011` 和 `000000025`。容量门槛通过。

## 9k/498 泛化结果

一轮训练后，空间线对象已达到 62.41% object accuracy 和 0.80% SDF exact；自由
query 对照为 0.0546% 和 0%。说明空间身份把跨图泛化提高了约三个数量级。

继续训练到总计 5 个 epoch：

| 指标 | 最佳整图 checkpoint | 最后一轮 |
|---|---:|---:|
| object accuracy | 67.55% | 69.03% |
| known-count object exact | 3.01% | 2.61% |
| predicted count accuracy | 50.20% | 49.40% |
| SDF exact，threshold=0.30 | 2.21% | 2.01% |
| SDF exact，校准 threshold=0.25 | 2.61% | - |

阈值 `0.20` 的计数准确率最高为 56.63%，但 SDF exact 只有 2.41%。阈值无法修复
中心漏检和长键长度误差。

## 决策

- ChemScene 对象监督：GO。
- 自由 learned Bond Query：NO-GO。
- 空间中心 + 无向角度 + 长度：组件 GO。
- 当前 9k checkpoint：不可部署，不替换 v0.7.10 或 v0.7.38 shadow。

下一步 v0.8.2：

1. 使用 stride-4/8/16 多尺度特征提高中心检测和长键长度估计。
2. 将中心计数与对象排序分开，避免单一 heatmap 阈值承担整图 cardinality。
3. 训练 Junction Assembler 联合匹配所有键端点，禁止独立最近点吸附。
4. 继续以 Scene SDF exact 为主指标，不用局部 object accuracy 代替整图结果。

# v0.9.88 候选键关系图与安全删除

## 假设

v0.9.87 仍有多余键。典型错误包括：

```text
A-B-C       错误增加 A-C

    A
  / | \
 B  C  D    错误增加 B-D
```

逐条键独立分类看不到“中间有第三顶点”或“两端已经通过共同邻居连接”。本实验将每条候选
AtomPair 当成关系图中的边对象，结合周围候选和原图墨迹，只审查 v0.9.87 已判为存在的键。
模型不能补边，因此不会把该实验与漏键 rescue 混在一起。

## 关系特征

每条候选键使用 18 个尺度归一或无序特征：

- 线段长度和无向方向；
- 线带直接墨迹 mean/min/std/coverage；
- 其他候选线段对当前线段的解释比例；
- 独占墨迹及独占比例；
- 第三 AtomObject 位于线段内部的强度与数量；
- 两端共同邻居、共线共同邻居；
- 两端软候选度数。

完整 head 还聚合共享端点和整图候选上下文。推理只有一个操作：

```text
base logit >= 0 且 deletion logit >= 固定阈值 -> 删除
其他候选保持 v0.9.87 原结果
```

不使用元素价态、绝对键长、分子类别或 MR-TADF 标签。

## 数据与协议

- 训练：ChemVision/full-v0 各 2,250 张；
- validation：两个域各 498 张；
- 基线：v0.9.87 calibrated graph context；
- checkpoint 和删除阈值只用 validation 选择；
- MR-TADF、USPTO 和 locked internal test 均未参与训练或选择；
- 因 validation 未通过门控，本实验没有运行 locked internal test。

## 三组训练

### 完整关系上下文

125,441 参数，class-balanced BCE 加整图内 ranking：

```text
outputs/checkpoints/chemvector-v0988-atom-pair-deletion-veto-4k5/best.pt
```

细粒度 calibration 后：

| 指标 | v0.9.87 | v0.9.88 |
|---|---:|---:|
| presence exact | 710/996 | 711/996 |
| presence+chemical exact | 527/996 | 527/996 |
| false positive | 361 | 306 |
| false negative | 527 | 570 |

模型删除 98 条 base-positive 键，其中 55 条是假键、43 条是真键。边级方向有信号，但误删率
不足以支撑整图部署。

### Precision-first

将 deletion positive weight 固定为 4，ranking 权重降至 0.25，提高误删真键的相对代价：

```text

  chemvector-v0988-atom-pair-deletion-veto-precision-4k5/best.pt
```

validation 选择 0 条删除，全部指标与 v0.9.87 相同。

### Relation-only

删除高维 group feature 和图上下文，只使用 18 个关系特征与 base logit；hidden=32，共 737
参数。deletion positive weight=8，ranking weight=0.25：

```text
outputs/checkpoints/
  chemvector-v0988-atom-pair-deletion-veto-relation-only-4k5/best.pt
```

validation 同样选择 0 条删除，全部指标与 v0.9.87 相同。

## 结构模式审计

双域 validation 的 33,966 条 base-positive 键中有 361 条假键：

| 模式 | 选中 | 真正假键 | 精度 | 假键召回 |
|---|---:|---:|---:|---:|
| 中间第三点 >= 0.5 | 59 | 41 | 69.49% | 11.36% |
| 共线两跳邻居 >= 0.4 | 9 | 8 | 88.89% | 2.22% |
| 共享邻居且无直接墨迹 | 2 | 2 | 100% | 0.55% |
| 共享邻居且独占墨迹低 | 3 | 3 | 100% | 0.83% |

共线两跳规则在 ChemVision 删除 2 条、整图 exact 不变；在 full-v0 删除 7 条，presence exact
`362→363`，chemical exact 保持 276。说明用户指出的错误机制成立，但覆盖面小，而且多数所在
图片还有其他错误；单独修掉一条假键不能恢复整图完全正确。

审计结果：

```text
outputs/audits/chemvector-v0988-deletion-features-exact/summary.json
outputs/calibration/chemvector-v0988-deletion-veto/summary.json
```

## 决策

v0.9.88 NO-GO，不接默认推理和前端。保留关系特征和审计工具，因为它们能准确解释一类错误，
但不再继续扫描 deletion threshold、class weight 或更大的 veto MLP。

下一步应在候选生成和联合图解码阶段同时处理漏键与多键，让模型选择一组能够共同解释整张图
墨迹的 BondObject，而不是在已经确定的 base-positive 集合上逐条做事后删除。

# v0.7.39 部署边界与角色校准

## 问题

v0.7.38 在 498 张 validation 上达到 56.02% 角色严格 vertex exact 和 51.00%
strict skeleton exact。错误审计显示：

```text
Count exact                 310 / 498
Under-count                 125
Over-count                   63
计数错误只差一个顶点        120 / 188
坐标全对但角色错误             4
```

旧 checkpoint 按真实 per-role Count 下的 NMS top-k exact 选模，但部署使用统一
`REAL >= 0.70`。本轮验证训练、选模和部署边界不一致是否是主要瓶颈。

## 零训练角色阈值扫描

对 v0.7.37 的 9 个 Group selector checkpoint 扫描：

```text
Implicit threshold  0.35 - 0.75
Text threshold      0.50 - 0.85
```

最优仍为 45k checkpoint，阈值 `implicit=0.55 / text=0.75`：

```text
Role vertex exact       55.82% -> 57.23%
Role Count exact        58.63% -> 60.44%
F1                      97.87% -> 97.78%
Stress exact            29.03% -> 29.84%
>70 atoms exact         12.50% ->  6.25%
```

未达到预设的 59% vertex exact 和 62% role Count exact，且大分子退化。单纯
per-role 常数阈值判定 NO-GO。

## 绝对边界损失

在候选等价组损失中增加：

```text
每个真值组最高分 >= probability 0.8
最难背景候选分数 <= probability 0.2
hard background top-k = 16
```

checkpoint 改为直接参考部署阈值 exact，不再只按真实 Count top-k exact 选择。

### 最后一层容量

冻结 selector 主体，只训练最终 `residual_score`。固定 100 图的部署 exact 没有超过
初始 62%，判定最后一层容量不足，不扩到 9k。

### 完整 selector 容量

相同 100 图解冻完整 selector：

```text
初始 REAL=0.70 exact      62%
2k 曝光 exact             88%
Candidate Oracle          90%
```

容量门槛通过，随后扩到 8,974 张训练、498 张独立 validation。5k checkpoint 最佳，
继续到 10k/15k 开始回落。

端到端结果：

## 决策

- 独立 Text/Implicit 阈值：有小收益，但零训练方案 NO-GO；
- 最后一层绝对校准：容量 NO-GO；
- 完整 selector + 绝对边界：方向有效；
- 角色 vertex exact 未达到 62%，strict skeleton 未达到 57%：正式门槛未通过；
- 顶点正确条件 edge exact 回退 1.05pp，略超 1pp 护栏；
- `>70` 原子组明显退化；
- 本轮不替换 v0.7.38 shadow，不打 tag；
- 下一步停止继续调阈值和边界权重，改为完整邻接 node-edge 消息传递。

# v0.9.31 Line-Band Bond Semantic A/B

## 观察

`Data/images/test1.png` 和 `Data/images/test2.png` 的左侧原图经过缩放、抗锯齿和截图后，单键、双键
及芳香环内线会形成灰色宽带。右侧预测把局部墨迹拆成额外键、漏键或错误键级。隐式 C 不会在
SDF 渲染图中单独显示，因此漏掉关系边时，正确预测过的顶点也可能在最终图上看起来消失。

USPTO clean 1k 已证明 Vertex/Junction 不是当前主要瓶颈：727 张原子数和键数同时正确的样本中，
724 张纯连接骨架同构，只有 3 张 count-correct 仍错连。因此本实验冻结全部顶点、端点聚合和
Bond selector，只替换最终键级来源。

## A/B

仓库已有 `NodeConditionedBondObject`：对一个端点对采样 `25×64` 二维 line band，一次输出
SINGLE/DOUBLE/TRIPLE/AROMATIC。此前它只为 Bond selector 提供特征，最终键级仍来自 dense cell。

新增实验参数：

```text
--junction-bond-type-source detector|line_band
```

两组都关闭 graph corrector，候选、端点、selector 和 OCR 完全相同。

| 指标 | Dense detector type | Line-band type |
|---|---:|---:|
| SDF valid | 67% | 66% |
| 化学 exact | 18% | 4% |
| 纯骨架 exact | 76% | 76% |
| 原子类型 + 骨架 | 29% | 27% |
| 键级 + 骨架 | 61% | 18% |
| 单键级 micro | 96.15% | 80.02% |
| 完整非立体图 | 25% | 6% |

Line-band 的主要混淆仍是：

- `AROMATIC -> SINGLE`：374；
- `AROMATIC -> DOUBLE`：136；
- 其他键级混淆：29。

现有 line-band reader 正式 NO-GO。它虽然按端点对输出一个对象，但输入仍是窄墨线带，训练目标
仍鼓励从局部线条数量、间距和宽度推断键级，没有获得稳定的关系语义。

## 新 Bond 路线

下一版冻结 Vertex/Junction，将 Bond 拆成三个严格阶段：

1. **Relation existence**：一个无序 Junction pair 最多产生一个关系对象，只判断是否存在键；
2. **Visible bond semantics**：对唯一关系对象读取更宽的二维上下文，分类当前画面表达的是
   SINGLE、DOUBLE、TRIPLE、WEDGE、DASHED 等，不允许输出多个物理线对象；
3. **Chemical ring semantics**：芳香性不再由单条局部线判断。先识别可见单双键，再由完整环上下文
   或确定性环编译器决定 AROMATIC chemical type。

建议的关系输入不是窄 line band，而是规范化的多尺度对象 crop：

- 两个端点固定映射到相同位置；
- 主 crop 覆盖端点外侧和完整键走廊；
- 附加较大 ring/context crop；
- 输入原始 RGB、灰度 ink、两个 endpoint heatmap 和文字 mask；
- 同一 GT bond 的清晰、模糊、缩放、不同线宽图片共享同一个关系标签，并增加一致性损失。

这里的模糊/线宽变化不是让模型学习阈值，而是监督同一个 Bond relation 在像素变化下保持类别不变。

## 决策

- Vertex/Junction：冻结；
- Dense local type：保留为旧基线；
- 现有 NodeConditioned line-band type：NO-GO；
- graph corrector 全量覆盖：停止；
- 下一实验：Semantic Bond Relation v0.1，先做 fixed-pair/GT-count 容量与跨风格门控，再接预测 pair。

# v0.9.42 AtomObject + BondObject 联合协议

> 状态：协议 GO，模型尚未开始训练  
> 数据：ChemVision pilot 现有 WebDataset  
> 外部评测：未使用 USPTO 或 MR-TADF 调参

## 问题判断

v0.9.41 在 USPTO clean 1k 上达到 72.7% skeleton exact，但 atom-typed skeleton
只有 29.3%。旧流水线先预测匿名 Junction，再检测文字框、执行 OCR，最后按几何距离
把文字附着到节点。这不是一个统一学习目标：原子位置、文字区域、化学身份和键端口
分别产生误差，末端规则无法知道哪一个中间结果可信。

因此本轮停止继续扩充 utility teacher，也不继续修补最近邻附着。新目标不是“先找顶点
再找原子”，而是联合预测 AtomObject 与 BondObject。

## 协议设计

AtomObject 同时包含：

- presence、chemical anchor 和 `IMPLICIT/TEXT` role；
- 元素、价态相关字段和手性字段；
- 可选开放字符串、文字中心和 bbox；
- 该原子拥有的全部 incident bond ports。

BondObject 同时包含：

- 两个 AtomObject 引用；
- 两个可见端口；
- 显示键型、化学键型、方向和立体信息。

端口所有权必须双向完全一致。协议不允许模型先输出两组对象，再在末端用最近邻把它们
拼起来。双键、三键仍分别是一个对象，不按墨线数量产生额外顶点。

## 下一实验

先做固定 100 图容量实验，不先扩数据：

1. 共享轻量视觉编码器；
2. AtomObject set head 预测 presence、anchor、role、text bbox/center；
3. BondObject set head 预测 presence、两个 port 和 bond type；
4. incidence head 直接预测每个 bond endpoint 属于哪个 atom query；
5. Hungarian 代价联合包含 atom、bond 和 incidence，禁止事后最近邻附着；
6. OCR 字符串先使用 Oracle 或冻结接口，先验证对象集合与 incidence 能否过拟合 100 图；
7. 100 图通过后扩到 1000 图，再进入 scaffold 独立 validation。

容量门控必须单独报告 AtomObject exact、BondObject exact、incidence exact、纯骨架 exact
和 SDF 往返。USPTO 只在内部协议通过后做公开门控；MR-TADF 继续只作外部诊断。

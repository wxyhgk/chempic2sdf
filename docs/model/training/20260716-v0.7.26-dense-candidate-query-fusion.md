# 2026-07-16 v0.7.26 Dense 候选与 Query 上下文融合

## 目标

v0.7.25 已明显减少多余键，但完整 skeleton exact 仍被顶点集合限制。v0.7.24 的误差
拆分显示，在 MolGrapher validation 1k 的 6px 门槛下：

| 模式 | F1 | Count exact | Vertex exact |
|---|---:|---:|---:|
| set-count + dense snap | 76.61% | 20.0% | 0% |
| 真实数量 + 现有排序 | 77.21% | 100% | 0.1% |
| 坐标 assignment Oracle | 93.62% | 100% | 40.2% |

真实数量只提高 0.60 个百分点，说明继续训练独立计数头不能解决主要问题。最大的缺口
是从候选集合中选错顶点。

## 否决的全 Query 吸附

第一版方案先把全部 128 个 query 与 dense 峰做全局一对一 Hungarian 吸附，再训练
post-snap selector。固定 100 图上 known-count F1 可从 72.05% 提高到 81.75%，说明
head 有学习能力；但独立 MolGrapher 1k 的 assignment Oracle 只有 81.69%，远低于
v0.7.24 的 93.62%。

根因是大量低质量 query 同时参与全局匹配并抢走真实 dense 峰。这条方案判定 NO-GO，
没有扩到 9k。诊断输出位于：

```text
outputs/diagnostics/v0726-all-query-grounding-oracle-validation1k
```

## Candidate-Centric 架构

改用 dense 峰作为不可移动的候选实体，Atom Query 只提供上下文：

```text
shared stroke feature
  -> packed dense head -> 最多 128 个候选峰和精确坐标
  -> Atom Query -> 128 个全局 query 上下文
  -> 每个 dense 峰聚合附近 4 个 query 的上下文
  -> 1 层 candidate transformer
  -> candidate presence logits
  -> Poisson-binomial set count + top-k
```

每个候选的输入包括 dense score、芳香标记、最近 query 距离、局部 query 密度，以及
presence/ranking/local/context 等冻结 query 分数。候选坐标始终来自 dense head，不允许
query 改写。selector 是零初始化残差，初始输出严格等于 dense score logits。

新增参数 522,645。query、dense head、视觉主干、OCR 和 relation 全部冻结。

```bash
.venv-train/bin/python -m chemvector.pretrain_grounded_selector \
  --candidate-centric \
  --query-checkpoint outputs/checkpoints/chemvector-v0724-shared-dense-snap/best.pt \
  --train-shards Data/sdf/molgrapher_synthetic_v0_1/overfit_100/train-000000.tar \
  --validation-shards Data/sdf/molgrapher_synthetic_v0_1/overfit_100/train-000000.tar \
  --output-dir outputs/checkpoints/chemvector-v0726-dense-query-fusion-overfit100 \
  --train-cache-samples 100 --validation-samples 100 \
  --train-samples 10000 --epochs 100 --batch-size 32 \
  --learning-rate 1e-4 --validate-every 1000
```

set-count F1 从 76.97% 提高到最高 92.74%，Count exact 最高 64%，证明候选排序和
计数可以由该 head 学习。

## 决策

- 全 query 全局吸附：NO-GO；
- dense candidate + query context fusion：GO；
- 替换稳定 v0.7.10 推理：暂不执行；
- MR-TADF/USPTO：未参与训练、阈值选择或 checkpoint 选择；
- 下一步：冻结 v0.7.26 顶点，在新候选分布上重训 relation。当前 v0.7.25 relation
  已能得到 5.7% skeleton exact，但仍是为旧 query-selected 顶点训练的分布。

所有边候选继续使用预测顶点的全部无向点对，不使用键长阈值、最近邻限制或长键删除。

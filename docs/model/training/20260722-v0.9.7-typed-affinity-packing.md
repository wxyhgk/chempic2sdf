# v0.9.7 Typed Affinity Packing

> 状态：capacity100 candidate oracle、500-step 训练与 formal evaluator 完成；
> typed-affinity + exact-cover 容量 GO
>
> 目标：删除 root 和 free slots，把 bond group 建模为 proposal 集合的无序分区
>
> 数据边界：capacity100，`internal_test` 封存，MR-TADF 不参与训练或阈值选择

## 第一性原理表示

给定 frozen usable proposals 集合 `P`，目标是找到互不相交且覆盖完整的 groups：

```text
P = G1 union G2 union ... union GK
Gi intersection Gj = empty
```

合法 group 只有：

```text
single_line     1 line
parallel_2      2 lines
parallel_3      3 lines
hashed_wedge    2..N lines
solid_triangle  1 triangle
solid_quad      1 quad
```

模型不再生成 group identity，只预测：

- proposal unary group-type score；
- proposal pair 的对称 typed affinity：`none/p2/p3/hashed`。

triangle 和 quad 由 frozen physical primitive type 直接形成 singleton，不重复学习其成员
数量。所有坐标、端点和 stroke 保持冻结。

## 候选与解码

候选生成不得读取 GT group identity：

- 每条 line 生成 `single_line` singleton；
- 几何宽松门控生成 `parallel_2` pair；
- 从相容邻域生成 `parallel_3` triple；
- hashed 使用相容图、顺序连续子集和 carrier-envelope 拟合生成可变长候选；
- triangle/quad 生成各自 singleton。

随后解 weighted exact cover：

```text
maximize sum(score(candidate) * selected(candidate))

subject to:
  每个 usable proposal 恰好属于一个 candidate
  known-count 模式下 selected candidate 总数等于 GT usable group count
  selected(candidate) in {0, 1}
```

capacity100 阶段允许使用 SciPy HiGHS/MILP 验证表示。若精度成立但 CPU 延迟过高，再把
求解器蒸馏为受约束的 agglomerative decoder。

## 分阶段门控

### 1. Candidate Oracle

用 GT 只给候选打分，不允许 GT 参与候选生成。必须满足：

```text
candidate recall       = 100%
oracle partition exact = 100%
oracle sample exact    = 100%
invalid groups         = 0
```

任一项失败，先修 candidate generator，不启动神经网络训练。

正式 capacity100 结果：

| 层 | candidate recall | GT partition candidate exact |
|---|---:|---:|
| geometry-only | 3376 / 3378 = 99.9408% | 99 / 100 |
| perfect-pair affinity oracle | 3378 / 3378 = 100% | 100 / 100 |

geometry-only 的 p2、p3、single、triangle 和 quad 全部 100% 覆盖；hashed 为
`72/74 = 97.30%`。唯一失败样本是 `000000046` 中两个轨迹交织的 hashed wedge。
perfect-pair oracle 不直接注入 GT group candidate，只注入 GT pair affinity，再经过与部署
路径相同的 affinity-to-candidate generator，因此证明候选生成和 exact-cover 表示完备。

geometry-only 共生成 18,851 个候选，每图 median 57.5、p95 671.6、max 2,428，其中
hashed 候选 12,456 个。不能继续放宽固定几何阈值；下一步应由 learned affinity 解决交织
hashed，并负责候选排序和压缩。

正式产物：

```text
outputs/evaluations/chemvector-v097-typed-candidate-affinity-oracle-capacity100-v2/
  candidate_metrics.json
  samples.jsonl
```

### 2. Geometry-Only Baseline

只使用 frozen geometry、stroke、proposal score 和 flat type，验证 pair/candidate 是否具有
可学习信号。negative 必须使用跨组 hard negatives，不能由全部 O(P^2) 负 pair 主导。

### 3. Typed Affinity 主实验

保持与 v0.9.5/v0.9.6 相同条件：

```text
capacity100
primitive SHA 0678a4bd...041a
768 image
batch 4
500 steps
LR 3e-4
seed 20260721
oracle usable proposal pool
known group count first
```

loss 按真实 group 内平均，再按 `p2/p3/hashed` type 宏平均。hashed 大组不得按 pair 数
平方加权。candidate ranking 使用与 GT group 重叠的高分 hard negatives。

模型只新增 `1,097,573` 个参数。500 step 共看到 2,000 个样本实例，frozen primitive
保持 `eval()`、`requires_grad=false`，checkpoint 不保存其权重。

独立 argmax 分类尚未校准：

| 指标 | Step500 |
|---|---:|
| node type macro accuracy | 75.75% |
| raw pair macro F1 | 33.07% |
| p2 raw F1 | 31.12% |
| p3 raw F1 | 17.19% |
| hashed raw F1 | 50.91% |

错误主要是高召回、低精度。按 class-vs-none margin 做离线 PR 诊断时，最佳 F1 为
p2 `73.50%`、p3 `43.48%`、hashed `79.10%`，证明 p2/hashed 已学到排序，p3 的 39 个
正 pair 仍明显不足。

### 4. Exact-Cover Structured Decode

低阈值 `0.35/0.50/0.65/0.80` 会生成大量重叠 hashed 候选。固定 capacity 校准为
`0.90/0.95` 后，完整 100 图的 proposal partition 结果为：

| 指标 | 结果 |
|---|---:|
| feasible / optimal | 100 / 100 |
| membership group exact | 3249 / 3378 = 96.18% |
| membership partition exact | 78 / 100 |
| single exact recall | 97.54% |
| p2 exact recall | 93.33% |
| p3 exact recall | 100% |
| hashed exact recall | 79.73% |
| triangle / quad | 100% / 100% |

solver latency 为 p50 `1.69 ms`、p95 `15.00 ms`、max `431.38 ms`；candidate union
为 p50 `57.5`、p95 `710.75`、max `2612`。所有 100 图均得到 optimal 解，无 timeout、
无 infeasible。

### 5. Formal Frozen-Geometry 结果

正式 evaluator 使用同一 `0.90/0.95` 配置，把 exact-cover rows 通过 frozen carrier
fitting 展开为 bond-only Visual SVG：

| 指标 | v0.9.6 pointer | v0.9.7 affinity packing |
|---|---:|---:|
| restricted partition exact | 0% | 77.00% |
| membership group F1 | 45.20% | 96.12% |
| pair F1 | 57.52% | 94.37% |
| line recall@8q | 46.40% | 85.37% |
| line recall@32q | 53.47% | 91.43% |
| Bond IoU | 43.20% | 70.17% |
| invalid objects | 1075 | 0 |
| carrier fit failure | 1086 | 0 |

`typed_groups` 指标同时比较 membership、group type 和原始 `member_count`，不是纯类型

primitive 未召回的虚线，因此 hashed 严格 typed exact 只有 `2/74`；其纯 membership
exact 是 `59/74 = 79.73%`。对 SDF 化学结构而言虚线条数不是键身份，但如果继续追求
Visual SVG 完整复现，需要增加独立 hashed total-count 预测。

容量判定：

- standalone pair argmax 未通过 90% 门槛，不能单独部署；
- structured exact-cover 的 group、pair、p2/p3/hashed、sample、r8 和 IoU 均通过门槛；
- 表示和联合解码容量 GO，不再回到 free slot 或 root；
- p3 数据量、pair calibration 和 hashed total-count 作为扩量阶段的独立残差。

## 未见分子上游门控

capacity GO 不等于泛化。当前 frozen primitive checkpoint 本身只在同一 100 图上训练。
将它直接用于独立 pilot validation 的前 100 图：

| 指标 | 结果 |
|---|---:|
| primitive exact | 0% |
| primitive count exact / MAE | 1% / 19.22 |
| line F1 | 0.055% |
| Bond IoU | 7.84% |

因此当前未见分子失败发生在 `raster -> flat primitive proposals`，不能归因于 v0.9.7
grouping。下一步必须先把 primitive-set predictor 正式训练到 pilot 9k train，并只在独立
validation 上选 checkpoint；随后再训练 typed affinity。`internal_test` 继续封存。

生产推理和前端在此阶段继续使用 `v0.7.10`。

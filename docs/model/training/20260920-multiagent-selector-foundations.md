# 三路并行复核：两个方案关卡未通过，先处理基础契约

## 本轮决定

三个agent分别完成稳定配对子集、组级目标的CPU数学原型、上游定位监督契约。
主agent独立重算关键反例并合并回归：**241 passed / 9.87秒**，其中本轮新增93项合成测试。
工程测试通过意味着预期行为和失败反例被正确捕获，**不意味着候选方案通过训练准入**。

本轮结论：稳定配对子集的原匹配非回退关卡未通过；exact-one组级概率目标的梯度契约也未通过。
因此停止原计划的真实保存logit接线，不把任何新目标接入原full loss，不启动第三轮模型试训。
三个agent和主agent都未加载真实模型/checkpoint、未运行真实图片前向、未更新参数、未使用GPU。
只重放原有匹配并对人工CPU tensor求导。

## 1. 匹配判定可以制造“删掉坏点反而退步”

反例是 `C#[13CH]` 的retention-400保存输出。
原selected槽为1、2、3、5；502稳定子集模拟移除1、3，敏感槽5不动，正确槽2也不动。

原匹配先对所有距离做Hungarian，再施加6px门限。
删除前槽2匹配目标1，距离3.812px；删除后它被分给目标0，距离68.866px，
槽5被分给目标1，距离23.599px，两个分配都被门限拒绝。

这是因为两条门外分配的总距离约92.465px，小于
“正确2→1 + 远处5→0”的总距离约97.987px。
但6px内有效关系2→1仍然客观存在。
**正确候选没有消失，是原全局指派改变了验收结果。**

主agent使用保存float32坐标独立构造成本矩阵并调用SciPy指派，复现上述结果。
647个输入SHA、58个逐图输出SHA及502/23分割也独立核对通过。
全部232阶段都没有实际移除正确或空间合格候选；回退出现在重匹配关系上。

这不允许直接把指标改高，也不证明真实模型训练必然产生同样回退。
下一步应先建立独立、诊断用的匹配参照：只把半径内关系视为有效边，允许未匹配，
先最大化有效匹配数再比较距离；始终并列保留原指标。
先验证明确反例及固定58图的差异，不替换生产matcher、不改历史报告或训练标签。

详见 [稳定子集结果与成本矩阵](20260920-selector-stable-subset.md)。

## 2. 一个看似合理的组级目标仍会把整组漏选推得更远

本轮只检查一个数学候选：有效组的“恰好选中一个”Bernoulli负对数概率，
另对明确片段作softplus下压；不按raw正/负区别同组有效替代，不指定winner，不扫系数。

令固定阈值为-0.25，`u = z + 0.25`。组内损失为：

```
L_group = sum(softplus(u)) - logsumexp(u)
dL/dz_i = sigmoid(u_i) - softmax(u)_i
```

主agent补充并独立复现的硬反例：三个有效候选分数为
`[-0.36, -0.35, -0.34]`，全部低于选择阈值；对应直接梯度约为
`[+0.14252, +0.14170, +0.14084]`。
梯度下降会把三者都继续压低，而不是至少救起一个。
这在不同分数下也成立，不只是精确平局驻点。

因此该目标被CPU反例拦截。没有为通过而增加随机破缺、硬winner、额外系数或新配方。
其数学实现保留在诊断工具中，`training_authorized=false`，不被现有训练器调用。
也没有必要再拿真实保存logits做接线，或消耗GPU去证明已经违反的最小契约。

后续重新设计前，要把最低条件写清楚：整组漏选时至少一个有效代表有抬升方向，
重复代表不能靠全体归零处理，敏感/未知项无新监督，且不能从独立logit梯度
直接推断共享模型参数更新后的行为。

详见 [数学契约、API和失败边界](20260920-selector-group-objective-contract.md)。

## 3. 定位缺口需要上游证据，不能继续只调selector

现有offset loss按真实目标所在格索引，错误候选在另一格时，该目标不会直接监督它的offset。
Gaussian邻格在现有focal实现中是减轻权重的负例，不是额外offset正例。
共享卷积参数和其他损失可能产生间接影响，但本轮没有测实际参数梯度，不能承诺恢复。

原10个缺口的目标格都不在保存raw中。解码的实际顺序是：
局部峰筛选 → top-k → 阈值mask。
只有raw坐标和grid ID，无法判定某目标格在其中哪一步被排除。

唯一优先的未来真实观测，是原10节点所属7张旧训练图的一次固定dense快照：
原initial、原参数、每图最多一次，只取heatmap/offset及原decoder判定，
不训练、不运行OCR、不扫阈值或top-k。建议CPU上限120秒；尚未执行该观测。
必须核对是否复现旧候选；若CPU与原GPU候选不同，不把新输出冒充历史失败的原因。

详见 [定位契约与未来观测字段](20260920-selector-localization-contract.md)。

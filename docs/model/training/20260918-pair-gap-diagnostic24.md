# 24 张干净图：端点大多可达，优先定位连键存在性

**固定 17 张新隔离图 + 7 张既有训练控制完成 initial-only CPU 诊断，整图严格身份正确 10/24。** 91 根目标键中 89 根的两端能在筛选后候选中匹配到，但其中漏连 12 根。N–N 单键漏 3/8，N–S 单键漏 8/11；这 19 根 N–N/N–S 单键的端点全部可达。

这支持把下一步重点缩小到现有连键模块，**不支持仅凭这些结果推翻架构、扩展 MoE 或继续联合重训**。本次只是有针对性的诊断，不是独立测试集准确率，也不是比原 170/800 取得提升。

## 连键的错误发生在哪一步

114 个目标原子，raw 匹配 113 个、selected 匹配 111 个；selected 共 113 个，其中 2 个没有对应目标。沿用原 Hungarian 匹配及 **6 px** 半径；匹配失败不自动等于图像中没有找到该原子。

| 每根目标键的互斥状态 | 根数 |
| --- | ---: |
| raw 端点对应关系不足 | 1 |
| raw 可匹配，但 selected 丢失对应关系 | 1 |
| selected 两端可达，但没连键 | 12 |
| 连上了，但局部化学类型不同 | 3 |
| 可达且局部存在性/类型均正确 | 74 |
| 目标总数 | 91 |

另有 **1 条确认误连非边**，以及 **1 条含未知对应端点的预测边**。后者不能当作确认负例；153 对真实非边中 151 对可达，另外 2 对未可达不能计为正确拒绝。

主要观察：

1. **N–N/N–S 主要不是被前级卡住。** 8 根 N–N 单键全部可达，3 根漏连、1 根局部类型不同；11 根 N–S 单键全部可达，8 根漏连。18 根 S=O 则全部可达并局部判对，不能笼统说含硫图都识别不了。
2. **不是单纯降低阈值能解决。** 真 O–O 控制 `OO` 的存在概率为 **0.005118**；`CCS(C)(=O)=O` 两个隔 S 的 O 被误连，概率为 **0.925397**、预测类型 TRIPLE，导致价态错误、最终无效。真实键与假键存在得分倒置，统一阈值不可能同时纠正这两个判定。未做降阈值试验。
3. **三键标签覆盖没有转化成可达监督。** `C#C` 的两个目标碳在 raw 中均可匹配到（候选 2、1），但 selection logits 分别约 -0.830、-0.624，被原 -0.25 阈值丢弃。保留的一个候选又不在原匹配半径内，最终预测 `C`。唯一三键目标因此不可达，现有全 pair 四分类试训的覆盖条件仍不充分。
4. **局部类型错误仍不等于整图错误。** `CN(C)N` 的 N–N 被局部判为 AROMATIC，默认非环芳香处理后最终身份正确；不能把这条局部错误计为可新增挽救的一张图。`N=N` 的相似局部误判最终却得到 `[NH][NH]`，仍为真正失败。保持严格身份评分，不改标签来迎合输出。

## 文字有独立错误链，但没有必要据此重训全部 OCR

71 个可见文字目标中，1 个在原半径下未匹配；其余匹配目标未见文字门误关，也未见隐式碳门误开。12 处字面差异里，9 处是 `H2N↔NH2`、`HN↔NH` 等，未造成已检查基础字段差异；不将字面差异直接当作化学错误。

另外 **3 处 `NH → NHH` 是实际错误**，位于 `CCNN`、`CNNC`、`NNC=O`：

`OCR 输出 NHH → parse_atom_display_text() 拒绝 → apply_atom_ocr() 跳过写回 → 原碳占位保留`

保存 trace 均显示 `parsed=false`，scene 中相应元素为 C，目标为 N。这不是模型明确认出了 C，也不是事后的整图 fallback（本批 fallback=0）。其中 `CNNC` 的候选、键存在性和键型都正确，但因该文字路径得到 `CCNC`，**只训连键不可能解决这张图**。

本轮没有 GT 裁框对照，不能进一步认定 NHH 是裁框问题还是 OCR 本身的问题；未把 NHH 强制改为 NH，也未更换或重训 OCR。基础字段检查只含元素、电荷、同位素和自由基，不等价于氢计数、连接或完整化学身份正确。

## 下一步收敛为最小实验，不启动联合训练

1. **优先准备连键“有/无”的专项验证。** 固定 initial 候选和上游特征，保留所有确认非边，未知端点不伪造负标签。可先考虑只允许现有 `pair.presence` 末层更新、冻结共同特征和 chemical 输出路径的定额可学习性试验；这是后续方案，本轮未实现或执行训练。它是否足以学会这些错误仍需验证，不能承诺改善。
2. **不能直接复用当前全 pair 试训。** `FrozenUpstreamPairStage` 会更新全部 pair 参数，presence 与 chemical 共用中间特征。只冻结 chemical 最后一层并不能保证键型 logits 不变。若要训练整个 pair 模块，必须先解决可达三键控制缺口；不能只凭四种标签都存在就放行。
3. **文字失败单独处理。** 下一项低成本契约检查是“已触发文字识别但解析失败时，如何显式保留不确定性，而不是默默继承 C”。这是错误状态/接口问题，不应通过硬编码 NHH→NH 掩盖，也不应把连键 loss 当成修复文字的工具。

完整数据发布、来源用途和训练预算仍是独立条件，旧训练授权不自动重用。24 图清单仍为诊断清单，不将它当作独立验证集或大规模训练集；本轮到此没有 optimizer 创建/更新或默认行为变更。

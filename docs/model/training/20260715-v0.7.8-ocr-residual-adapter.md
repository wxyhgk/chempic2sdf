# 2026-07-15 v0.7.8 OCR 残差适配器与角色监督

> 状态：接受为当前最佳开发候选  
> 基础 checkpoint：`outputs/checkpoints/chemvector-v076-vertex-pilot-head-lr1e4-9k/best.pt`  
> 最佳 checkpoint：`outputs/checkpoints/chemvector-v078-ocr-adapter-role-1000/best.pt`

## 目标

v0.7.7 证明字体覆盖可以改善公开域 OCR，但整体更新 157 万个 OCR 参数会遗忘
旧分布。v0.7.8 冻结 v0.7.6 的全部既有参数，只在多尺度像素 memory 后增加
零输出初始化的瓶颈残差适配器，并在检测器实际锚点上学习三种视觉角色：

- `implicit_c`：没有文字的真实碳原子顶点；
- `atom_text`：真实原子文字中心；
- `non_molecule_text`：字形笔画或外围文字造成的伪检测峰。

同一真实原子只允许匹配一个预测峰；同一字形上的其他峰全部作为伪顶点监督。
USPTO 和 MR-TADF 均未进入训练或 checkpoint 选择。

## 模型改动

- 残差适配器：`LayerNorm -> 192 -> 48 -> GELU -> 192`，末层零初始化；
- 角色头：attention pooling 后三分类；
- 新增参数 29,044，其中适配器 19,056、角色头 9,988；
- v0.7.6 的所有共有 tensor 逐位不变；
- 角色头默认处于影子模式，只记录和训练，不参与删除顶点。

直接用角色 `argmax` 控制拓扑的 200 张 MR-TADF 消融只有 68.0% 完全一致，主要
错误变成缺原子，因此未启用角色路由。角色头必须先做置信度校准，不能直接作为
硬门控。

## 训练

数据为 `chemvision_layers_v0_2/font_pilot_10k` 的 9,000 张 train 图片。每批同时
使用 oracle 原子中心和 vertex detector 实际预测锚点，后者损失权重为 1.0。

```bash
.venv-train/bin/python -m chemvector.pretrain_ocr \
  --init-checkpoint \
    outputs/checkpoints/chemvector-v076-vertex-pilot-head-lr1e4-9k/best.pt \
  --dataset chemvision-layers --pixel-ocr --pixel-multiscale \
  --train-shards \
    Data/sdf/chemvision_layers_v0_2/font_pilot_10k/shards/train-000000.tar \
    Data/sdf/chemvision_layers_v0_2/font_pilot_10k/shards/train-000001.tar \
    Data/sdf/chemvision_layers_v0_2/font_pilot_10k/shards/train-000002.tar \
  --validation-shards \
    Data/sdf/chemvision_layers_v0_2/font_pilot_10k/shards/validation-000000.tar \
  --output-dir outputs/checkpoints/chemvector-v078-ocr-adapter-role-1000 \
  --steps 1000 --batch-size 4 --workers 2 \
  --ocr-learning-rate 3e-4 --weight-decay 0.01 \
  --validate-every 250 --validation-samples 500 \
  --predicted-anchor-weight 1.0 \
  --residual-adapter --adapter-dim 48 \
  --role-head --role-loss-weight 1.0 --freeze-base-ocr \
  --seed 20260715
```

内部 validation 可见 OCR 从 v0.7.6 的 87.36% 提高到 91.62%，空白准确率为
99.70%。小字体可见 OCR 为 83.40%，仍是下一轮字体数据的主要缺口。

checkpoint 为 v0.7.8 开发候选。

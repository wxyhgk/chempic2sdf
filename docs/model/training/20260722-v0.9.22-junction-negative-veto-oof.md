# v0.9.22 Junction-Negative Veto OOF

> 状态：正式 3-fold OOF 已完成，结论为 `FIT-OOF-PAIR-JUNCTION-VETO-NO-GO`。
> 只用 target group type 强调稀有 junction negatives 会大量误删 positive，路线停止。

## 假设

fit7200 negative pair 的 group-type 分布：

| group type pair | negative count | raw-active count |
| --- | ---: | ---: |
| parallel2 / parallel2 | 49,562 | 7 |
| single / parallel2 | 1,045 | 9 |
| single / single | 956 | 17 |
| single / parallel3 | 367 | 5 |
| parallel3 / parallel3 | 91 | 0 |

v0.9.21 hard 8 集中在 single/single 和 single/parallel3，因此本轮不增加图片，只在 loss 中对
“negative 且至少一端为 single-line group”的 2,368 个 junction negatives 增加 mean 与 worst
margin 项。

group type 只用于训练 loss 选样，绝不进入模型 forward。部署输入仍只有 raster crop、candidate
mask、21D token、global count 和 endpoint incidence。

## 正式评估协议

```text
consensus rescue = min(v0.9.19 corrected, v0.9.20 corrected)
candidate = consensus 中被 v0.9.22 veto 删除后的分数
```

三个模型对当前 OOF fold 都只使用另外两折训练。v0.9.22 每折 2,000 steps，37,313 参数，CUDA
deterministic。

| 指标 | raw | consensus | junction veto |

| pairable exact | 94.58255% | 96.38265% | 96.38265% |

三折 veto 统计：

| fold | consensus cross → candidate | veto positive | veto negative |
| --- | ---: | ---: | ---: |
| 0 | 10 → 9 | 14 | 1 |
| 1 | 5 → 3 | 4 | 3 |

类别强调没有教会模型识别 junction，只让它更愿意删除外观相似的真 stroke。fold 间差异很大，
说明 target group label 不能替代真实 junction 位置证据。本路线 NO-GO，禁止继续增加该 loss 权重。

# v0.7.45 独立 PASS_THROUGH 语义上下文

## 目标

v0.7.44 的 32px 原图 patch 将 3px 线内假点从 152 降到 116，但漏点从 473 增到
512。该结果证明 patch 能看到部分穿越结构，但把线内监督直接作用在 REAL 排序分数上
会让 selector 过度保守。

本轮检验：把 `PASS_THROUGH` 训练成独立视觉语义，再作为图上下文使用，是否能避免
直接压低 REAL 分数造成的漏点。

## 方法

每个候选继续采样 `32×32` 原图墨线 patch，通过四层 CNN 得到局部表示。新增二分类
头，只在两类无歧义候选上训练：

```text
PASS_THROUGH = 距离真实键内部不超过 3px、远离端点和所有真实原子
REAL         = 属于任一真实顶点等价组的候选
IGNORE       = 其他背景、文字/键歧义区域
```

分类器输出的穿越概率先 `detach`，再经过零初始化上下文投影加入节点 hidden。这样：

- PASS_THROUGH 分类器只接受独立辅助损失；
- REAL 集合损失不能反向把分类器训练成“见到墨线就删点”；
- 图模型仍可结合角色、邻边和全局上下文决定是否保留候选；
- 全部 256 候选和 32,640 点对保持不变。

可训练参数为 529,376。候选协议、数据和随机种子与 v0.7.44 容量实验一致。

## 容量结果

固定 validation 前 100 图，训练 5,000 exposures：

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| 最佳 deployed exact | 87% | 88% |
| Count exact | 87% | - |
| F1 | 99.74% | - |
| Candidate Oracle exact | 90% | - |

相对 v0.7.44 的 feature/pixel 两组 90% 容量，本轮低 3pp；相对预注册门槛低 1pp。
固定 100 图只剩 3 张低于 Candidate Oracle，但没有稳定复现已有 88% 容量。

## 决策

- 容量门槛 NO-GO，不进入 2k/10k；
- 独立分类避免了 v0.7.44 的直接 REAL 排序惩罚，但单一 detach 概率上下文表达不足；
- 不扫描辅助损失权重，不通过增加 exposure 绕过容量门槛；
- 代码保留且默认关闭，不替换 v0.7.38 shadow，不打 tag；
- 下一步优先评估候选覆盖协议，因为 v0.7.44 已实测 203 个漏点没有正确角色候选。

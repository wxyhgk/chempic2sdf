# 2026-07-15 v0.7.7 字体扩展 OCR Pilot

> 状态：NO-GO，数据与预处理修复保留，checkpoint 不升级正式版本  
> 基础 checkpoint：`outputs/checkpoints/chemvector-v076-vertex-pilot-head-lr1e4-9k/best.pt`  
> 数据：`Data/sdf/chemvision_layers_v0_2/font_pilot_10k`

## 目标

公开 USPTO clean 图片使用细衬线 ChemDraw 字体，而 v0.7.5 OCR 的 9,000 张训练
图片只覆盖 3 个无衬线字体。该实验保持分子、布局、字号和线宽分布不变，只扩展
训练字体，验证公开域 OCR 错误是否主要来自字体分布差异。

双键、重复顶点和 relation head 本轮不训练，避免同时改变多个变量。

## 数据

- 2,500 个分子，10,000 张图片；
- train 9,000，validation 500，internal test 500；
- train 使用 12 个字体文件，覆盖 sans、serif、bold 和 condensed；
- validation 使用 Rasa、Nimbus Roman；
- internal test 使用 URW Bookman、Ubuntu；
- scaffold 和字体 ID 跨 split 重叠均为 0；
- 80,000 个 tar 成员全部通过验收，`rejected=0`；
- 没有使用任何 USPTO 或 MR-TADF 图片训练。

构建命令：

```bash
cd Data/sdf
.venv/bin/python build_chemvision_layers.py \
  --source webdataset_full_v0 \
  --output chemvision_layers_v0_2/font_pilot_10k \
  --font-profile v077-font-expanded \
  --workers 24
```

## 预处理修复

旧 `prepare_input_image()` 会把同时贴近四边的大型分子连通域误认为页面边框。
USPTO clean 1k 中有 20 张触发，平均删除 75.8% 前景。v0.7.7 要求页面框连通域
同时覆盖至少 50% 的画布边界才删除，贴边化学结构必须保留。

## 训练前基线

| split | 可见标签准确率 | 空白准确率 |
|---|---:|---:|
| validation | 87.36% | 99.45% |
| internal test | 89.83% | 99.70% |

较弱标签包括 `Br/Se/Si/S/I`，validation 上分别为 54.17%、42.86%、50.00%、
68.75%、73.21%。

## 训练协议

- 只训练多尺度 Pixel OCR head；
- vision、vertex、stroke、relation 和 decoder 全部冻结；
- 三尺度 ROI：12/20/32px；
- 字体扩展是唯一训练变量；
- checkpoint 只按两个未见字体 split 的可见标签准确率选择；
- USPTO clean 1k 只在候选确定后运行，不参与 checkpoint 选择。

```bash
.venv-train/bin/python -m chemvector.pretrain_ocr \
  --dataset chemvision-layers --pixel-ocr --pixel-multiscale \
  --visible-jitter-copies 1 --n-jitter-probability 0.05 \
  --init-checkpoint outputs/checkpoints/chemvector-v076-vertex-pilot-head-lr1e4-9k/best.pt \
  --train-shards 'Data/sdf/chemvision_layers_v0_2/font_pilot_10k/shards/train-*.tar' \
  --validation-shards \
    Data/sdf/chemvision_layers_v0_2/font_pilot_10k/shards/validation-000000.tar \
    Data/sdf/chemvision_layers_v0_2/font_pilot_10k/shards/internal_test-000000.tar \
  --steps 1500 --batch-size 4 --workers 4 \
  --validate-every 250 --validation-samples 1000 \
  --ocr-learning-rate 5e-5 --vision-learning-rate 0 \
  --output-dir outputs/checkpoints/chemvector-v077-font-expanded-ocr-1500 \
  --seed 20260715
```

## 结果

### 字体扩展单独训练

训练 1,500 step，内部未见字体最佳点为 1,250 step：

| split | v0.7.6 | 字体扩展 1,250 step |
|---|---:|---:|
| validation 可见标签 | 87.36% | 96.89% |
| internal test 可见标签 | 89.83% | 93.36% |

内部 oracle 原子中心结果显著提高，但外部端到端结果不能同时通过：

| 模型 | MR-TADF 完全一致 | MR-TADF 有效 SDF | USPTO 完全一致 | USPTO 有效 SDF |
|---|---:|---:|---:|---:|
| v0.7.6 + 预处理修复 | 77.55% | 91.91% | 5 / 1000 | 88 / 1000 |
| 字体扩展全量更新 | 71.27% | 89.82% | 8 / 1000 | 90 / 1000 |
| OCR 权重插值 25% | 77.73% | 91.91% | 4 / 1000 | 67 / 1000 |
| 旧/新字体 1:1 混合，750 step | 71.09% | 87.09% | 未运行 | 未运行 |

全量更新证明字体覆盖对 USPTO 有正收益，但整体更新 157 万 OCR 参数造成旧分布
遗忘。25% 插值能保住 MR-TADF，却没有保住 USPTO 收益。旧/新图片混合也不能
解决，因为总体 oracle 标签准确率仍不能约束检测器实际产生的偏移锚点。

`uspto_clean_0002` 是直接证据：修复预处理后，模型从只预测 8 条断边恢复到 19 个
原子、20 条键，拓扑接近真值的 18 个原子、21 条键；但三个 `O` 在检测器实际
锚点上仍被读成隐式 `C`，最终分子式为 `C19H20`。同一 checkpoint 在 oracle
中心的 O 准确率超过 99%，说明剩余问题是字体、锚点偏移和文字角色耦合，而不是
单纯缺少 O 样本。

## 决策

- 接受 `prepare_input_image()` 的页面框修复；
- 保留 `chemvision_layers_v0_2/font_pilot_10k` 作为字体适配数据；
- 否决三个 v0.7.7 checkpoint，不修改 `VERSION=0.7.6`；
- 下一步冻结现有 OCR head，新增零初始化的小型字体残差适配器；
- 新增 `implicit_c / atom_text / non_molecule_text` 视觉角色输出；
- 适配器必须在检测器实际锚点上训练，不能只使用 oracle 原子中心；
- 双键和 relation head 继续保持不变。

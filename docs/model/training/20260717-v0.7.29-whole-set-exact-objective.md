# 2026-07-17 v0.7.29 Whole-Set 整图精确目标

## 目标修正

局部顶点 F1 不是最终目标。平均每张约 23.5 个顶点时，即使单点成功率达到 99%，
整图全部正确的粗略概率也只有约 79%。因此继续只优化逐点 BCE/F1，无法保证
`vertex exact` 和最终 `skeleton exact`。

本轮将训练和门控改为两个整图量：

1. `Candidate Oracle vertex exact`：候选池允许达到的严格上限；
2. `Whole-set margin`：每张图最弱真候选必须高于最强假候选。

```text
L_set = softplus(margin + max(false logits) - min(true logits))
```

真实数量已知时，只要该 margin 满足，top-k 候选集合才可能整图正确。

## 监督口径审计

### 16px 训练与 6px 评测不一致

v0.7.27 Graph 使用 16px Hungarian 匹配生成 node/edge 标签，但最终 vertex exact 使用
6px。一个离真值 7–16px 的候选会被训练成正样本，最终却被评测判错。本轮 structured
node 统一改用 6px 监督。

### `torch.cdist` 与 TF32 相消误差

训练入口启用了：

```python
torch.set_float32_matmul_precision("high")
```

`torch.cdist` 的欧氏距离会走矩阵乘法形式。归一化坐标非常接近时，平方距离中的相消
误差把真实 1–3px 的候选错误计算到 6px 以外。相同候选用最终 Python 欧氏距离评测
时又会匹配成功，导致训练标签和评测不一致。

错误路径曾报告：

```text
Candidate Oracle F1    72.55%
Candidate Oracle exact 14%
```

改为显式坐标差平方求和后：

```text
Candidate Oracle F1    97.38%
Candidate Oracle exact 57%
Oracle matched points  2289 / 2351
```

新增公共 `geometry.stable_pairwise_distances`，并替换 Atom Query、Grounded Selector、
Proposal Keep、Proposal Graph 和 Grounded Graph 中全部坐标监督 `torch.cdist`。

### 阈值匹配优先级

普通 Hungarian 最小化总距离，不保证优先最大化阈值内匹配数量。本轮改为：

```text
第一优先级：最大化 6px 内匹配数
第二优先级：在相同匹配数下最小化距离
```

## 决策

- 逐点平均损失作为主要目标：NO-GO；
- Candidate Oracle exact 作为上游硬门控：GO；
- whole-set weakest-positive / strongest-negative margin：容量 GO；
- 稳定显式欧氏距离：必须用于全部坐标监督；
- 当前候选池 6px Oracle exact 只有 57%，仍是下一上限；
- 本轮仅为固定 100 图容量实验，不替换 v0.7.10 稳定推理。

下一阶段分成两条线：先把 Candidate Oracle exact 从 57% 提高到至少 90%，同时将
whole-set 训练扩到 MolGrapher 9k/1k。只有二者都通过，才重新评估完整 skeleton。

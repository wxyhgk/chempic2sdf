# v0.9.95 Bond Proposal 跨风格残差

## 目标

v0.9.94 证明 AtomPair context 无法修复上游缺失的 Bond proposal。本轮先冻结现有模型，逐层
审计同一分子四种渲染的可表达性，再把 paired-style 监督上移到 Bond detector。

MR-TADF、USPTO 未参与训练和选模。locked internal 仅在 candidate 通过两套 official
validation 后读取。

## 数据与训练协议

- paired style train：250 个 molecule、1,000 张图，每个 molecule 四种渲染；
- replay：ChemVision 500 张、full-v0 500 张；
- 每 epoch：1,000 style + 1,000 replay；
- 3 epoch，总曝光 6,000 张；
- official validation：ChemVision/full-v0 各 498 张；
- style validation：498 张，含 124 个完整四渲染 molecule；
- objective：`dense_bond_object_loss`，使用 Hungarian slot matching；
- vision、Atom、set/incidence 全部冻结。

正式入口：

```bash
.venv-train/bin/python -m chemvector.train_bond_proposal_style_replay
```

## 实验 A：完整 Bond Head 微调

先以 `1e-5` 微调整个 multiscale Bond head。epoch 1 已出现明确破坏，随后提前停止：

| 指标 | Baseline | Epoch 1 |
|---|---:|---:|
| Official ChemVision proposal recall | 98.22% | 98.01% |
| Official ChemVision deployed exact | 211 | 2 |
| Official full-v0 deployed exact | 238 | 5 |
| Style Bond coverage | 78.71% | 78.11% |
| Style representable | 78.11% | 77.51% |
| Style 四渲染全覆盖 | 46 | 43 |

完整微调改变了下游 set head 所依赖的 `object_features`，使旧 selector 失去校准。该现象不是
训练时长不足，继续训练会混淆 proposal 学习与下游特征漂移，因此实验 A 为 NO-GO。

## 实验 B：零初始化 Proposal Residual

保留原 Bond detector 的 object features 和三类键型 logits，只增加 37,391 参数 residual：

- 输入冻结的 `object_features`；
- 输出 heatmap logit 修正；
- 输出最多 16px 的两个端点修正；
- 最后一层权重和偏置全部初始化为 0；
- 初始化输出与原模型逐位一致；
- checkpoint 可由通用 `load_components` 直接重新加载。

## Locked Internal

固定读取两个 internal_test 域各 498 张：

| 域 | Proposal recall | Deployed exact | Full object exact |
|---|---:|---:|---:|
| ChemVision | 98.290% -> 98.307% | 198 -> 200 | 146 -> 146 |
| full-v0 | 98.340% -> 98.360% | 251 -> 244 | 210 -> 208 |

proposal recall 在两个域均微升，但 full-v0 下游出现 7 张 deployed、2 张 full-object 回退。
这说明 proposal 几何变化仍需和 set/incidence 联合重对齐，不能直接替换旧 Bond head。

## 决策

v0.9.95 为组件 GO / 部署 NO-GO：

- 瓶颈审计与零残差 checkpoint 协议 GO；
- paired-style Bond proposal 学习有小幅、跨 official/internal 可复现的 recall 增益；
- 四渲染 mixed 没有下降，crossed-bonds 仍基本未解决；
- locked full-v0 端到端回退，candidate 不接默认前端；
- 默认继续使用 `structure-v0992-carbon`。

下一步不继续单独扩大 residual 数据量。应冻结 candidate proposal residual，重新训练与其几何
分布对齐的 set/incidence 小头，并同时回放原 proposal；选模直接守住两个域的 full object exact。

# 两张失败图的完整错误清单：缺候选、匹配失败、错文字、错连与漏连分别处理

## 结论

本轮只分析上轮两张训练侧案例的保存结果，没有训练、模型推理或修改预测。
新增逐原子、逐目标键清单，覆盖 60 个目标原子、65 条目标键的 initial/50 步状态。

**桥环图主要不是漏连；NH 图同时存在真正缺候选和现有端点之间的漏连。**
这两个案例不足以估计全数据错误比例，但足以说明不能把所有失败都交给连键头，
也不能把“严格匹配不可达”直接理解成“图片里的键没有预测出来”。

这也不是对历史严格计分的修改。

## 1. 如何确保没有错误重建历史匹配

原试训没有保存浮点候选缓存、逐候选 assignment 数组；本轮没有凭 q1023 重新匹配后冒充原始结果。

证据分三层：

1. **局部几何对应**：仅用保存的入选节点坐标和源标注。要求互为唯一最近邻、量化扰动后仍唯一，
   并位于最近其他目标间距的一半以内；否则不强制分配。它只是诊断对应，不是新训练标签。
2. **历史 matched 成员身份**：已恢复的实际采样行全部来自 matched-only 池，所以这些行的端点一定匹配成功。
   两图分别覆盖了 41 / 16 个不同候选，恰好等于缓存回执中的成功匹配数；剩余 P41 / P13 因而确定未匹配。
3. **matched 候选对应的目标身份**：只在考虑量化误差后，6px 内仍只有一个可能目标时推导。
   两图所有已匹配候选都满足；推导出的正键数 45 / 14、每阶段正确键型 ID 列表，均与历史记录完全一致。

精确浮点距离仍不可恢复。训练适配器的真实坐标规则是
`round(source_pixel / 767 * 1023) / 1023`，匹配距离再乘 768；不能拿源像素坐标直接做 6px 裁决。
预测锚点量化的径向误差约 0.531 匹配像素，本轮另保留微小浮点容差。

NH 图有一个很好的反例：T6/P11 和 T12/P13 的保存锚点距离都约 **6.053**，
但历史采样证据证明前者 matched、后者 unmatched。仅用量化后距离重新截断会把前者也错判掉。
同样，上一轮画图用的像素近似距离不是训练 matcher 的精确距离。

## 2. 桥环图：连线基本齐全，元素和额外边才是主要问题

- **T38 / P41**：可见的 `C` 被判为 IMPLICIT，未进入 OCR。适配后量化距离约 8.755，
  计入误差仍超过 6px，历史 P41 确定 unmatched。不能说这个原子“完全没检测到”。
- **T39 / P38**：应为 `C`，保存 OCR 输出和最终节点元素均为 `F`。这是文字接口输出错误；
  尚未区分裁剪框不佳与识别器本身的贡献，也未用化学价态强行改成 C。
- **T30 / P32**：源文字 `HN`、预测 `NH`，N 元素和 1 个 H 的解释一致，不算化学错读。
- **B37、B38**：连接 T34–T38–T39，对应 P15–P41–P38，两条 SINGLE 在 initial 就已存在。
  它们因 P41 unmatched 被排除出严格可达正键，不能算实际漏连。
- **其余 45 条目标键**：initial 和 50 步都存在且原始类型正确，与历史严格计分一致。

额外边为：

| 候选连接 | 对应目标 | initial → 50 步概率 | 证据性质 |
| --- | --- | --- | --- |
| P32–P38 | T30–T39 | 0.9220 → 0.9943 | 历史实际采样负例，旧错连 |
| P15–P18 | T34–T31 | 0.3511 → 0.9501 | 历史实际采样负例，新错连 |
| P18–P41 | T31–T38 | 0.4473 → 0.9596 | 局部几何对应下为非边；历史 unknown，不能变成确认负例 |

真实桥上路径 T34–T38–T39–T31 原来就在，新增的是跨过中间节点的捷径。
这张图的下一步不是“继续补更多真键”，而是区分元素可信度、候选定位和多余连接。
不能按预测 F 的一价规则盲删真实 C 原本的连接来追求 sanitize 成功。

## 3. NH 图：一个真实缺点，另一个只是匹配口径缺口

### 原子与文字

- **T5：腈基 `–C≡N` 的中间 C**，源坐标约 `(415.02, 499.67)`。
  没有稳健对应的入选候选；最近入选节点 P9 在训练匹配坐标系中相距约 67.23，实际对应 T4。
  因而 B4（T4–T5，SINGLE）和 B5（T5–T6，TRIPLE）都没有可用的端点组合。
  这两条不能靠仅输出现有候选之间连线的 pair head 补回。
- **T6 / P11：末端 N** 已存在、文字 N 正确、历史 matched，但因中间 C 缺失而孤立。
  不应把这个孤立 N 删掉，也不能把相隔的 T4 和 T6 直接连起来代替缺失 C。
- **T12 / P13：环上 N** 已存在、N 正确，但历史 unmatched；两条相邻芳香键 B11、B12
  实际都存在且类型正确。这解释另外两条“不可达键”，并非模型漏画了环。
- **T4 的 HN→NH** 是氢文字左右排列变化，不是元素错误。其余已对应节点未发现元素错误。

所以历史“4 条不可达键”实际拆成：**2 条缺端点的真实缺连 + 2 条已经连对但未计入严格匹配的键**。

### 当前端点之间，连键头确实需要修的部分

| 目标键 / 候选对 | 应有键型 | initial → 50 步存在概率 | 原始键型 / 结果 |
| --- | --- | --- | --- |
| B2，T2–T3 / P0–P3 | DOUBLE | 0.0473 → 0.7835 | 两阶段都预测 AROMATIC，且均未达到固定 0.85 存在阈值 |
| B7，T7–T8 / P4–P10 | SINGLE | 0.0088 → 0.9455 | 类型正确，50 步补回 |
| 非边 T7–T14 / P4–P6 | 不应连 | 0.0697 → 0.9633 | 新增错误 SINGLE，已确认实际采样负例 |

B2 不只是阈值问题：即使降低存在阈值，原始分类仍是 AROMATIC，不能据此得到正确双键。
本轮没有改变阈值，也没有把可视化判断送回模型。

### 为什么去掉假边会留下三块

initial 的四个片段按目标身份为：

1. T0、T1、T2、T14–T17：烷基和其连接 N。
2. T8–T13：完整芳香环。
3. T3、T4、T7：中间支架。
4. T6：腈基末端 N。

50 步通过正确 B7 把第 2、3 块连上，又通过假边 P4–P6 错接第 1 块。
删除该假边后的三个片段，就是烷基侧、芳香环及中间支架、孤立末端 N。
连接第一、二块需要正确的 B2；连接末端 N 则必须先补回 T5，再恢复 B4、B5。
这是保存状态的结构解释，不是对 50 次更新内部时间顺序的恢复。

## 4. 后续优先级：按责任定位，不启动新一轮泛化试训

1. **先补上游原因证据**：下一次若获准做小范围模型回放，保存原始候选、筛选前后分数和坐标、

   目前保存结果不足以回答，不能把猜测作为修改 selector 或重新训练 OCR 的理由。
2. **连键修复只针对连键责任**：B2 的 DOUBLE/AROMATIC 错分与漏连、确认假边的抑制。
   任何改动必须同时检查“真边不丢、假边不新增、类型正确”，不能只看平均 BCE 或存在率。
   保留 T12 的两条正确芳香键，不以“历史 unknown”作为删边理由。
3. **拓扑与元素稳定后单独补立体通路**：本轮两个手性中心的标记和相关楔键/E 信息没有保留。
   四类化学键分类正确，并不等于已有立体表达能力；先独立记录，不把所有工作混进一次 pair 训练。

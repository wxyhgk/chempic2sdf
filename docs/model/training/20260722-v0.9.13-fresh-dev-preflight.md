## Formal Loader 门禁

正式 loader 的门禁已经在完整 `fresh_dev/commitment.dev.json` 上闭合。正式 dev 包只有同时
满足以下条件才会被接受：

1. `selection.commitment.json` 精确绑定 selection、replacement、rejected、provenance 和
   identity isolation report；2,000 个 fresh 与 500 个 replacement 的身份、顺序和计数必须
   与这些 artifact 完全一致；
2. 每条 committed identity 的 source SDF 原始字节数与 SHA256、source ChemMol SHA256、
   原子数和键数必须一致，SDF 仍执行 `source-sdf-byte-preserving-0.1`；
3. 最终 molecule/sample/paired manifests、全部 shard 及独立 final validation 必须按精确路径、
   SHA256、sample/member 数量互相绑定；final validation 还必须声明全部 8,000 sample 和
   96,000 members 已检查、结构检查为 8,000、`errors=[]`；
4. preflight validation 必须绑定同一份 selection commitment SHA256，不能拿另一轮 16/64
   报告替代；
5. commitment 和 final validation 必须携带相同的 canonical 字体 inventory，并与固定的两个
   字体文件 SHA256 完全一致；
6. final validation 必须逐项复述 commitment 中冻结的 implementation SHA256；identity
   auditor 与 final isolation auditor 可使用不同实现，但各自的 algorithm/config hash 必须被
   对应 artifact 绑定，共享的 exclusion、style、scaffold 和 source-record hash 必须一致；
7. `validation500`、`old_validation500`、`internaltest`、sealed、reserve、MR-TADF 及其路径
   变体继续在选择设备或加载模型前被拒绝。

这套校验解决的是“正式 fresh 输入能否被证据链唯一确定”，不是模型能力。完整 8,000 图、
最终 manifests、final validation、isolation 和 commitment 已全部通过；formal dev registry
已登记精确 commitment SHA256。

## 执行事件

### selector 字段注入错误

首次正式 selector 在写任何 artifact 前以 `selection_capacity:0:0` 停止。raw candidate 调用
完整 ChemMol/SDF 校验前还没有注入 `source_atom_count/source_bond_count`，导致所有候选在
内存中触发字段缺失。这是实现错误，不是 161,348 个候选全部化学无效。

该次执行：

- 没有生成 selection/replacement/rejected/commitment；
- 没有生成或持久化 PNG、tar、SDF 副本；
- 没有更换 rank、输入、阈值或样本身份；
- 修复后在相同输入上运行，selector 的真实结构拒绝为 0。

### 重复 builder 被拒绝

正式 preflight 首次成功生成后，主线程误重复启动相同 builder。因为输出已经存在且没有传
`--overwrite`，builder 抛出 `FileExistsError`。已有 artifact 未被修改，正式 hash 保持不变。

这两个事件均保留在数据 README 和本记录中，不能用“全程无异常”替代。

### Full Builder 与 Loader 实包事件

旧版 full builder 曾在 selection index 204 遇到瞬态 Cairo `WRITE_ERROR`。失败记录保留为
`candidate_rejected.dev.failed-20260722T133651.csv`；同一身份单独及 205 分子并行重放成功，
最终固定身份没有替换，正式 full build 的 errors 和结构拒绝均为 0。

一次 full build 在性能改造后、最终审计闭环代码落盘前被并行任务提前启动。主线程发现运行
代码与待写入 implementation hash 会发生漂移后发送 SIGINT，清理唯一 staging，未安装任何
正式 artifact；随后以最终 builder SHA256
`edaed2260bc215705db9ab9fb38fe46372d4a102c20379d18c6ab18d94932b87`
重新完成全量构建。builder 现捕获 `BaseException` 清理 staging 后原样抛出。

正式 commitment 首次进入真实 loader 时又暴露两项 fixture 协议错误：layers 的 dataset root
与 meta 的 split-qualified provenance 被误要求字符串相同；ChemMol 重建后的 canonical
SMILES 被误要求逐字相等。两项都只修正验证语义，不修改数据、模型、阈值或 coverage，详细
说明见 v0.9.14。最终 loader SHA256 为
`dd0abc2ab8593458bfd185fc184ad98e3fc31952c8714e54f02bb51655dbc71a`，并已完整遍历
8,000/8,000 样本。

## 判定边界

本轮数据建设可以证明：

- fresh identity commitment 是完整 2,000 身份，不是临时 16 分子抽样；
- 首 16 个 committed 身份可以生成确定性的 12-member、SDF 字节保真数据；
- 身份隔离、source 结构、字体/style、Visual SVG 和 tar/manifest 协议通过独立预检；
- formal loader 已强制绑定 selection/replacement/provenance、source SDF/ChemMol、最终验收、
  字体 inventory 和 implementation hash；
- run8 在 loader 实包修复后仍为 `SMOKE-PASS`，且相对冻结 run6 没有逐样本功能差异；
- 异常重跑不会静默覆盖正式 artifact；
- 完整 full-data isolation、validation 和 commitment 已通过；
- 数据建设过程没有读取或物化 sealed/reserve 逐条身份。

本轮不能证明：

- B+coverage 在 fresh_dev 上优于 B；该问题已由 v0.9.14 独立判定为 NO-GO；
- 图片到 SDF 或完整分子的端到端准确率；
- 可以启动 sealed audit 或 Phase B。

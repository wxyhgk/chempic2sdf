# 2026-07-16 v0.7.14 MolGrapher 9k 顶点扩量

> 状态：dense 局部定位 GO，整图顶点 NO-GO  
> 数据：MolGrapher pilot train 9,000 / validation 1,000  
> 当前最高整图 checkpoint：`outputs/checkpoints/chemvector-v0714-dense-vertex-long-90k/checkpoint-0005000.pt`

## 目标

v0.7.12 和 v0.7.13 已在固定 100 图上分别通过顶点与 relation 过拟合门槛。本轮不再
复用 100 图指标推断泛化，直接在 scaffold 独立的 MolGrapher 9k/1k 上回答三个问题：

1. Atom Query 的集合计数能否扩展到未见分子；
2. dense heatmap 能否在规模训练后承担计数和像素级定位；
3. 如果全局阈值不够，轻量计数校准器能否决定每张图保留多少峰。

relation、OCR 和 MR-TADF 均未参与本轮训练或 checkpoint 选择。

## 数据审计

全量审计输出：

- `outputs/audits/molgrapher-v0713-train-9k/`；
- `outputs/audits/molgrapher-v0713-validation-1k/`。

结果：

- 坐标越界、锚点无墨迹等硬错误：train 0 / validation 0；

系统安装了 Tesseract 4.1.1 进行离线数字审计试验。它没有作为 OCR 教师，也没有进入
模型推理。安装期间系统原有的 `realtek-r8126` DKMS 配置报错，但 Tesseract 本体安装
成功；未修改或清理该系统级 DKMS 状态。

## Atom Query 45k

初始化：v0.7.12 100 图 Atom Query；视觉主干冻结。训练 45,000 次图片曝光，约 5 轮。

固定阈值 `0.5`、6px：

- F1：20.40%；
- Count exact：12.2%；
- Count MAE：2.676；
- Vertex exact：0%。

阈值网格输出：`outputs/evaluations/v0714-atom-query-9k-45k-grid.json`。

按所有 presence 概率之和四舍五入，并取 top-k 后：

- Count exact：17.9%；
- Count MAE：2.197；
- 6px F1：20.59%；
- 16px F1：55.25%。

结论：query 已能学习粗区域，但集合计数没有从 100 图过拟合迁移到 9k 泛化。

## Atom Query 计数消融

### Bernoulli 权重平衡

把非原子权重从 `1.0` 降到 `0.1`，cardinality loss 从 `0.01` 提到 `1.0`，微调 4k。
模型明显过检，Count exact 降到 10.7%，判定 NO-GO。

### 显式计数分类头

新增 0–128 全局计数分类头，增加 25,281 参数：

- 全 query 联合训练 9k：Count exact 11.5%；
- 冻结 query、只训练计数头 20k：最佳 Count exact 14.7%。

训练交叉熵继续下降，但 validation 停在 14%–15%，说明固定 query hidden 的全局平均
特征不足以可靠区分相邻计数。该方案判定 NO-GO，代码保留作实验基础设施。

## Dense vertex 约 44k

只训练 92,548 个 dense vertex head 参数，视觉主干冻结。第一次训练在 16k 时人工
中断，但保存了完整 checkpoint；随后从 16k 继续约 28k，总曝光约 44k。

完整阈值网格：`outputs/evaluations/v0714-dense-vertex-9k-44k-grid.json`。

最佳阈值稳定为 `0.35`：

| 容差 | F1 | Count exact | Vertex exact |
|---:|---:|---:|---:|
| 4px | 87.07% | 20.7% | 4.9% |
| 6px | 89.06% | 20.7% | 5.3% |
| 10px | 90.30% | 20.7% | 5.8% |
| 16px | 90.87% | 20.7% | 6.1% |

dense 已明显优于 Atom Query，证明像素级 heatmap 是当前更有效的规模路线；但
Count MAE 仍为 1.889，整图准确率远未达到接 relation 的门槛。

## 峰值计数校准器

新增 `PeakCountCalibrator`，输入排序后的 128 个局部峰分数和 9 个软阈值计数特征，
不更新 dense 权重。

- 129 类计数分类，9k：Count exact 10.0%；
- 连续 Smooth-L1 回归，9k：最佳 Count exact 19.4%，Count MAE 2.118；
- 两者均未超过固定阈值的 20.7%。

计数校准器判定 NO-GO。结果说明错误不只是每图阈值漂移，dense 峰值本身仍有稳定的
多峰和漏峰。

## Dense 长训

从 44k checkpoint 以 `5e-5` 继续训练，原计划追加 90k；观察到平台后在追加 40k
主动停止。

| 追加曝光 | 6px F1 | Count exact | Vertex exact |
|---:|---:|---:|---:|
| 20k | 89.48% | 19.4% | 6.1% |
| 40k | 89.38% | 20.0% | 6.3% |

20k 到 40k 只增加 0.2 个百分点 vertex exact，且 F1 略降，证明仅增加相同训练曝光
已进入平台。最高整图 exact 位于 `checkpoint-0005000.pt`，不是旧 F1 规则选出的
`best.pt`。训练器已改为按 `vertex exact -> count exact -> F1 -> MAE` 选择 checkpoint。

## 决策

- Atom Query 规模计数：NO-GO；
- 显式 count head：NO-GO；
- 峰值计数分类/回归：NO-GO；
- dense 局部定位：GO；
- 当前整图顶点：NO-GO；
- detected relation 扩量：暂缓。

下一步只做一个受控实验：在 dense head 基础上解冻最后一个 stride-4 视觉 block，
训练参数从 92,548 增至约 171k，并用同一 validation 1k 门控。v0.7.12 的 100 图结果
显示该改动能把 vertex exact 从 87% 提到 90%；现在需要验证它是否能突破 9k 平台。
若仍不能显著提高 Count exact 和整图 exact，再改目标表示，而不是继续增加 epoch。

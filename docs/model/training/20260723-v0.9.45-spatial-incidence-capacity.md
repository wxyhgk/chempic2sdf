# v0.9.45 空间 Atom-Bond Incidence 容量实验

> 状态：GT-associated proposal 容量 GO，预测 proposal 泛化待验证  
> 数据：固定 100 张 ChemVision train 图片  
> 外部数据：未使用 USPTO 或 MR-TADF

## 目标

验证完整空间 AtomObject 与 BondObject 之间的连接关系能否直接学习。每个 BondObject
的两个 endpoint 分别对完整 AtomObject proposal 集合输出一个 incidence 分类分布：

- 不生成匿名 Junction；
- 不使用最近邻文字附着；
- 不使用键长阈值删除候选；
- 双键、三键仍各自只占一个 BondObject；
- incidence 直接表达 `Bond endpoint -> AtomObject`。

本轮是容量实验。GT 只负责将冻结 AtomObject/BondObject 的空间 proposal 与目标对象
一一对齐，并生成 endpoint 指针监督；`SpatialIncidenceHead.forward()` 不读取 GT。

## 实现

- incidence 模型与损失：`chemvector/spatial_incidence.py`；
- proposal 对齐、训练和评测：`chemvector/train_spatial_incidence.py`；
- 单元测试：`tests/chemvector/test_spatial_incidence.py`。

模型输入包括：

- AtomObject feature、anchor、role、文字中心和文字 extent；
- BondObject feature、两个 chemical endpoint、display/chemical 类型概率；
- endpoint 与每个 AtomObject 的相对二维几何。

两个 endpoint 独立分类，但同时共享 BondObject 上下文。若冻结 BondObject 输出的端点顺序
与 GT chemical endpoint 相反，训练数据构建器会同步翻转目标 AtomObject 引用。

## 训练命令

```bash
.venv-train/bin/python -m chemvector.train_spatial_incidence \
  --output-dir outputs/checkpoints/chemvector-v0945-spatial-incidence-capacity100-step1000 \
  --samples 100 \
  --max-steps 1000 \
  --batch-size 4 \
  --validate-every 100 \
  --log-every 20 \
  --learning-rate 3e-4
```

训练前已通过 1-step 真实 checkpoint/WebDataset smoke，以及输出 shape、Atom mask、反向
传播和 endpoint 方向翻转测试。

## 判断

直接 incidence 表示在空间对象已覆盖的条件下可以稳定学习，容量门控正式 GO。结果支持
“AtomObject 与 BondObject 是一等对象，连接由 endpoint 指针表达”，不支持恢复匿名顶点和
最近邻附着。

100% 不是未见图片准确率：训练和容量验证使用同一固定 100 图，且 proposal 由 GT-associated
协议抽取。本实验只排除了“表示或损失本身不可学”，尚未排除预测 proposal 的漏检、重复、
计数错误和跨风格分布偏移。

## 决策

- 完整空间 AtomObject：继续使用；
- 旧空间 BondObject chemical endpoint：继续作为当前冻结输入；
- 学习式 endpoint-to-AtomObject incidence：容量 GO；
- 最近邻文字/原子附着：继续禁止；
- 替换稳定推理：NO-GO；
- 下一步：构建完全不依赖 GT 对齐的 predicted-proposal incidence，先做内部独立验证，再接
  ChemScene v0.2/SDF；USPTO 只作公开门控，MR-TADF 只作外部诊断。

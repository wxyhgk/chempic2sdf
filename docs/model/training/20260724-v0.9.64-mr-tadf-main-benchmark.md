# v0.9.64 MR-TADF 主测试协议

## 决策

从 v0.9.64 开始，MR-TADF v1 作为当前结构路线的主要能力测试集。原来的 locked
internal100 保留为回归护栏，用于检查已有能力是否退化，但不再单独代表模型在目标复杂
分子上的主要表现。

MR-TADF 的 1,100 个分子不进入训练，不参与阈值拟合，也不用于直接构造 hard replay。
训练侧只能使用 ChEMBL、COCONUT、ChemVision 等既有训练域，评测后按失败类型改进通用
结构建模能力。

## 评测对象

本轮评测的是 v0.9.63 joint object 结构解码协议：

- 主 checkpoint：`chemvector-v0962-representable-hard-replay-step1500/best.pt`；
- 主 checkpoint SHA256：`959282581098433d2bddaace12c6169b3cf535ebec6d718a22b25ebe83eaec98`；
- joint MILP 同时选择 AtomObject、BondObject 和 endpoint incidence；
- 主模型失败后依次尝试主模型 independent、旧模型 joint、旧模型 independent；
- Atom 最大容量 128，Bond 最大容量 192；
- 不使用键长上限删除候选键；
- 双键和三键各自仍是一个 BondObject。

本次使用 Oracle 原子化学状态，只评估原子/键对象、端点关联和图编译能力。它不是完整
OCR 端到端准确率，不能把 55.55% 写成当前完整图片识别准确率。

## 交付与验收

结果目录保存了 1,100 张输入图、1,100 份真值 SDF 和渲染、1,100 份预测 SDF 和
渲染。预测 SDF 文件使用 `correct_`、`wrong_`、`invalid_` 前缀；因此正确、错误和无效
样本都可以在前端左右对照。

`scene/` 只有 874 份，因为四条解码路径全部失败时没有合法 ChemScene；这不影响无效
SDF 和诊断渲染的交付。

## 当前结论

新版对象路线在标准布局上已经具备可用信号，但还没有解决极端长键和大型稠密芳香系统。
后续版本以 MR-TADF 三个分桶作为主要报告，任何提升必须同时报告 internal100 回归结果，
避免用专项提升交换基础能力。

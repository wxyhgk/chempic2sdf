# 2026-07-16 v0.7.16 一对一顶点候选筛选

> 状态：proposal keep GO；shadow 分支端到端仍不替换 v0.7.10  
> 数据：MolGrapher pilot train 9,000 / validation 1,000  
> dense 权重：`outputs/checkpoints/chemvector-v0715-dense-unfreeze1-9k-45k/best.pt`  
> keep 权重：`outputs/checkpoints/chemvector-v0716-proposal-keep-9k-24k/best.pt`

## 问题

v0.7.15 证明 dense heatmap 已经能看到绝大多数真实顶点，但 `3×3` NMS 会保留大量
稳定次峰。固定 `19×19` NMS 在同源数据有效，却因绘图尺度变化在 USPTO 增加断图。
因此本轮不再预测全局原子数，也不写死更大的像素半径，而是直接学习每个 dense peak
是否应保留。

## 结构

proposal keep head 使用原 dense detector 的 `3×3` 局部峰作为高召回候选。输入为：

- stride-4 视觉特征；
- dense heatmap 概率；
- subcell offset；
- aromatic 概率。

head 用 dilation `1/4/8` 三个上下文分支输出每个 cell 的 keep logit，共新增 56,673
个参数。dense checkpoint 和视觉主干完全冻结。

训练标签不是独立像素分类。每张图先用 Hungarian 在 proposals 与真实顶点之间做
一对一匹配，16px 内的匹配 proposal 为正；同一真实顶点附近的其他峰以及线段响应峰
都作为困难负样本。这样损失直接优化“一个真实点只留下一个候选”。

候选阈值为 `0.05`，最多 256 个 proposal。validation proposal recall 为 99.78%，
因此筛选前的候选池不是当前召回瓶颈。

## 训练

```bash
.venv-train/bin/python -m chemvector.pretrain_proposal_keep \
  --dense-checkpoint outputs/checkpoints/chemvector-v0715-dense-unfreeze1-9k-45k/best.pt \
  --train-shards 'Data/sdf/molgrapher_synthetic_v0_1/pilot_10k/shards/train-*.tar' \
  --validation-shards Data/sdf/molgrapher_synthetic_v0_1/pilot_10k/shards/validation-000000.tar \
  --output-dir outputs/checkpoints/chemvector-v0716-proposal-keep-9k-24k \
  --train-samples 24000 --epochs 3 --batch-size 8 \
  --learning-rate 3e-4 --weight-decay 0 \
  --matching-radius-pixels 16 --proposal-threshold 0.05
```

最佳 checkpoint 位于 step 2500，约 20,000 次图片曝光。细扫 keep threshold 后，
`0.74` 最佳：

| 解码 | 6px F1 | Count exact | Count MAE | 6px vertex exact | 16px vertex exact |
|---|---:|---:|---:|---:|---:|
| dense `3×3`, t=0.35 | 90.72% | 23.8% | 1.763 | 9.5% | 11.1% |
| 固定 `19×19`, t=0.175 | 88.46% | 38.8% | 3.116 | 23.1% | - |
| proposal keep, t=0.74 | 93.67% | 38.2% | 1.152 | 22.0% | 26.5% |

proposal keep 的 6px exact 略低于同源固定宽 NMS，但 F1 高 5.2 个百分点，Count MAE
显著更低，并且没有使用固定宽抑制窗口。

## USPTO clean 1k 盲测

keep threshold 只在 MolGrapher validation 选择，USPTO 不参与调参。相同 dense 权重、
OCR、relation 与 repair 下，只切换 proposal keep：

| 指标 | dense 基线 | proposal keep |
|---|---:|---:|
| 有效 SDF | 63 | 107 |
| 原子数一致 | 3.0% | 5.9% |
| 键数一致 | 0.8% | 1.8% |
| 化学完全一致 | 2 | 4 |
| 平均指纹相似度 | 0.0111 | 0.0208 |
| 有效预测平均指纹相似度 | 0.175 | 0.194 |
| disconnected | 349 | 435 |
| valence | 580 | 444 |

输出目录：

- `outputs/evaluations/uspto-clean-1k-v0716-dense-baseline/`；
- `outputs/evaluations/uspto-clean-1k-v0716-proposal-keep-t074/`。

有效 SDF 提高 69.8%，原子数一致接近翻倍，证明学习式候选筛选能够跨到官方图片。
断图仍增加，说明 keep head 仍会漏掉部分紧邻或弱响应顶点；下一步应加入绘图尺度增强
和漏点代价，而不是回到固定宽 NMS。

## 决策

- 一对一 proposal keep：GO；
- 固定宽 NMS：继续只作诊断；
- proposal head 默认关闭，通过独立 checkpoint 显式启用；
- v0.7.16 shadow 分支仍不替换稳定 v0.7.10。

原因是 v0.7.10 在 USPTO clean 1k 已有 192 个有效 SDF 和 22 个完全一致，而本轮
shadow 分支即使加入 proposal keep 仍为 107/4。proposal keep 解决了顶点候选质量，
但当前 shadow checkpoint 的 OCR、relation 与 repair 组合尚未恢复稳定基线能力。

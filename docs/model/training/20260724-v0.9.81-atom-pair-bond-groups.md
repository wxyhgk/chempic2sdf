# v0.9.81 AtomPair 语义键组

## 目标

v0.9.76-v0.9.80 已证明：proposal coverage 可以跨风格提升，但当前 set head 把每个 Bond
proposal 当成独立对象，导致候选 cell、数量或 score 分布变化时整套后端失效。新后端将
“同一对预测 AtomObject 之间的多个 Bond proposal”视为一个无序语义组。

## 表示

1. incidence 为每个 Bond proposal 预测两个 AtomObject；
2. 使用无序 AtomPair `(min(a,b), max(a,b))` 作为组键；
3. 对组内 proposal 做对称池化或注意力聚合；
4. 每个 AtomPair 只预测一次：是否存在语义键、display type、chemical type 和方向；
5. 编译器直接消费组级 BondObject，不再先做 proposal-wise keep/drop 后再删除重复边。

双键、三键仍各是一个 BondObject、两个语义端点。不得使用键长阈值删除候选，也不得用
MR-TADF 或 USPTO 参与阈值和 checkpoint 选择。

## 与 v0.9.74 的区别

v0.9.74 只在推理末端对已经独立判定的 proposal 去重，ChemScene 编译器本来就有类似行为，
所以没有收益。v0.9.81 必须在训练目标层面把 AtomPair group 作为一等对象，让 loss 直接
监督“这一对原子是否有一根键”，而不是监督组内每个 proposal 的身份。

## 前置门控

先在 ChemVision、full-v0、MolGrapher 三域审计 incidence AtomPair 分组：

- 组内混入多个真实键的 collision rate；
- 每个真实键是否至少有一个 proposal 落入正确 AtomPair group；
- 组级 oracle exact 与 proposal reduction；
- 若 MolGrapher 分组本身不纯，先修 incidence，不直接训练 group head。

## 前置审计结果

使用 v0.9.79 的 4,500 proposal checkpoint：

| 域 | collision | 候选减少 | 未训练 group deployed exact |
|---|---:|---:|---:|
| ChemVision | 0.20% | 47.46% | 58.23% |
| full-v0 | 0.60% | 44.79% | 68.07% |
| MolGrapher | 0.00% | 43.90% | 4.82% |

分组纯度通过门控，因此进入组级存在性训练。

## 组级存在性结果

模型冻结 proposal 和 incidence，只训练 AtomPair group presence MLP。4,500 总样本为最佳：

| 域 | 4,500 deployed exact | 9,000 deployed exact |
|---|---:|---:|
| ChemVision | 61.85% | 62.05% |
| full-v0 | 66.27% | 68.07% |
| MolGrapher | **10.84%** | 6.43% |

9,000 开始向旧域过拟合，因此停止并保留：

`outputs/checkpoints/chemvector-v0981-atom-pair-bond-group-balanced18k/best.pt`

该结果是 v0.9.76-v0.9.81 中第一个明确跨域 GO：MolGrapher 从 proposal-wise 0% 提升到
组级 10.84%，证明 proposal 身份不变性是正确方向。当前指标只覆盖语义键存在性，还不是
完整分子准确率；下一步必须接入组级键型/方向和真实 ChemScene 解码，再跑 MR-TADF 外部
benchmark，不能把 10.84% 直接宣称为端到端结果。

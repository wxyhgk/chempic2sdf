# 候选保留排查：标签、匹配与损失竞争要分开

这轮不跑模型、不训练，只重放上轮固定 32 张干净图的候选记录。
原始统计完整复现：113 个目标原子，raw 匹配 112、selected 匹配 99；89 根目标键中 74 根可达。

主要结论：

1. **12 个附近候选被全部筛掉的目标，原来对应的候选在现有监督中全是正例。**
   这批记录不支持“正负标签写反了”的解释。
2. **另 1 个是先分配、后截断造成的匹配缺口。**
   单独改变离线匹配契约，可匹配原子从 99 变成 100，但可达键仍为 74；不是模型提升。
3. **发现计数损失与正例保留之间的局部梯度竞争。**
   对保存的 logits 计算原子部分损失导数，112 个正例中 92 个受到净压分作用；
   其中 7 个已在保留阈值 -0.25 与 0 之间。这是下一步应优先验证的训练目标问题，
   还不是完整参数梯度或历史训练退步的因果证明。

默认仍为 initial。原模型、训练损失、阈值、历史 SHA 绑定文件、数据授权状态均未改变。
没有新身份查询，也没有训练发布。

## 1. 重放了什么

输入来自 [上轮固定诊断](20260919-curriculum-v02-identity-and-bond-diagnosis.md)，不选新图、不补换样本。
核对原计划、原报告和 32 份候选文件 SHA，并在执行前后验证原来全部 **453 个输入绑定**；
新审计共绑定 490 个输入。checkpoint 仅校验文件哈希，没有加载模型。

从 JSON 恢复 float32 几何、selector logits、原始候选 mask 和保留 mask，保持原阈值 -0.25、半径 6 px。
调用现有 matcher 重现逐目标覆盖、目标键端点对应、已知/未知 pair 分母。
调用 `associate_predicted_proposals` 的真实原子分支复现 raw/set 标签，与 matcher 逐项一致。

缓存没有 bond proposal、incidence 特征或训练态 dropout。因此原子标签重放使用空的诊断 bond 容器；
不声称复现了完整 bond/incidence/topology 监督。保存的 candidate ID 是候选槽位，不是原始 peak-grid 索引。

## 2. selector 错误不等于标签错误

32 张共有 4,096 个 raw 候选槽位，现有一对一监督标记 112 个正例：

- 正例保留 98 个、丢弃 14 个；负例保留 7 个，共保留 105 个候选。
- 14 个被丢弃正例分布于 11 张图。其中 12 个目标附近不再有任何保留候选。
- 另两个丢弃正例来自 `C=N` 与 `CC(C)=N`，均由附近的另一保留候选成功承接目标。
  这两个替代候选在 raw 一对一监督中是负例，但 selected 重匹配后有正确对应。
- `C#[13CH]` 还丢失了一个本来保留的正确候选的匹配。因此是 **12 + 1 = 13 个目标缺口**，
  不能直接拿“丢弃 14 个 raw 正例”当缺失原子数。
- 7 张图存在最高负例 logit 高于最低正例 logit；另一些图排序没有反转，但正例分数仍低于保留阈值。

13 个目标附近存在多个 raw 候选。一对一监督必然将部分邻近重复候选标为负例，
这是去重约束，不能把所有邻近负标签都改成正标签，否则可能多生成原子。
这里描述的是 initial 的固定 eval 缓存上的监督规则，不是某次历史训练实际产生的标签日志。

`C#C` 是明确的排序/保留失败：距两个目标约 1.55、1.76 px 的候选是正例，
logits 为 -0.624、-0.830，均被丢弃；距最近目标 10.21 px 的负例 logit 为 -0.089，反被保留。
它不是“拿到正确两端以后，把三键判成单键”。

## 3. 匹配缺口：有合法对应，却先分配到远处

`C#[13CH]` 保留候选与目标的距离如下，单位 px：

| 保留候选 | 目标 0 | 目标 1 |
| --- | ---: | ---: |
| candidate 2 | 68.8663 | **3.8118** |
| candidate 5 | 94.1752 | 23.5994 |

现有 Hungarian 先最小化总距离，选择对角线，总和约 92.4657，
小于另一分配的 97.9871；随后按 6 px 剔除，两条对应都不成立。
但允许不匹配的 candidate 5 留空时，candidate 2 → 目标 1 显然在原半径内。

独立离线对照先最大化半径内的一对一匹配数量，再最小化有效距离；没有扩大半径、修改候选或调阈值。
合成测试用小矩阵穷举核对最大匹配数和距离次序，覆盖空集、重复、边界与上述反例。

- raw：仍为 112 个匹配，32 张的 raw 分配均不变。
- selected：只有此图的分配变化，合计 99 → 100 个匹配。
- 可达目标键：**仍为 74/89**，因为该分子的目标 0 对应候选已被 selector 丢弃。

没有把对照结果改写为正式成绩，也没有用新匹配重评分 pair 预测。
原报告中的 6 对未知 pair 与其中 3 条存在预测保持原定义，不变成确认负例。
这与 9 月 15 日已修复的“用 raw 标签代替 selected 重匹配”不同：此次缺口存在于 selected 重匹配自身的分配后截断规则。

## 4. 新线索：计数约束会同时压低正确端点

现有 selector 本来就有 focal 分类、ranking、count 和 incidence 等损失，不能说“缺少排序训练”。
此次只检查以下已有的原子部分：

```text
L_atom_partial = L_focal + 0.5 L_ranking + 0.1 L_count
L_count = SmoothL1(sum(sigmoid(raw_logits)), raw_positive_count)
L_ranking = relu(1 - min(positive_logits) + max(negative_logits))
```

导数针对独立复制的保存分数，不对模型反传、不更新分数或参数。
正导数表示若将该 logit 当独立变量做梯度下降，它会降低；不等于共享网络更新后的实际 logit 变化。

本面板 32 张的 sigmoid 总数均高于 raw 正例数，count 分支因此向所有候选施加压分作用。
focal 在 128 个 active 候选上取均值，正例权重上限为 8；ranking 只对最弱正例和最高负例施加梯度。
因此其他正确端点也可能受到 count 主导的净压分。

- 丢弃的 14 个正例：原子部分净导数全部指向提分，没有发现它们在当前点被该部分损失反向压制。
- 保留的 98 个正例：其中 **92 个**的 count 压分超过 focal 提分，ranking 对这些分数的导数为 0。
- 这 92 个中，有 **7 个分数位于 [-0.25, 0)**；其余多为更高分正例，不能把所有压分都等同于即将丢失。

具体例子是 `C#[13CH]` 的 candidate 2，logit 为 -0.039925：

| 原子部分损失 | 对该 logit 的导数 |
| --- | ---: |
| focal | -0.0196531 |
| 0.5 × ranking | 0 |
| 0.1 × count | +0.0249900 |
| 合计 | **+0.0053370** |

focal 要提高它，count 要降低它，合计在当前点是压分。另一方面，分数最低的另一个正确端点仍被 ranking 明确提分。
这提示需要检查“补回丢失端点的同时，会不会压低已保留端点”，不能只看平均候选数下降或局部 loss 下降。

另用不导入 PyTorch/模型的 NumPy float64 闭式公式独立复核全部保存的相关候选导数，
最大绝对差 **3.221e-8**，小于预设 2e-7 容差。没有做 count 权重搜索或替换正式 loss。

限制：incidence、bond、共享特征、其他任务、训练态、batch 混合和真实参数梯度未包含在这个导数中。
因此本轮证据支持“值得优先验证的损失竞争”，**不支持直接宣布这是历史整分子回归的唯一原因**，
也不证明删除 count 后整图准确率必然提高。

## 5. 下一步：单一小验证，不扩大试训

优先做 selector 损失隔离验证：固定前端候选、OCR、pair 和阈值，比较原目标与一个明确的计数压力隔离原型，
先核对真实 selector 参数梯度，以及对被删正例、已保留正例、重复/背景候选三类的影响。
不同时引入新架构、增大模型、调阈值或更换默认 checkpoint。

匹配契约修正作为独立事项处理；不能用它的匹配数变化替代模型验收。
在错误端点仍大量被删除之前，不以“数据中已有三键标签”为理由直接开大规模 pair 训练。

只有上面的隔离验证支持该改动，再进入数据发布与单次定额 selector 试训；
必须保留旧完整分子回放、未知对应不当负例的约束及无改善停止条件。本轮不授予新训练预算。

# 2026-07-16 v0.7.22 全局 Cardinality Token

> 状态：固定 100 图 GO，scaffold 独立计数 NO-GO  
> 稳定推理：仍为 v0.7.10  
> 外部数据：未使用 MR-TADF 或 USPTO 训练、调参、选 checkpoint

## 目标

在 MolGrapher scaffold 独立 validation 1k 上满足：

- 6px F1 不低于 39.5%；
- Count exact 从 v0.7.21 的 23.9% 提高到至少 30%；
- 达不到则停止继续扩大计数头，判定结构 NO-GO。

## 结构

在原有 128 个 Atom Query 之外增加一个独立全局 token。每层先以 token 为 query
关注 atom query hidden，再关注带二维位置编码的整图视觉 memory，最后输出：

- `0..128` 的 count logits；
- 一个连续 count regression 值；
- 原有 query presence 的 Poisson-binomial 集合计数分布。

全局支路不会改写坐标 query。联合阶段只解冻 presence、最后两层 query decoder 和
decoder norm；坐标、双阶段 refinement、role 与视觉编码器保持冻结。checkpoint 必须
通过 6px F1 `>= 0.395` 的保留门控。

核心实现：

- `chemvector/atom_query.py`；
- `chemvector/pretrain_atom_query.py`；
- `chemvector/evaluate_atom_query.py`；
- `tests/chemvector/test_atom_query.py`。

## Ground-Truth Count Oracle

评测器新增只读 Oracle：直接使用真实原子数选择 presence 最高的 top-k queries，不参与
训练或正式推理。

| 容差 | Count exact | F1 | Vertex exact |
|---|---:|---:|---:|
| 6px | 100% | 40.22% | 0% |
| 16px | 100% | 69.06% | 0.1% |

即使计数完全正确，坐标集合仍几乎没有整图正确。这证明 v0.7.21 将主失败归因于
cardinality 是错误判断：计数错误主要是 query 候选覆盖、presence 排序和坐标偏移的
共同表象。

## 决策

- 显式全局 cardinality token：`NO-GO`；
- 连续计数回归：`NO-GO`；
- token 与 set count 联合训练：未超过旧基线，`NO-GO`；
- 坐标 F1 保留门控：通过，没有破坏 v0.7.21 坐标能力；
- 稳定推理：继续使用 v0.7.10；
- 不打 tag。

下一阶段首先提高 ground-truth-count Oracle 上限，而不是继续优化计数。建议门槛：

- Oracle 6px F1：40.22% -> 至少 60%；
- Oracle 16px vertex exact：0.1% -> 至少 10%；
- 达到后再重新训练 presence/cardinality。

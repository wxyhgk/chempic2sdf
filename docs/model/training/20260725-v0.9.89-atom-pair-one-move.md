# v0.9.89 AtomPair 集合级 One-Move

## 问题

v0.9.88 证明第三顶点、共同邻居和墨迹归属特征可以识别部分假键，但逐条 deletion veto 无法同时
处理漏键，且逐边阈值没有直接优化整图完全一致。v0.9.89 将输出改为每张图只选择一个结构动作：

```text
KEEP
DELETE 一条当前正键
ADD 一条当前负键
SWAP 一条正键和一条负键
```

模型直接在同图动作集合上做 softmax，正确动作必须同时击败 KEEP 和其他候选动作。

## 上限审计

固定 v0.9.87 双域 validation 996 张：

| 项目 | 数量 |
|---|---:|
| AtomPair 候选可完整表达 | 806 |
| v0.9.87 presence exact | 710 |
| 只需一次 DELETE | 37 |
| 只需一次 ADD | 18 |
| 只需一次 SWAP | 10 |
| 需要多次编辑 | 31 |

动作候选不需要全组合搜索：

- 47 个 DELETE/SWAP 假键中，42 个是图内最低分正键，47 个全部位于 bottom-4；
- 28 个 ADD/SWAP 漏键中，22 个位于负候选 top-4，27 个位于 top-16；
- 只有 1 个漏键排在第 61，第一版不为它扩大整个动作空间。

因此每图动作数约为：

```text
1 KEEP + 4 DELETE + 16 ADD + 4×16 SWAP = 85
```

## 模型

动作头共 51,844 个参数：

- 19D edge feature：v0.9.88 的 18D 关系特征加 v0.9.87 base logit；
- 64D edge encoder；
- 独立 KEEP、ADD、DELETE head；
- SWAP head 额外读取共享端点、无向方向对齐、长度比例和 base-logit 差；
- 推理使用 checkpoint 固定的 action-versus-KEEP margin。

不使用元素价态、绝对键长、分子类型、MR-TADF 或 USPTO 标签。

## 推理接入

正式入口新增：

```text
--atom-pair-one-move-checkpoint
```

前端 profile：`structure-v0989-carbon`，运行时注册表实时加载，无需重启。v0.9.87 保留为可选
回退。默认继续关闭 v0.9.84/85 长键 rescue。

同时修复旧推理 fallback：所有高优先级 AtomPair 尝试都因占位化学失败时，carbon fallback
现在保留第一个高优先级 scene，不再使用最后一个低优先级 base scene。

GD906 smoke 可生成有效 SDF，one-move 选择 KEEP。`test1.png` 选择 DELETE `(121,124)`，但碳
占位后仍存在 atom #39 五价，因此没有有效 SDF；这说明结构动作提升不能替代 OCR/原子化学状态。

## 决策

v0.9.89 GO，替换 v0.9.87 作为当前普通结构默认 profile。下一步优先研究 multi-move/迭代动作，
但必须继续以双域 chemical exact 和 locked internal test 为门控，不能只看局部边准确率。

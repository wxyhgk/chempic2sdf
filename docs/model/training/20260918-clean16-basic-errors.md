# 干净小图的基础错误：候选保留、连键判别、带电文字

完成一次固定 16 图的 initial CPU 回放：**18.539 秒，16/16 与历史预测一致，严格正确仍为 8/16，有效 SDF 14/16**。没有训练、阈值扫描、自动重试或部署。此处是既有课程开发验证切片，不是新的独立测试成绩。

这次定位的是 **initial 本身在干净小图上的错误**，不是 initial→last 的退步原因；不推翻此前固定上游/筛选器交叉诊断的结论。原完整开发基线仍为 170/800。

## 固定范围和方法

- 选择规则：已发布清单中全部 `curriculum / validation / reference`，共 16 个分子；包含原本正确的 8 张，不按新预测换图。
- 每图 2–7 个重原子、无指定立体信息；原始 RGB 768×768、白底黑线、24 px 字号、2 px 线宽、约 72 px 实测键长。模型使用原图，不先裁掉大块留白或放大。
- 只加载原 initial 和冻结 OCR；原 atom 筛选阈值 −0.25、pair 阈值 0.85、role 阈值 0.85 不变。
- 16 次原始结构前向，保存全部 raw/selected 候选、筛选分数、配对连键概率、文字 gate、裁框、OCR 原文、失败前 scene 和编译错误。
- 预测完成后才做几何匹配和真值评分。单独将 25 个可见文字的同源标注 ink bbox，按现有 `crop_tensor` 的 4 px context 和 192×48 预处理送给同一个 OCR。没有 margin 扫描、挑选最佳 OCR 或把识别结果写回原预测；这个对照不产生新的 SDF 正确数。

## 八张错误的逐图定位

下表是本组的主要失效环节划分，不宣称只修这一处一定能恢复整图，也不是总体责任比例。

| 目标 | 原预测 | 主要观测 |
| --- | --- | --- |
| `C=CC` | `CC` | 双键端点原子已在 raw 中，但被筛选删除 |
| `C=CC(=O)O` | `CC(=O)O` | 同样删除末端烯碳；另有可被现有编译处理的局部键型差异 |
| `NN` | `[NH2].[NH2]` | 两个原子、文字都在，N–N 连键被拒绝 |
| `CNS(C)(=O)=O` | 无效 | 漏 C–N，另外错误增加 O≡O，造成氧价态超限 |
| `CN(C)S(C)(=O)=O` | `CNC.C[SH](=O)=O` | 原子与 OCR 正常，漏 N–S 后断成两段 |
| `C[S-]` | `CS` | 结构连键正确，OCR 丢负号 |
| `C[NH3+]` | `C[NH]` | 结构连键正确，OCR 丢电荷并误读氢数 |
| `C[N+](=O)[O-]` | 无效 | N–O 漏连，同时 N+、O− 电荷识别失败 |

互斥分组为：候选筛选 2 张、连键 3 张、带电文字 2 张、连键与文字混合 1 张。若按受影响模块计数，则连键 4 张、文字 3 张，有 1 张重叠，不能直接相加。

### 1. 两处不是“没有找到原子”，而是找到了又删除

| 目标 | 原子 / raw candidate | 距目标 anchor | proposal 分数 | 筛选 logit | 阈值 |
| --- | --- | ---: | ---: | ---: | ---: |
| `C=CC` | atom 0 / candidate 1 | 0.440 px | 0.623 | −0.691 | −0.25 |
| `C=CC(=O)O` | atom 0 / candidate 3 | 1.940 px | 0.440 | −0.310 | −0.25 |

两图 raw 均匹配全部目标原子，selected 各少一个末端烯碳，对应双键随后不可达。这给出明确的候选保留问题，不能要求 pair 去连接一个已经被筛掉的端点。

它没有证明单纯放松筛选阈值安全，也没有区分筛选头权重、上游特征和训练分布各自的贡献。本轮没有强行保留 GT 对应候选或回放“补入原子后的准确率”。

### 2. 连键头对真边和假边的排序存在基础错误

- `NN`：两个目标候选完整保留，OCR 都读出 `NH2`（左侧实际显示串为 `H2N`，不是元素识错）。真实 N–N 的存在概率只有 **0.0701**，阈值为 0.85；其条件键型预测是 SINGLE。
- `CN(C)S(C)(=O)=O`：真实 N–S 存在概率只有 **0.0155**，条件键型同样是 SINGLE。原预测中多出来的隐式 H 与断连后编译有关，不能把这个结果称为 OCR 先把 N/S 认错。
- `CNS(C)(=O)=O`：真实 C–N 概率 **0.8172** 被拒绝；不存在的 O–O 概率 **0.9154** 被接受且判为 TRIPLE。两根真实 S=O 都被保留，概率分别为 0.9929、0.9972，条件键型正确。因此氧同时接上额外三键，出现显式价态 5 的错误。

最后一例直接排除了“只调统一 pair 阈值就能同时解决这两条边”：接纳真实 C–N 需要阈值 ≤0.8172，拒绝错误 O–O 却需要阈值 >0.9154，两个条件无法同时满足。

其图上 O–S–O 近乎共线，S 位于 O–O 连线中点。错误连边跨过了中间原子，是后续干净训练图需要覆盖的“看起来有线但端点不直接相邻”的具体难负例。但仅此见证不能证明模型内部把两根 S=O 当成一根长键，更不授权现在加几何硬规则。

### 3. 带电文字：不只是框没框全，也不能认为标注框一定更好

| 图 / 文字 | 模型框 + 冻结 OCR | 标注框 + 同一个 OCR | 可支持的解释 |
| --- | --- | --- | --- |
| `C[S-]` / `S-` | `S` | `S` | 标注框对照仍丢负号 |
| `C[NH3+]` / `NH3+` | `NH` | `NH2` | 裁框改变输出，但电荷及 H 数仍错 |
| 硝基 / `N+` | `NH` | `N+` | 有明确的裁片输入敏感性 |
| 硝基 / `O-` | `O` | `O` | 标注框对照仍丢负号 |
| 正确控制 `CS` / `SH` | `SH` | `SiH` | 标注框反而引入元素错误 |
| 正确控制 `CCS` / `SH` | `SH` | `SiH` | 同样发生反向退步 |

人工查看保存的标准化裁片，`S-`、`NH3+`、`O-` 中的电荷字形仍可见。说明 **冻结 OCR 加当前裁片预处理，在这些字符布局上并不可靠**；不能全归于 bbox 漏包字符，也不能宣称换成更高 IoU 的框一定能改善识别。

25 个 reference crop 中包括一个几何未匹配的正确 O。严格按现有匹配能配对比较的是 24 个文字目标；本轮不把未匹配项从模型最终结果中删掉，也不把前后不同覆盖分母的字符串计数当作 OCR 准确率改善。上表只是固定条件对照，没有进行新的整图修复。

## 正确控制揭示的评分限制

总计 53 个目标原子、37 根目标键。原 6 px 规则下 raw 匹配 52、selected 匹配 50，selected 总数 51，可达正键 34。**这些局部计数不等于真实图中丢失了 3 个原子或 3 根键。**

具体控制：`CC=O` 最终 SDF 完全正确，实际 selected candidate 2 的 OCR 也为 O，但它距目标 anchor **7.090 px**，超过固定 6 px，局部匹配将其记为未匹配，其 C=O 边也成为 unknown correspondence。不能把这张图归入“原子没检出”或“OCR 没执行”。本轮没有为它放宽匹配半径。

50 个几何匹配原子的 role 开关均与可见文字标记相符；这批错误没有发现文字入口开关本身错的见证。上述未匹配 O 则单列保留，不靠事后对应抬高覆盖率。

## 下一步优先级

**干净图排查已经把重点从立体输出转回了基础候选保留和连接判别。** 这 16 张都没有指定立体信息，当前立体输出缺口不是这八个错误的解释。

1. 先准备训练侧的干净连键单组件验收：真 N–N/N–S、跨中间节点的假连边以及正确控制。冻结上游和文字接口，只能用不同的训练身份；本轮 16 张仍是验证图，不拿去训练以“过关”。本次证据支持提出 pair 的具体学习目标，但不证明某个优化配方会有效，也不自动开 GPU。
2. 末端双键碳的候选保留单独处理，不与 pair/OCR 同时联动更新；保留候选误检控制，不能只追召回或直接调阈值。
3. OCR 支路围绕电荷、上下标和 H 排布做受限对照，优先检查已有识别器/预处理的适配；不能拿 bbox IoU 当文字正确率，也不默认自己重训 OCR。

这不是再次换架构的证据，不启动 MoE 或更大模型试错。此轮只把具体失效环节定位清楚；训练数据分布、损失和优化为何产生这些分数，尚未得到因果证明。

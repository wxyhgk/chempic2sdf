# 键头定额试训：协议准备与已有入口复用

本轮完成**试训草案、监督入口等价核对、冻结配置和验收规则的合成测试**。
尚未实现专用缓存/训练启动器，也没有创建优化器、加载真实模型或开 GPU。
这是对上一轮“准备试训协议”的落实，不是新的训练执行授权。

## 1. 不再增加一套键头监督实现

现有 `FrozenUpstreamPairStage` 已经使用 `pair_targets_with_unknown()` 和
`select_known_pair_rows()`，对未匹配端点不做负监督。新加入的
`pair_trial_contract.py` 复用这个入口，显式设为全模型 eval，仅 pair 开启梯度；
eval 不会禁止 autograd。旧 stage、默认 continuation、旧 launcher 和历史报告均未修改。

在固定58训练/回放图的**保存候选与原 selected matching**上，逐张固定相同随机种子，
比较已有 stage 的监督契约与 `matched-only-v1` 的掩码及采样行号：

| 项目 | 核对结果 |
| --- | ---: |
| 掩码一致、采样行号一致 | 58 / 58 |
| 原有正例 / 本次保留正例 | 1103 / 1103 |
| 采样确认负例 | 6244 |
| 暂不监督的未知 pair 池 | 626 |
| 实际采样未知 pair | 0 |
| 空监督分支 | 4 张 |
| 全部目标键 / 严格匹配可达目标键 | 1150 / 1103 |
| 严格匹配下仍不可达目标键 | 47 |

这47条没有正监督的目标键不会因屏蔽负例自动得到正监督，也不能直接理解成47条
最终分子图漏键；之前已有最终 SDF 正确、严格6px匹配却不完整的例子。
原来诊断归属仍有疑问的3条正例、54条负例也没有在此重新标注。

本轮是旧候选上的 CPU 等价核对，不是重新执行58张真实模型前向。
上一轮真实 initial 的四图 CPU 新旧入口比较仍是4/4通过；与历史 GPU 的严格
候选复现只有2/4通过，不能把二者混成一个“全部复现”结论。

## 2. 唯一拟定试训，不扩大架构或数据

- 同一 initial，固定58张训练/回放图；不读取64张开发图或封存测试逐图文件。
- 只更新现有完整 pair head，视觉、原子、键候选、selector、文字角色、bbox、OCR均冻结。
  它不只更新最后一层 presence readout，也不引入 MoE 或新的模型。
- 全模型 eval、FP32、关闭 autocast/TF32；6px匹配、原有阈值、候选上限全部不变。
- 原 `direct_atom_pair_loss`，只监督 `matched-only-v1`；负采样比例6、最少48。
- AdamW，LR `2e-5`，weight decay 0，clip 1，batch 1，seed `20260921`。
  学习率沿用原 continuation 的 pair 参数组，不进行搜索。
- **拟定单卡最多600秒、200次更新**，先到即停；时间含缓存、初始评估、中途检查和保存。
- 固定原清单顺序，最多4遍、232次 batch 尝试；空分支不消耗 optimizer step，
  但照计时间和完整图分母。无正例但有确认负例的图仍可监督，不能误判为空分支。
- 0/50/100/200步检查；不自动续训、换设备、重试或部署。initial继续作为默认模型。

这仅是训练侧可学性小试，不能产生独立准确率结论；一组“新监督+仅键头更新”的试训
也不能单独证明收益来自掩码，而非改变了更新范围。

## 3. 节省计算，同时不冻结正在学习的内容

将来在实际执行设备上，先从 initial 为58张图各生成一次冻结上游缓存，并用
**当次候选**重新匹配、构造全 pair 标签；不把历史槽位标签拼到新候选上。

缓存冻结视觉图、raw/selected候选及上下文、匹配、pair索引、标签、known mask。
同时绑定初始权重、输入、实现、配置、设备、数值环境以及张量哈希。
缓存可无损转存CPU，再送回同一执行设备；设备变更则中止，不自动迁移运行。

**不能缓存并复用 pair head 的 hidden 或 ribbon encoder 输出来训练完整 pair head**：
这部分权重本身要更新。每步仍执行键头自身编码，只省掉冻结的上游前向。
此前 presence-readout-only 实验的 hidden 缓存不适用于这份完整键头配方。

GT只用于损失与评分，不进入候选、文字预测或分子编译接口。未来保存独立 pair delta，
绑定 initial、协议、新授权与缓存，并明确记录监督策略；不覆盖旧 bundle 或伪称
旧 checkpoint 已含此策略。

## 4. 验收已写成可测试的规则

`checkpoint_decision()` 对比固定完整样本集合，不使用训练损失，也不只看采样负例：

1. 任一原有正确且类型正确的可达键丢失、原有正确/有效SDF丢失、新增fallback，
   或任一图的确认假边数增加，立即停止。不能用别处改善抵消退步。
2. 候选/标签/文字签名、可达键和全部目标键分母必须不变；异常则拒绝判分。
3. 到100步，正确类型的可达键数或严格SDF正确数没有增加，停止；有改善也不得越过200步。
4. 未知 pair 的预测数单独报告，不擅自视作假边；完整SDF评分仍包含端点不可达、
   编译失败等问题。空监督图不能从检查集合删除。

这里的局部键型指标是原始匹配/化学标签下的正确键，并不替代编译后的键语义与整图身份；
严格SDF作为单独保护条件。上述函数目前是纯规则检查，未来启动器仍须生成全58图指标，
校验指标来源，并把早停规则真正接入运行循环。

## 5. 距离开跑还差什么

准备报告明确 `safe_to_launch=false`：

- 原准入 `use=local_selector_retention_fit_only`，新用途为 `local_pair_only_matched_fit58`。
  需要针对同一固定58图记录用途扩展，不能改旧准入、重用旧试训许可，也无需因此重新查询身份。
- 还需专用预算启动器：新单次授权检查、冻结缓存、完整图检查、优化器、硬时间上限和结果记录。
- 新执行许可尚未签入；仅同意准备方案不等于批准新的GPU调用。
- 新执行设备缓存及其 initial 基线尚未生成。它们应在获准调用的总预算内、第一次更新之前完成。

下一实现步骤是**接缓存和预算启动器，先做合成无真实训练验证**；最终方案和实现绑定后，
再确认本次数据用途及单次预算执行。未检查GPU可用性，也没有据此声称CUDA存在问题。

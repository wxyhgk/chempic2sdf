## 为什么从物理图元改为 Bond Group

Visual SVG v0.1 把双键拆成 2 条独立 line、三键拆成 3 条独立 line、虚楔键拆成最多
31 条独立短线。primitive-set 模型必须在整张图上分别找齐所有物理线，再依靠下游逻辑
恢复它们的归属。这个目标对双键和虚楔键存在不必要的组合难度。

Visual SVG v0.2 保留精确物理 members，但把一个完整可见键符号作为外层集合对象：

```text
single_line / parallel_2 / parallel_3 / hashed_wedge
solid_triangle / solid_quad / text_box
```

这里的 `parallel_2` 只表示两条线属于同一个可见符号，不等于化学双键结论。模型仍然只
恢复图片，没有读取键级、原子、价态或 SDF。

## 数据目标

默认容量：

```text
object queries = 192
max_members   = 32
```

每张图的 target 是一组无序对象。每个对象包含：

- `type`：六种 bond group 或 `text_box`；
- `member_count`：当前 group 的实际物理成员数，文字框为 0；
- `member_geometry[max_members, 8]`：每个 member 的完整点坐标；
- `member_stroke[max_members]`：每个 member 的线宽；
- `text_geometry[4]`：文字框的中心、宽和高；
- `target_mask/member_mask/geometry_mask`：严格区分 padding 与真实目标。

坐标按 `q2047` 归一化，线宽按 `1..63` 归一化。collator 直接调用
`visual_primitives_v0_1_to_visual_svg_v0_2()`，因此 capacity100 原 tar 不需要重写。

capacity100 的虚楔键最多 31 条 member，所以 P1 使用 32。该数字没有写死在模型头和
损失里：成员头按共享 MLP 逐槽预测，配置、target、Hungarian cost、loss 和 decode 都能
实例化为 143。测试已经实际构造并编码 143-member hashed wedge。任何 group 超过当前
`max_members` 都会硬失败，并明确报告 `targets are never truncated`，不会静默丢线。

## 模型结构

入口为：

```text
chemvector/bond_group_set.py
chemvector/bond_group_set_data.py
chemvector/train_bond_group_set.py
chemvector/evaluate_bond_group_set.py
```

模型复用当前 primitive-set 的：

- `ChemVisionEncoder`；
- raw-ink memory；
- 固定 reference query 网格；
- Transformer decoder；
- query-aligned local feature；
- stride-4 endpoint local refinement。

默认 `local_query_kernel=5`、`endpoint_refine_kernel=25`。外层 192 个 query 预测对象类型，
每个 query 与可学习 member embedding 组合后，通过共享头输出最多 32 个 member。这样将
来把容量改成 143 时不需要把最后一层改成一个巨大的固定 143 倍输出矩阵。

独立总对象 count head 输出 `0..192`。每个对象另有 member count head，输出
`0..max_members`。两者不能互相替代：前者确定整张图保留多少个 group/text object，后者
确定一个 hashed wedge 应展开多少条物理线。

## 匹配与损失

外层对象使用 Hungarian 一对一匹配，cost 包含：

```text
对象类型 + 精确 member 几何 + member 数量 + member 线宽
```

外层对象顺序完全无关。group 内 member 使用 Visual SVG v0.2 的 canonical 空间顺序。
线端点正反方向等价；triangle/quad 的循环起点和正反方向等价。线 member 继续使用
endpoint、center、length、orientation 对齐目标，避免普通坐标 L1 对长线方向不敏感。

训练 loss 包含：

```text
object classification
member count classification
member coordinate + line endpoint geometry
member stroke width
text bbox geometry
soft cardinality
independent total-count classification
```

decode 同时支持 threshold 和 count-head top-k，并保留模型预测的原始 member count，便于
capacity 取证，不在 decode 阶段把错误数量偷偷修成类型规定值。

## 恢复训练与写盘

`--resume-checkpoint` 严格检查 checkpoint schema、Visual SVG v0.2、模型类型、固定视觉
源 SHA、模型结构、image size 和封存标志。恢复时：

- checkpoint 的 `global_step/samples_seen` 会延续；
- `--max-steps` 表示最终 global step，不是再训练多少步；
- optimizer 固定重新创建，不加载旧 optimizer state；
- checkpoint SHA、来源 step 与 samples 写入 `resume_lineage`；
- 架构或 image size 不一致会直接失败。

checkpoint 先写同目录 `.tmp`，完整落盘后使用 `os.replace()` 原子替换目标路径。中断不会
暴露半写入的 `.pt`。validation 对相同 target 同时计算真实图和纯白图 loss，固定报告
`white_image_loss` 与 `white_image_loss_ratio`。

续训示例：

```bash
python -m chemvector.train_bond_group_set \
  --resume-checkpoint outputs/checkpoints/chemvector-v093-bond-group-set-capacity100-stage1-1000/step-001000.pt \
  --output-dir outputs/checkpoints/chemvector-v093-bond-group-set-capacity100-stage2-3000 \
  --max-steps 3000
```

## Capacity Evaluator

`evaluate_bond_group_set.py` 默认同时运行 threshold 与 count-head decode。指标分三层：

1. v0.2 对象层：总对象 count、每种 group/text 的 count、tolerance group F1、严格 group
   object exact、完整 group-set exact、member-count exact；
2. member 几何层：全图与 group-first 两套 line member `recall@1/2/4/8/16/32/64/128q`，
   endpoint/center/length/angle 的 p50、p90 和 max；
3. flatten v0.1 层：line/triangle/quad/text 与 polygon F1、严格物理图元 exact、Bond IoU。

错误 cardinality、hashed 少于 2 条、退化图元、NaN/Inf、协议序列化错误与 overflow 都计为
invalid。invalid 对象仍进入预测 count 和 precision 分母。Bond IoU 只能验证 flatten 后的
像素，不能证明 group partition 正确，因此不能替代前两层指标。

可选 `--compare-white` 会增加纯白图 loss ratio、type/count argmax 一致率，以及 member/text
坐标变化分布。

```bash
python -m chemvector.evaluate_bond_group_set \
  --checkpoint outputs/checkpoints/.../step-003000.pt \
  --shard Data/sdf/visual_svg_v0_1/capacity_100/shards/capacity-000000.tar \
  --output-dir outputs/evaluations/... \
  --threshold 0.5 \
  --compare-white
```

## 封存边界

训练入口在展开 shard 路径时拒绝任何包含 `internal_test` 的路径。collator 还会检查
`key` 和完整 sample metadata；即使调用者绕过路径检查，把封存样本混进普通 tar，也会
在构造 target 前失败。

## Capacity100 正式结果

所有结果都来自同一份 100 张 train-only capacity shard。主口径使用 count-head 解码和
group-first member matching；threshold 会通过多预测对象抬高 recall，只作为辅助。这里的
实验只判断表示和优化容量，不能证明未见分子泛化。

| 实验 | group r@8q | group r@32q | endpoint p50 / p90 | Bond IoU | invalid |
|---|---:|---:|---:|---:|---:|
| cold 1k | 0.02% | 5.72% | 83.60 / 235.88q | 7.55% | 0 |
| flat warm 1k | 0.13% | 13.98% | 66.41 / 246.76q | 9.32% | 7 |
| cold 6k | 1.56% | 38.21% | 37.00 / 152.99q | 13.75% | 5 |
| cold 6k -> full 7k | 2.95% | 49.46% | 30.27 / 117.20q | 15.42% | 4 |
| cold 6k -> refiner-only 7k | 7.35% | 55.42% | 24.04 / 125.67q | 17.32% | 3 |
| full 7k -> refiner-only 8k | **9.50%** | **60.97%** | **22.83 / 95.88q** | **18.32%** | 5 |
| flat primitive-set 11k 参考 | 85.45% | 92.99% | 2.24 / 18.03q | 66.88% | 0 |

flat warm 只加载 219 个共享 encoder/decoder/refiner tensor，排除了 query/reference 和所有
flat 输出头。warm 1k 基本追平 cold 3k，说明视觉迁移能把早期训练效率提高约 3 倍；但它
没有跨过 cold 6k，更不能证明 group geometry 已解决。

从同一 cold 6k 分叉的受控 A/B 显示：full 训练更能压 endpoint 长尾，refiner-only 更能
提高 8q 局部精度。先 full、再冻结主干精修 refiner 的 8k checkpoint 同时改善 r@8q、
r@32q、p50、p90 和 Bond IoU，是 P1 内部最优路径；但完整 group-set exact 仍为 0，
`parallel_2` 在 8q 下只有 4/868 个 group 命中，`parallel_3` 与 `hashed_wedge` 仍为 0。

## NO-GO 原因与转向

P1 对每个 query 无条件输出最多 `32 x 8` 个绝对 member 坐标，并按 canonical 空间顺序逐槽
监督。capacity100 审计发现，旋转会让所有 parallel-2、parallel-3 和 hashed-wedge group
发生 member slot 交换；slot 目标跳变的 p95 分别为 60.0、76.0 和 125.9q。member index
不是稳定视觉语义，因此继续增加训练步数只是在拟合不连续标签。

同一批 GT 可以被低维 typed carrier/envelope 几乎无损表达：

| group | 内部参数 | GT 重建误差 |
|---|---:|---:|
| `parallel_2` | carrier + spacing + 两端 trim，共 7 个 | 最大 1.407q |
| `parallel_3` | carrier + spacing，共 5 个 | 最大 0.655q |
| `hashed_wedge` | 首末中心 + 首末半宽，共 6 个，再加 count | 最大 0.846q |

所以 v0.9.3 的最终判定是：group 作为一等对象的方向保留，canonical absolute-member head
NO-GO。下一阶段保留 Visual SVG v0.2 外部协议，把模型内部目标改成 typed
carrier/envelope，再确定性展开物理 members。`internal_test` 继续封存，生产推理仍保持
`v0.7.10`。

# v0.9.90 AtomPair 第二阶段 Residual Move

## 问题

v0.9.89 每张图最多执行一次 `KEEP / ADD / DELETE / SWAP`。它在双域 validation 将
presence exact 从 710 提高到 720，但仍有一部分可表达样本只差一条边，或者第一步后仍剩一处
错误。v0.9.90 验证是否值得继续叠加受约束的第二次整图动作。

本实验继续遵守以下边界：

- 只用 ChemVision/full-v0 训练和选择 checkpoint；
- MR-TADF、USPTO 不参与训练、阈值或 checkpoint 选择；
- 不使用绝对键长、元素价态或分子类型规则；
- locked internal test 只在 checkpoint 和 margin 固定后运行一次。

## 可达上限审计

冻结 v0.9.89，在固定双域 validation 996 张上真实执行第一步：

| 项目 | 数量 |
|---|---:|
| AtomPair 候选可完整表达 | 806 |
| v0.9.89 已 presence exact | 720 |
| 再执行一次 one-move 可达到 | 779 |
| bottom-4 delete + top-8 add，两删两加可达到 | 788 |
| bottom-4 delete + top-16 add，两删两加可达到 | 792 |

完整两删两加只比第二次 one-move 多覆盖 13 张，却会把每图动作从约 85 扩到上千。因此不做
暴力多动作枚举，选择冻结第一步，再训练一个第二阶段 residual head。

## 模型

第二阶段动作头共 52,228 个参数：

- 18D 候选键关系特征；
- v0.9.87 base logit；
- 第一阶段执行后的 selected bit；
- 是否被第一阶段改变的 changed bit；
- 当前选中边数、候选数和第一阶段变更数的整图摘要；
- `KEEP / ADD / DELETE / SWAP` 联合 softmax。

候选仍为当前正边 bottom-4、当前负边 top-16。候选依据第一步后的 selected mask 生成，因此
既能继续修第二处错误，也能撤销第一步刚执行的错误动作。

## 失败 Pilot

### Cold Start，edit weight 16

4.5k 双域训练后所有 validation 样本都选择 KEEP：

```text
outputs/checkpoints/chemvector-v0990-atom-pair-second-move-4k5/
```

presence/chemical 保持 `720/532`，没有学习到可部署编辑。

### Cold Start，edit weight 64

只把 edit loss 权重从 16 提高到 64，结果仍全部选择 KEEP：

```text
outputs/checkpoints/chemvector-v0990-atom-pair-second-move-4k5-edit64/
```

说明问题不是简单类别权重，而是 4.5k 数据不足以从零重学第一阶段的动作排序。

## Locked Internal Test

结果：

```text
outputs/evaluations/chemvector-v0990-second-move-internal-test996/metrics.json
```

| 指标 | v0.9.89 | v0.9.90 |
|---|---:|---:|
| Presence exact | 730 | 734 |
| Presence+chemical exact | 527 | 530 |
| False positive | 306 | 338 |
| False negative | 449 | 404 |
| ChemVision presence / chemical | 355 / 239 | 358 / 243 |
| full-v0 presence / chemical | 375 / 288 | 376 / 287 |

第二阶段动作：KEEP 871、ADD 100、DELETE 23、SWAP 2。

presence 在两个域都提升，pooled chemical 增加 3 张，但 full-v0 chemical 回退 1 张。这表示
presence-only 动作可能补回拓扑正确但键型错误的候选，或破坏原本 chemical exact 的样本。

## 决策

v0.9.90 组件 GO、默认部署 NO-GO：

- 保留可达上限审计、warm-start 方法、checkpoint 和独立评测脚本；
- 不接入正式推理，不替换前端默认 `structure-v0989-carbon`；
- 不根据 locked internal test 重新调整 margin；
- 下一阶段不继续叠第三次 presence-only move，应在训练域中让动作效用同时读取并监督 Bond
  chemical type 置信度，直接优化 presence+chemical 整图目标。

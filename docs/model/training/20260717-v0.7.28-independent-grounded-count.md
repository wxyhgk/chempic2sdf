# 2026-07-17 v0.7.28 独立 Grounded Count 校准

## 目标

v0.7.27 在固定 100 图中把 known-count vertex exact 从 12% 提高到最高 18%，但模型
自行决定数量时偏向少选点。该现象说明两个任务必须明确拆开：

```text
候选排序：具体选哪些点
数量校准：从排序结果中取前多少个点
```

本轮冻结 v0.7.27 的视觉主干、dense candidates、Atom Query、selector、edge reader
和 node residual。新增 Count head 只输出 `0..128` 的整数分类，绝不修改 node logits
及其排序。

## 第一版失败：过度压缩的集合统计

第一版将候选特征编码后只保留 mean、root-sum、max 和 6 个全局统计。输入包括：

- node logit 和 probability；
- soft degree；
- 最强两条 incident edge；
- candidate mask；
- 候选数、概率和及边数量统计。

固定 100 图训练 10,000 次后：

| 指标 | 结果 |
|---|---:|
| Count accuracy | 23% |
| Count MAE | 3.32 |
| Calibrated vertex exact | 5% |
| Known-count vertex exact | 16% |

该结构连固定 100 图都无法记住，判定 NO-GO。原因是聚合操作丢失了完整候选分数
分布，多个不同分子被压缩成近似特征。

## 第二版：完整排序分布

先按冻结的 node logits 对最多 128 个候选排序，再保留每个候选的全部 6 维节点/边
统计，展平后与 6 个全局统计共同进入两层 MLP。排序操作使输入不依赖候选原始编号，
同时不丢失分数曲线和 incident edge 分布。

新增参数 298,893。

训练命令：

```bash
.venv-train/bin/python -m chemvector.pretrain_grounded_count \
  --grounded-graph-checkpoint \
    outputs/checkpoints/chemvector-v0727-grounded-graph-two-stage-overfit100/checkpoint-0006000.pt \
  --train-shards Data/sdf/molgrapher_synthetic_v0_1/overfit_100/train-000000.tar \
  --validation-shards Data/sdf/molgrapher_synthetic_v0_1/overfit_100/train-000000.tar \
  --output-dir outputs/checkpoints/chemvector-v0728-grounded-count-sorted-overfit100 \
  --train-cache-samples 100 --validation-samples 100 \
  --train-samples 20000 --epochs 200 --batch-size 32 \
  --hidden-dim 256 --learning-rate 1e-3 \
  --validate-every 2000
```

## 容量结果

| 曝光样本 | Count accuracy | Count MAE | Calibrated F1 | Calibrated vertex exact |
|---:|---:|---:|---:|---:|
| 2,000 | 44% | 1.60 | 91.71% | 7% |
| 4,000 | 73% | 0.59 | 93.11% | 13% |
| 6,000 | 90% | 0.18 | 93.47% | 15% |
| 8,000 | 98% | 0.03 | 93.49% | 15% |
| 12,000 | **100%** | **0.00** | **93.51%** | **16%** |

12,000 次样本后，calibrated 输出与同一 batch-1 路径的 known-count 输出逐项一致：

```text
F1                 93.51% = 93.51%
Vertex exact       16%    = 16%
Count classification 100%
```

检测指标中的 count exact 为 99%，是因为一张图的有效候选数少于真值数量；Count head
本身预测了正确真值数量，但 top-k 解码只能取现有候选，因此最终输出少一个点。这也
再次区分了“数量预测正确”和“候选池足够”两个条件。

## 决策

- Count 与候选排序解耦：GO；
- mean/max/sum 压缩集合统计：NO-GO；
- 完整排序节点/边分布：容量 GO；
- 固定 100 图只证明结构能学习，不能证明独立 scaffold 泛化；
- 不替换 v0.7.10 稳定推理。

下一步必须先把 v0.7.27 edge reader 和 node ranking 扩到 MolGrapher 9k，并只使用
validation 1k 选择 checkpoint；随后在冻结的 9k graph checkpoint 上训练本 Count
head。不能直接把只见过 100 图的 graph 当成正式上游扩 Count 数据。

## v0.7.29 复核

Count head 的 100% 容量结论仍成立，但上游 v0.7.27 node 使用了与最终评测不一致的
坐标监督。修正稳定距离并改用 whole-set 目标后，同一路径 calibrated vertex exact
从 16% 提高到 41%。Count 仍能完全追平 known-count，说明数量解耦结论不变。

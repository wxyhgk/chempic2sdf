# v0.9.9 Evidence Carrier Extent

> 状态：P0 正式训练完成；局部 extent 表示 GO，整图与部署闭环未过
>
> 目标：用栅格线条证据固定 carrier 的位置和方向，只学习有限的法向修正、左右 extent、
> keep/type，再复用 v0.9.7 typed affinity + exact-cover
>
> 数据边界：pilot train / validation；`internal_test` 封存；MR-TADF 不参与阈值或
> checkpoint 选择

## 为什么换路线

v0.9.8 已触发预注册 Hard NO-GO。fresh pilot 9k full-model 在 step1,000 的独立
validation100 上只有：

```text
line F1@8q  0.146%
Bond IoU    11.39%
```

因果审计进一步证明 endpoint refiner 在 capacity100 记忆了绝对位置：同一图片仅水平
平移 16px，line F1@8q 即从 `81.4%` 降至 `0.16%`。因此停止以下表示：

```text
raster -> fixed/free queries -> unrestricted absolute coordinate residual
```

v0.9.7 的 typed affinity + exact-cover 不在停止范围内。它在正确 proposal pool 上已经达到
`96.12%` membership group F1、`94.37%` pair F1、`77%` partition exact，并且没有
invalid 或 carrier fitting failure。

## Evidence Carrier 正式审计

可复现入口：

```text
chemvector/audit_evidence_carrier_proposals.py
tests/chemvector/test_audit_evidence_carrier_proposals.py
outputs/evaluations/
  chemvector-v099-evidence-carrier-proposals-validation100-formal-v3/audit.json
```

OpenCV LSD 只读取完整 PNG，不使用 target geometry 生成 proposal。GT 仅在 proposal
生成完成后用于 Hungarian coverage 审计。正式 validation100 结果：

| 指标 | 结果 |
|---|---:|
| raw proposals / image | 95.27 |
| q8 all-line recall | 77.52% |
| q8 recall，排除 hashed | 91.02% |
| q8 single group strict | 88.42% |
| q8 parallel-2 group strict | 92.52% |
| raw candidate precision | 41.61% |
| 整数平移 proposal F1 | 94.78% |

固定局部枚举可把 q8 非 hashed recall 提高到 `96.62%`，single/parallel-2 group strict
提高到 `96.48% / 96.21%`，但候选暴增到 `3715.5/image`，precision 只有 `1.13%`，
所以不能作为训练或部署表示。

最关键的审计不是端点 exact，而是方向载体 support：

| 范围 | direction carrier support |
|---|---:|
| 普通 single/parallel-2/parallel-3 | 3454 / 3455 = 99.97% |
| single | 2557 / 2557 |
| parallel-2 | 895 / 896 |
| parallel-3 | 2 / 2 |
| 长键，至少 96px | 127 / 127 |

raw LSD 对 127 个长键只有 `60/127` 完整端点覆盖，但 `127/127` 都提供了正确方向与局部
墨迹。这说明图像中几乎总有足够证据确定 carrier，失败主要来自要求模型一次性生成完整
两个端点。

去掉文字只把 q8 提高约 1pp；text-adjacent 与非文字相邻 ordinary group recall 分别为
`89.56% / 89.40%`。当前 primitive 几何失败不能继续归因于 OCR。

## 新表示

普通线组采用：

```text
full raster
  -> multi-scale LSD / line evidence anchors
  -> candidate-relative oriented strip
  -> keep/drop
  -> bounded normal offset
  -> discrete left/right extent on the image-line interval
  -> frozen physical line coordinates
  -> symmetric typed affinity
  -> exact-cover with DROP candidates
  -> deterministic carrier fitting
```

约束：

1. anchor center/orientation 来自栅格证据，不由 learned query 自由生成；
2. 特征全部使用 candidate-relative 坐标，不输入绝对 x/y position embedding；
3. 法向修正有界，extent 在 carrier 与画布交线上的有限离散 bins 中分类；
4. 多个支持同一 GT line 的 anchor 都可以是正样本，不能用单一 Hungarian winner 把等价
   proposal 标成负样本；
5. 输出坐标冻结后才进入 grouping，不允许 typed affinity 重写 geometry；
6. 双键和三键最终只有两个语义端点，physical members 不直接变成 Junction；
7. 交叉点若位于 carrier 内部，不生成语义节点。

## 连续 Extent Oracle

在训练模型前，先用同一套 association 和连续 target 参数做表示上限审计。该 oracle：

- carrier 仍由完整 raster 的 LSD 生成；
- carrier 方向完全冻结；
- 只应用 GT normal offset 和连续 left/right extent；
- GT 不参与 proposal 生成；
- 不运行 learned model。

可复现入口：

```text
chemvector/audit_evidence_carrier_extent_oracle.py
tests/chemvector/test_audit_evidence_carrier_extent_oracle.py
outputs/evaluations/
  chemvector-v099-evidence-carrier-extent-oracle-validation100/
    oracle_metrics.json
```

validation100 正式结果：

| 指标 | q8 |
|---|---:|
| ordinary physical-line recall | 4353 / 4355 = 99.954% |
| structural sample exact | 98 / 100 = 98% |
| single group coverage | 2557 / 2557 = 100% |
| parallel-2 group coverage | 895 / 896 = 99.888% |
| long group coverage | 127 / 127 = 100% |

`parallel-3` 只有 2 组，其中 1 组完整覆盖；样本量太小，不能用 `50%` 或早期 raw audit 的
`100%` 判断 triple 泛化。该类需要在后续训练采样中单独保证支持量。

q8/q16/q32 结果完全相同，说明剩余两条漏线来自 association support 缺失，而不是固定
carrier 方向的几何精度。normal + finite extent 这一表示正式 GO，不需要增加自由角度或
绝对端点回归。

## 特殊符号分支

普通 line carrier 不承担所有视觉符号：

- `hashed_wedge`：60 组中只有 2 组具有至少两条 raw LSD 可用短线，必须预测整体 dash
  cloud envelope 或使用多尺度短线/连通域分支；SDF 不要求严格复现每条 dash 数量；
- `solid_triangle`：validation100 有 67 组，使用 contour/fill-mask + apex/base symbol head；
- `solid_quad`：有 5 组，归入同一 polygon symbol head；
- text box/OCR：继续独立，不进入本轮普通线 extent 模型。

## 分阶段门控

### P0 Learned Extent

只训练/评估普通 line anchors，GT association 只产生标签，不进入模型输入。连续 oracle
已经通过，本阶段判断离散 385-bin extent 与局部视觉头能否逼近该上限。

- q8 非 hashed member recall `>= 98%`；
- q8 single / parallel-2 group coverage `>= 98%`；
- 长键 group coverage `>= 95%`；
- p95 proposals `<= 400/image`；
- 16/32px 平移后 recall/F1 下降 `< 2pp`；
- 无绝对位置 feature。

若方向 support 保持高但 extent 不收敛，说明 oriented strip/extent bins 设计不成立；停止
增加数据，先修局部坐标与目标定义。

### P1 Keep + Extent

加入全部 raw candidates 与 hard negatives，但 hashed/polygon/text 是 out-of-scope，不作为
普通线负样本。

- keep recall `>= 98%`，precision `>= 80%`；
- q8 line recall `>= 90%`，q32 `>= 97%`；
- structural sample exact，排除 hashed/polygon/text，`>= 80%`；
- 长键 q8 `>= 95%`；
- invalid geometry `= 0`。

### P2 Typed Affinity + DROP Exact Cover

- pair F1 `>= 90%`；
- membership group F1 `>= 93%`；
- partition exact `>= 40%`；
- line R@8q `>= 85%`，Bond IoU `>= 65%`；
- solver p95 `< 100ms/image`；
- invalid / carrier fit failure `= 0`。

DROP 已以 backward-compatible 方式加入 `bond_group_exact_cover.py`：

```text
sum(x_G for G contains proposal_i) + drop_i = 1
```

默认 `allow_drop=False` 时旧行为和测试完全不变；开启后 `known_group_count` 只统计化学
group，不统计 DROP，结果单独返回 `dropped_proposal_indices`。tie-break 顺序为主分数、
少 DROP、少化学 group、canonical rank。正式 P2 必须使用 `known_group_count=None`，不能
再依赖 GT group count。

注意：当前 v0.9.7 packing 的 candidate score 来自 log-softmax，数值恒不大于 0；若直接
配合默认 `drop_score=0`，最优解会把所有 proposal DROP。P2 接入前必须改成相对 all-drop
基线的 log-odds 增益：chemical candidate 得分为 keep/type 相对 NO_GROUP 的增益，正值才
能击败 DROP。solver API 已就绪，不代表旧 packing 已可直接启用 DROP。

在训练 affinity 前还要先跑 perfect-affinity candidate oracle：带 DROP 的 solver feasible
必须为 100%，ordinary proposal partition exact 至少 95%。否则仍属于 candidate generator
问题，不进入 affinity 训练。

### P3 Junction / SDF

group carrier 拟合后再做 endpoint-to-Junction：

- same-junction pair recall `>= 99%`；
- Junction partition exact `>= 80%`；
- topology exact `>= 70%`；
- crossed-line false Junction `<= 2%`；
- SDF sanitize、graph exact 和立体正确率作为最终指标，Visual SVG 只做诊断。

# 文字锚点与坐标契约：修正离线投影解释，暂缓23组边界配对

## 本轮结论

固定58图的1090个目标、7316个raw候选和上一轮525组配对已全部核对。
**未发现当前标签适配、原子头坐标监督和匹配之间的归一化契约不一致**；
但确认上一轮离线位置解释把模型归一化坐标乘768叠到原图，
没有使用标签适配器的逆变换乘767。这是诊断层的投影问题，不能据此宣称训练坐标整体错误。

本轮生成独立的正确投影图册和敏感项清单，**不覆盖历史报告、模型输出或图册**。

- 上轮525组待复核配对中，**19组对源图投影敏感，另4组对q1023量化敏感**，共23组暂缓。
- 其余**502组**在本次两项检查下稳定，仍不是已批准训练标签。
- 原10个无6px内候选的文字节点中，去掉目标q1023量化的诊断口径会让**4个**跨回6px内；
  单纯把距离倍率768换成767，**0个**跨回。原始验收保持不变。
- 10个节点的目标网格都不在保存的raw候选中。只允许已有网格内的偏移改变，
  9个在几何上有进入6px的可能，1个即使最理想偏移也达不到。
- **选择错误与定位误差必须分开处理**：冻结候选坐标只训selector，不能修好这些定位缺口。

工作进程CPU **2.167秒**，无GPU、模型前向、checkpoint加载、参数更新或部署。
相关合并测试 **148 passed / 10.00秒**。没有新的识别准确率结果。

## 实际坐标链

设原图化学节点坐标为 `a`，保存的候选归一化坐标为 `p`，量化后目标为 `q`。

| 环节 | 当前实现 | 本轮处理 |
| --- | --- | --- |
| 同源渲染标注 | `a = RDKit GetDrawCoords(atom_id)`；不是字形框中心 | 核对原标注，不重渲染 |
| 目标适配 | `q = round(a / 767 * 1023) / 1023`，存float32 | 与保存目标逐值相同 |
| 原子头监督/解码 | 目标格由 `q * 192` 决定；输出 `(cell + sigmoid(offset)) / 192` | 监督与输出在同一归一化坐标域 |
| 原匹配距离 | `torch.cdist(p, q) * 768`，6px门限 | 完全保留 |
| 回投原SVG/PNG | 标签归一化的逆变换为 `p * 767` | 新图册采用此投影；旧图册的 `p * 768` 不覆盖 |

这里不存在“把一边乘767，另一边乘768后做原匹配”的情况。
原子头的offset loss本身已按同一个q目标构造；合成测试直接调用现有loss函数，
确认按其公式构造的正确offset损失为0，并能还原同一归一化目标。
全部7316个候选的坐标也与其保存的192×192网格ID一致。

代码依据：

- `chemvector/training/curriculum/data.py:39`：像素除767并量化；`:208`：分别构造化学锚点和文字框。
- `chemvector/components/atoms/objects/spatial_atom_object.py:70`：坐标输出；`:114`：目标格与格内偏移监督。
- `chemvector/components/graph/joint/predicted_incidence.py:79`：从预测格取原锚点，不改坐标。
- `chemvector/training/graph/relations/train_direct_atom_pair_bond.py:166`：归一化距离乘768后匹配。
- `chemvector/training/curriculum/pixels.py`：保持原768×768图，不隐式resize。
- `Data/sdf/text_source_renderer/v2/layers.py:56`：保留原子锚点，同时单独保存glyph union bbox。

本轮只检查这条实际使用路径，不声称整个仓库所有坐标消费者都经过了审计。

量化导致这10个目标的位移仅约0.115–0.411px；它能决定几个边界样本过不过6px，
**但不能解释原来约6–8px的全部定位误差**。不能据此简单删掉量化或扩大半径。

全部58图的目标覆盖在去量化诊断下为4个增加、0个减少；这不是重新运行Hungarian的结果。
全体候选—目标距离中，float32 cdist与直接双精度距离最大差约0.302px，
但6px内/外的关系翻转数为0；不据此宣称任意全局匹配分配也必然相同。

“已有格下界”允许在保存网格的4×4范围内任意放置点，是几何可行性下界，
并非模型能够达到的误差，也不涉及实际优化offset。
最后一个C节点下界约6.879px，说明固定这批网格时单改格内偏移也不够。
所有10个目标格均不在raw候选内；由于没有保存完整heatmap，不能进一步归因为
局部峰筛选、0.01阈值、top-k容量中的某一项。

## 化学节点不等于文字框中心

数据适配器分别保留 `atom_anchors` 和 `atom_text_center`，没有把它们当成同一个目标。
例如N或NH，候选可能落在N字形中部，而化学节点锚点在字形中更靠上的位置；
含H的联合文字框中心还可能位于两个字符之间。

新图册使用原始PNG，标出：绿十字为真实化学锚点，蓝框为量化锚点，红圈为最近候选，
灰框为文字墨迹联合框。图示支持“文字区域里的定位偏差”，不等于字形伪点或原子未被看见。
本轮没有把文字框中心替换成化学锚点，也不据这些图认定网络内部使用了哪种特征。

## 下一步边界

当前先完成坐标证据修订，**没有开始组级新损失或梯度实验**，避免把敏感配对带入监督。
后续应按以下顺序做CPU工作：

1. 在单独版本中固化节点组、排除23个敏感项，并对实际使用子集重新检查原匹配不回退；
   不篡改历史文件、不把“坐标稳定”自动等同于语义人工核验通过。
2. 验证节点级监督的最小数值/梯度契约：有效代表不能全被压低，重复代表需处理，
   笔画片段与正确代表需区分；未知项不参与新标签。
3. 对上述定位缺口另列上游定位实验范围，不期待冻结坐标的selector修复它们。
   是否更新heatmap或offset必须有单独证据与预算，不自动打开整个主干训练。

模型仍用自研路线，不改OCR、不换架构、不追加GPU试训。

# Selector 正例保留定额试训：覆盖改善，但验收失败

## 结论

按用户“继续推进”对上一轮明确预算的确认，执行了唯一一次试训。
RTX 5090 单卡实际 **16.735 秒、400 步**，在 600 秒 / 400 步上限内完成。
这不是全模型训练：只更新 178,565 参数的 set_head，冻结上游预测并缓存，
所以不需要每步重算视觉编码器。

**NO-GO：没有启动条件式 944 图 CPU 回归，没有部署，没有续训或第二次尝试。默认仍为 initial。**

端点覆盖改善，但误保留也增多，核心 `C#C` 仍未修好。
这排除了“本轮多保留几个正确候选就足以安全推进”的判断，
不等于证明整个自研架构不可行，也不支持立即扩大训练。

## 配对结果

所有前后比较使用本次 GPU 上的相同输入和冻结上游，不拿历史 CPU 数字替代本次 baseline。
完整端点指所有目标原子在选中候选中能匹配到，**允许额外点存在，不是分子识别准确率**。
可达键只要求两个目标端点存在，**不代表键分类、连接或最终 SDF 已正确**。

| 指标 | 26 张拟合反例 | 32 张旧完整分子回放 | 64 张新分组开发图 |
| --- | ---: | ---: | ---: |
| 完整端点图数 | 19 → 23 | 21 → 21 | 51 → 56 |
| 匹配目标原子 | 88 → 96 / 99 | 970 → 972 / 991 | 490 → 499 / 507 |
| 可达目标键 | 69 → 77 / 81 | 1,034 → 1,038 / 1,069 | 436 → 449 / 459 |
| 原始全候选匹配下的误保留 | 6 → 12 | 23 → 25 | 17 → 20 |
| 选中集合重新匹配后的多余点 | 4 → 9 | 17 → 19 | 9 → 12 |
| 严格 SDF 正确图数 | 未测 | 8 → 8 / 32 | 未测 |

原始匹配的负例和选中集合重新匹配后未匹配的点不是同一概念，不能混用分母。
即使采用后一个指标，新开发图仍增加 3 个多余点，因此不是单纯的统计口径问题。
没有旧图丢失 baseline 可达键，也没有 baseline 正确 SDF 变错。
上述 32 图参与训练回放，其 8/32 不是独立准确率。

64 张开发图未进优化器，但已经查看结果，以后不能继续称它们是未观察数据。

## 核心反例：问题不只是阈值偏保守

保持筛选阈值 -0.25 不变，`C#C` 的固定 raw 正例槽为 1、2，已知错误槽为 0。

| C#C 候选 | initial 分数 | 400 步分数 | 最终决策 |
| --- | ---: | ---: | --- |
| 错误候选 0 | -0.0851 | 0.5575 | 仍被保留 |
| 正确端点 1 | -0.6260 | -0.1049 | 从丢失变为保留 |
| 正确端点 2 | -0.8177 | -0.2891 | 仍被丢失 |
| 新误保留候选 3 | -0.7101 | -0.2405 | 从拒绝变为保留 |

最弱正例减已知错误候选分数，最终为 **-0.84664**。
对这个固定输出，不存在一个标量阈值能同时保留两真端点又排除错误槽 0：
前者要求阈值不大于 -0.2891，后者要求阈值大于 0.5575。
这是保存分数直接推出的结果，没有搜索或修改阈值。

- `C#[13CH]`：正确槽 2 仍保留，槽 4 仍丢失；新增误保留槽 1、3，核心保护失败。
- `C#CC`：正确槽 0、1、5 全部保留，未新增误保留，完整端点恢复。
- `CCC#N`：正确槽 0、1、2、3 全部保留，未新增误保留，完整端点恢复。

这轮配方在部分样本补回端点，但还没有把最难反例的真伪候选分开。
没有训练“仅原 full loss”的对照组，因此不能把改善或副作用单独归因于新增项。

## 早停和预算履约

固定配方：original full set loss + 1.0 × positive-retention；AdamW LR 5e-6、eps 1e-8、
weight decay 0、clip norm 1、batch 1、seed 20260920，模型 eval，无 AMP/TF32。
图像、阈值、上游结构、OCR、pair/role/bbox 都没有调整。

- 第 100 步：拟合完整端点 21/26；旧图严格正确与可达键无回退；未触发约定早停。
- 第 200 步：拟合完整端点 22/26，优于 baseline 19/26；旧图无约定回退，继续到硬上限。
- 第 400 步：拟合完整端点 23/26；核心反例新增误保留、C#C 不通过。
- 最终 new64：覆盖提高，但误保留 17 → 20，开发非退步关卡失败。
- local_pass=false、development_nonregression=false、full_regression_allowed=false。

约定的中途早停针对旧图严格正确/可达键丢失，以及到 200 步覆盖不改善；
不是看到任意负例计数增加就提前终止。最终验收仍严格执行，没有事后放宽。

400 条持久化更新意图与 400 条完成记录逐条对应，步数连续、无重试。
267 次旧完整分子回放、133 次反例拟合，严格按 old/old/witness 循环；
全部 58 个训练记录至少使用一次，64 个开发记录从未进入优化器。

独立 CPU 读取前后 checkpoint 验证：仅 set_head 的 39 个状态张量变化，
所有其他张量逐值相等，provenance 不变，保存文件标注不支持恢复、不部署。
冻结权重、OCR、标签与预测缓存哈希在任务前后相同。
授权绑定的初始模型、旧数据清单、冻结来源及默认前端配置再次校验通过。

## 下一步的重点

先冻结这次结果，不自动续训、不调整阈值、不扩大数据或启动第二个 GPU 方案。
当前需要解决的是 **真实端点与伪候选的区分**，而不是继续提高全部疑似候选的分数。

下一次方案设计应从已保存的 C#C / 同位素反例及新增多余点出发，
核对候选位置、原始匹配与选中后匹配是否表达了同一套端点监督，
再决定是否需要更明确的正负候选区分目标。
这一步可以先做保存产物和监督契约的检查；本轮没有授权或执行新的训练配方。

暂不据此增加 MoE、换 MolGrapher，或直接全量训练新课程库。
候选筛选不是最终目标，下一轮仍必须同时验证正确端点、错误点和旧图键连接。

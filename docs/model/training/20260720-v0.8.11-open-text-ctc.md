# v0.8.11 Open Text CTC

> 状态：模型容量 GO，真实预测框 GO，开放字符串与后缀校准未过门槛  
> 最佳实验输出：`outputs/checkpoints/chemvector-v0811-open-text-full-1500k/full/best.pt`

## 目标

使用 `Data/ocr/open_text_v0_1` 训练不依赖化学词典的 byte-level CTC OCR。训练只识别
图片中的原始字符串，不展开 `Ph/CH3/R1`，不使用 PaddleOCR 教师，也不使用 MR-TADF
分子训练或调参。

Open Text v0.1 共 120,000 条 crop：

- train / validation / internal test：108,000 / 6,000 / 6,000；
- 100,000 条组合式合成字符串；
- 20,000 条分子 crop；
- 分子 crop 包含 6,000 个 GT 框、10,000 个采样扰动框和 4,000 个真实 detector 框。

## 实现

新增：

- `chemvector/pretrain_open_text_ctc.py`：专用 `png+json` WebDataset loader、分层采样、
  A/B/C 训练和 validation/internal test 门控；
- `chemvector/audit_open_text_ctc_capacity.py`：固定 250 条样本的容量审计；
- `tests/chemvector/test_open_text_ctc.py`：letterbox、采样概率、解冻范围、评分和门控测试。

输入图片保持纵横比后 letterbox 到 `192x48`，不拉伸字符。正式采样概率为：

| 分桶 | 概率 |
|---|---:|
| 随机开放字符串 | 30% |
| 规范合成字符 | 20% |
| 分子 GT bbox | 10% |
| 分子采样 bbox | 10% |
| 分子真实预测 bbox | 30% |

随机字符串按长度和字符类别均衡，不按每条唯一字符串过采样；化学常见字符串按完整
字符串均衡。

## 20k 受控实验

v0.8.8 在 Open Text validation 上的直接基线：

- overall exact：3.88%；
- 真实预测框 exact：27.00%；
- molecule exact：22.80%；
- 随机开放字符串 exact：0%。

冻结 Pixel Encoder 与只解冻后两层卷积的 20k pilot 均未产生有效泛化。修正随机
字符串采样比例后结果仍相近，说明 20k 次样本呈现不足以重建开放字符视觉表征。

## 容量审计

从五个训练分桶各固定抽取 50 条，共 250 条，完整解冻 Pixel Encoder，在同一集合上
训练和评测：

| epoch | exact | 随机字符串 exact | 分子 exact |
|---:|---:|---:|---:|
| 40 | 54.0% | 1.96% | 79.33% |
| 80 | 79.2% | 23.53% | 95.33% |
| 120 | 89.2% | 持续上升 | 接近 100% |
| 160 | 100% | 100% | 100% |

因此 byte CTC、48 个横向时间步和当前卷积容量能够表达长度 1-8 的开放字符串。20k
pilot 失败不是结构性不可表达，而是训练预算和视觉适配不足。

## 扩大训练

从 v0.8.8 初始化，完整解冻三层 Pixel Encoder，分三段训练：

1. 300k：head `3e-4`，Pixel Encoder `1e-4`；
2. 续训至总计 900k：head `2e-4`，Pixel Encoder `5e-5`；
3. 续训至总计 1.5M：head `1e-4`，Pixel Encoder `2.5e-5`。

validation 关键结果：

| 训练量 | overall | 真实预测框 | molecule modifier | 常见单字符 | 开放随机串 |
|---:|---:|---:|---:|---:|---:|
| 基线 | 3.88% | 27.00% | 28.33% | 23.85% | 0% |
| 300k | 13.08% | 71.50% | 46.80% | 87.53% | 0.54% |
| 900k | 30.05% | 83.50% | 67.49% | 89.50% | 2.27% |
| 1.5M | 46.95% | 81.50% | 67.49% | 86.43% | 5.62% |

1.5M checkpoint 的开放随机串 edit similarity 为 26.29%，supported-label macro 为
74.15%。internal test 的真实预测框 / molecule exact / supported macro 分别为
76.50% / 72.00% / 64.16%，对应分桶与 validation 的差距均在门控容差内。

## 结论

- 模型容量：GO。250 条容量审计达到 100%。
- 真实预测 bbox：GO。validation 达到 81.50%，首次超过 80% 门槛。
- modifier：67.49%，未达到 70%。
- 常见单字符：86.43%，未达到 95%。
- molecule simple 假修饰符：5.56%，未达到 2%。
- 开放随机字符串：仍明显不足，不能宣称已经解决任意字符串 OCR。

因此 v0.8.11 checkpoint 保留为实验组件，不替换稳定默认。后续不再只增加相同混合
训练步数；v0.8.12 应利用 Open Text 已有的同风格反事实组，显式训练
`N/NH/NH2/N+`、`B/Br`、`P/Ph`、`C/Cl/CH3` 的后缀存在性和字符差异，同时保留
真实预测 bbox 训练。该方向仍是纯 OCR，不加入化学价态或 MR-TADF 专项偏置。

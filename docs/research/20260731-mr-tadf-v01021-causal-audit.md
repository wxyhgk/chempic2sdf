# MR-TADF v0.10.21 因果错误审计协议

> 状态：固定审计集已生成，等待人工首因复核
> 模型：`v0.10.21-invalid-only-ocr-fallback`
> 审计集：200 个错误 + 100 个正确对照

## 目的

在设计 ChemTraverse 前，区分以下首因：文字笔画与结构混淆、隐式碳多漏、语义键多漏、
OCR 转写、键级、原子属性/立体和 SDF 编译。自动诊断只用于预分桶，最终首因必须查看原图、
GT/预测对象叠加、真值 SDF 和预测 SDF 后人工确认。

MR-TADF 仍然只作为主应用 benchmark。本审计不会产生训练标签，不用于模型训练、阈值选择或
checkpoint 选择；它只决定下一条架构路线应先解决哪类错误。

## 自动审计结果

完整 1,100 张中有 836 个 Chemical error。按确定性优先级得到：

| 自动首因 | 数量 | 占 836 个错误 |
|---|---:|---:|
| 原子集合多检/漏检 | 390 | 46.65% |
| OCR 转写 | 201 | 24.04% |
| 交叉多余键 | 69 | 8.25% |
| 原子属性/芳香性相关 | 99 | 11.84% |
| 其他键重连、多漏和键型 | 42 | 5.02% |
| 尚未解析 | 35 | 4.19% |

前三类合计 660 个，占错误的 `78.95%`。这支持文字/结构语义分离和整图生成方向，但不能据此
把全部原子集合错误归因于字形；必须完成下面的人工首因复核。

## 人工复核

前端地址：`http://0.0.0.0:8765/audit.html`。

每张显示：

1. 输入图片；
2. GT（绿色）与预测（洋红）对象叠加；
3. 真值 SDF 渲染；
4. 正确、错误或 invalid 预测 SDF 渲染；
5. 原子/键数量、漏检、多检、OCR 和键型诊断。

人工选择唯一主要原因、置信度和可多选 MOSAIC 风格标签。保存后写入
`outputs/audits/mr-tadf-v01021-causal-300/annotations.json`，也可以从页面导出副本。

## 判定门

完成 300 张复核后：

- 至少 80% 的错误必须得到 `high/medium` 置信度首因，否则诊断协议信息不足；
- 正确对照用于测量某种视觉风格是否只是相关而非致因；
- 若“文字笔画被当作结构 + 隐式碳多漏”占主导，进入 ChemTraverse 表示 A/B；
- 若数量正确但拓扑或语义键错误占主导，先修遍历/键对象协议；
- 若 OCR 转写单独占主导，才追加化学专用 OCR 支线；
- 任何结论同时报告 standard、long 和 extreme-long 三桶，不能只报 pooled 数字。

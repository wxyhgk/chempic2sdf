# 2026-09-18：三路调研后的低算力推进建议

## 决定

**保留自研模型和 initial，停止原六组联合续训配方；下一步先做一次有终点的 CPU 接口定位，不默认再训 pair，不换架构。** 定位后还须确认 initial 在该接口有实际可改善空间，才提出一次单组件小训练。

本次完成三个 subagent 的独立只读调研及交叉讨论：训练机制、保存预测、实验路线。主 agent 复核了主要配对统计、图同构计数、训练覆盖和数据调度代码。没有新模型推理、优化器更新、GPU 作业、私有身份查询或封存数据访问；没有改变生产代码、模型、发布清单或前端。本文是研究报告，不是新训练授权。

## 新核对的证据

固定开发集仍为 200 个分子 × 4 种样式 = 800 图。initial 为 170/800，修复后 last 为 116/800，最终仍选 initial。

| initial → 修复后 last | 图数 |
| --- | ---: |
| 始终正确 | 97 |
| 原正确、现错误 | 73 |
| 原错误、现正确 | 19 |
| 始终错误 | 611 |
| 有效 → 无效 | 155 |
| 无效 → 有效 | 60 |

正确性与有效性是两组不同的配对划分，不能把表中所有行相加。有效 SDF 净少 95 张。

73 张新增错误中，35 张无效、38 张有效但身份错。与修复前冻结试训的 71 张新增错误相比，交集 **62 张**，并集 82 张；只有本轮出现的 11 张，只有旧轮出现的 9 张。主要退步模式重复，不能把问题全归于这次 selected 标签修复。

对 38 张有效新增错误，用 RDKit 解析保存的 SMILES，并以 NetworkX 比较忽略原子标签、保留连接与键类型的图：

- 33 张元素组成不同，27 张原子总数相同，两者交集 22 张。
- 其中 18 张是原子总数不变，但 C 增加、杂原子减少。
- **17 张连接和键类型同构**，其中 14 张元素组成不同，另 3 张涉及 H、自由基或电荷等属性。

这些是相互包含/相交的子集，不相加。17 张不意味着候选坐标、逐原子对应或立体化学正确，也不证明错误都来自 OCR。35 张无效记录的显式价态报错只是最终失败症状；文字属性或错误连接都可能导致它。当前无效结果未保存失败前完整 graph，不能靠这些记录进一步给出根因比例。

训练日志也不支持“普遍没有正键监督”的解释：800 步累计可达正键为 **18,450/18,650（98.93%）**；匹配的 selected 原子覆盖 17,294/17,425 个目标原子（99.25%，不是候选 precision；selected 总数为 17,459）。这只描述训练监督可达性，不是开发集效果。

## 三路观点与取舍

### 训练机制审查

当前六组 vision/atom/bond/set/pair/bbox 同时更新。硬 atom mask 使最终 pair 损失不能经过筛选决策回传到 set_head；总训练损失是局部任务之和，不含最终 OCR/SDF 身份指标。局部损失下降、整图结果下降并不矛盾，但也不能因此断言代理损失必然有害。

role/OCR 权重冻结，文字接口仍会变：预测锚点改变 role 的输入，bbox 继续更新并改变 OCR 裁剪。bbox 的框回归损失不保证字符正确率改善。

全局 norm=1 裁剪在 800/800 步触发，裁剪前范数 10.97–313.40。bbox 虽只接收自身损失梯度，也受到其他组梯度范数的共同缩放；不能据此换算 Adam 的有效学习率或宣判它是根因。

机制组倾向把固定其他组件的 pair-only 当作新发布数据的兼容性验收，但明确它不等于已定位 pair 为主因，而且候选/文字不可达、pair 已基本正确时应取消更新。

### 保存预测审查

17 张连接/键型同构但属性错的案例支持窄文字接口检查：同一预测锚点、结构和冻结 role/OCR 下，只比较 bbox 对裁剪、OCR 原文和编译属性的影响。不要把整个 73 图都叫“文字错误”，也不要因为 role 没更新就排除文字链路。

### 路线审查与最终取舍

不默认再做 pair-only：历史冻结上游的 Direct AtomPair 已有成功训练记录，重复证明“它能学”信息增益有限。旧 12 图反事实中，8 张退步图回退上游救回 6 张、回退 bbox 救回 3 张；initial 上游 + last pair + initial bbox 为 7/8。这些是重叠且错误富集的小样本计数，不是总体责任比例，但已足以停止六组联动。

主 agent 采用路线组建议：**补拆旧实验尚未拆开的上游候选生成与 set 筛选，保留窄 bbox 对照；不再次做泛泛八组合扫描，不再重复 Dropout/梯度调查，不等完整责任百分比才作停止决定。** pair-only 仅保留为有明确剩余连键错误、且冻结接口可达时的备选，而非默认训练任务。

## 有边界的下一步（尚未执行）

### 1. 一次 CPU 定位，建议上限 300 秒，GPU/优化器均为零

使用最新 initial/last；沿用旧 probe 预先固定的 **12 张开发图（已含控制）与 12 张训练诊断图**，不按新结果换样本。该清单保存在 `outputs/audits/chemvector-freeze-regression-probe-20260915/worker.log` 的第一条 JSON，并非单独的 plan.json。

- 开发图：固定 initial 的 pair/role/bbox/OCR，对 `(vision+atom+bond)` 与 `set_head` 做有限交叉；缓存同一候选输入，对照两个 set 的保留/删除和最终 SDF 变化。initial/last 原样回放用于核对历史保存结果。
- 文字对照：在完全相同的结构、锚点、role/OCR 下仅更换 bbox，保存 gate、crop、OCR 原文、解析属性与失败前图；不做阈值扫描或自动化学修补。
- 训练诊断图：仅用已准入、同源渲染的对齐标签量化 raw/selected 候选覆盖和多余候选，真值只评分、不注入预测。

重要边界：当前 fresh-dev loader 只给原 PNG 与 SDF 化学真值，没有发布经过核验的像素级原子标注。**不能把 SDF 坐标当作原图像素坐标，或直接声称在开发图上量出了 GT 候选召回。** 开发图做反事实与身份评分；候选覆盖定量在既有对齐训练诊断图上完成，两者不能混称为同分布验证。

通过条件是定位可复现的具体对象/接口变化，而非仅获得一个较好总数。若同一候选输入下 set 改动能解释错误，先冻结/修正筛选环节；若生成候选已改变，进一步关注候选生成；若同锚点 bbox 替换改变文字并救回，记录裁框接口问题。各来源可以同时存在，不强行选一个唯一根因。

本次预定范围不能区分时，明确报告不确定并结束，不自动扩样或轮番训练各头。不能将错误富集诊断集的分数作为新准确率。

### 2. 只有存在可改善空间，才申请一次单组件验收

“某模块续训后破坏结果”首先说明它应受保护，不自动证明它值得再训练。先在 initial 上确认该组件有实际错误、当前候选/标签能表达修复目标。

满足前提后，可固定 **32 张已准入完整分子训练图**，从 initial 出发，只更新选定组件，其他部分和 OCR 保持固定；建议一次最多 400 步 / 单卡 10 分钟，需新协议和明确授权。不因结果换图、不扫描学习率、不自动续跑。

验收包括该组件的整图任务指标、最终 SDF 和冻结状态；不可达目标仍报告，不能要求 pair 修复不存在的原子，也不能删掉这些图制造通过。历史已有 overfit32，不能包装成首次证明模型可学习。失败只否定此次受限配方。

### 3. 通过小验收后才考虑单组件扩量

仍以固定 800 张开发图严格 SDF 为主指标，课程 144 图单独报告；必须超出 initial 的 170/800，并报告有效率、各样式、救回/改错，不能只看 loss。正式门槛和预算在运行前固定，另行授权。微小开发集改善不算最终泛化证明，更不自动部署。

## 关于课程路线与架构

`release.py:101-114` 实现的是固定 `full/full/curriculum` 混合队列，**不是原子→官能团→小分子→大分子的阶段式课程**。13,151 个训练行中课程为 657 行，约 5%；本轮 800 步却有 266 步课程、534 步完整分子。按既定比例，单课程行平均抽取机会约是单完整分子行的 9.5 倍。这是需要控制的训练配方因素，不是已证实根因。

所以既不能声称用户提出的阶段课程已得到失败验证，也不应下一轮同时改变课程顺序、解冻范围、loss 和架构。当前重点是找出可稳定更新的接口。MoE、循环深度、渲染闭环暂不作为修复手段；只有确认现有候选/表示无法承载必要目标，才针对那个瓶颈改表示。

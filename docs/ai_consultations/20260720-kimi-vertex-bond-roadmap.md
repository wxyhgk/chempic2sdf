# Kimi：ChemVector 顶点与键主线评审

## 基本信息

- 日期：2026-07-20
- 咨询对象：Kimi Code
- 项目版本：v0.8.11
- 主题：在 OCR 可外置后，如何优先解决整组顶点和键图
- 状态：等待项目侧验证

## 提交给专家的说明

我们正在做一个“化学结构图片 -> SDF”的模型 ChemVector。请从模型架构和训练方法
角度评审，不要只给出“增加数据量”“换更大模型”这类泛化建议。

### 一、任务目标与约束

1. 输入是论文或专利中的二维化学结构图片，输出必须是包含原子、键级、电荷、立体
   信息和二维坐标的 SDF。
2. 化学图中可能有长键、拥挤键、双键/三键、楔形键、交叉线、稠环、桥环、文字原子
   和任意缩写。禁止用固定最大键长、最近邻或距离阈值直接删除候选键。
3. MR-TADF 只做外部诊断，不能参与训练、阈值选择或 checkpoint 选择。
4. 当前训练机器是 RTX 5090，但最终希望核心模型可在 CPU 上运行。
5. OCR 可以使用独立的开放字符串模型；当前重点是顶点集合和键拓扑，不要求一个模型
   同时学习字形、顶点和键。

### 二、数据

我们已经有完整 WebDataset：180,000 个分子、720,000 张图片，每个分子四种布局，
scaffold 跨 split 重叠为 0。为了快速做可控实验，最近的结构模型主要使用
ChemVision pilot：约 8,974 张 train、498 张 validation，包含原子中心、文字 bbox、
键对象、显示线层和完整分子图真值。

### 三、当前模型如何训练

当前不是单一端到端模型，而是分阶段组件：

```text
原图
  -> TextObject 分支：检测可见文字原子的 anchor 和 bbox
  -> ImplicitVertex 分支：检测未显示 C 的线端点和折点
  -> 高召回候选 + 等价组 selector：决定哪些候选是真实顶点
  -> 对所有选中端点对读取二维 line band
  -> Node-conditioned BondObject：判断是否有键、显示类型和化学键型
  -> ChemScene/ChemSVG 确定性编译
  -> RDKit sanitize
  -> SDF
```

双键/三键按一个 Bond Object 监督，不把平行显示线当作多条化学键。文字角色和隐式
顶点分开训练。边模型枚举全部端点对，不用最近邻和键长上限。

### 四、已有实验事实

1. 文字与隐式顶点的高召回候选覆盖约 98.7%，Candidate Oracle exact 约 86.4%。
2. group selector 的单点 F1 约 97.9%，但整张图角色严格 vertex exact 只有约 56%。
3. 当提供真实端点时，Node-conditioned BondObject 在 498 张 validation 上：
   - Edge F1：99.16%；
   - skeleton exact：78.31%；
   - 双键 recall：99.04%；
   - 三键 recall：100%。
4. 换成预测端点后：
   - Vertex F1：92.85%；
   - Vertex exact：9.84%（早期版本）；
   - Edge F1：84.44%；
   - 已匹配端点条件 Edge recall：98.70%；
   - strict skeleton exact：7.83%。
5. 改进整组顶点 selector 后，角色严格 vertex exact 约 56%，strict skeleton exact
   提高到 41%–55%，Edge F1 约 95%。这说明端点集合改善会直接传导到骨架。
6. 当前最好的一组仍只有：role vertex exact 59.64%，strict skeleton exact 54.62%，
   没达到我们设定的 62% / 57% 门槛。
7. USPTO clean 1k 的稳定基线只有 192 个有效 SDF、22 个完全一致结构，说明内部组件
   指标尚未转化为公开分布的可靠端到端结果。

### 五、典型失败

1. 双键的两条平行线和拐角会被拆成多个伪顶点，例如一个双键局部可能被解释成
   4–6 个点。
2. X 形交叉处会产生并不存在的对角连接或中心伪顶点。
3. `N/H/Ph/CH3` 等字形的笔画会污染线端点检测；文字 bbox 中心又不等于化学连接
   anchor。
4. 每张图通常有 20–100 个顶点。局部 F1 很高时，只要多一个或少一个点，整图
   vertex exact 和最终 SDF 就失败，不能用独立单点概率的简单乘积理解。
5. 当前流水线存在多个顺序训练的小头和 repair，误差分布逐层变化，后面的模型无法
   恢复上游漏掉的顶点。

### 六、OCR 的最新决定

我们自研的小型 CTC 在固定 250 条容量实验能达到 100%，但跨字体开放随机字符串
exact 仍低。调研了 MarkushGrapher-2 的 ChemicalOCR：它是 256M SmolDocling VLM，
使用 235k 合成图和 7k 人工专利图训练，直接输出开放字符串和 bbox，在公开化学 OCR
benchmark 上 cell F1 为 86%–93%。我们计划把它作为可插拔 OCR 分支，而不是让结构
模型继续学习字形。

### 七、希望你重点回答

1. 根据“真实端点时边接近解决、预测端点时骨架崩溃”的证据，当前首要瓶颈是否就是
   整组顶点生成与选择？有没有相反解释？
2. 应继续采用“先顶点、后全点对读键”，还是改成“先预测完整 Bond Object，再聚类
   Bond 端点生成 Junction”？请比较两种方法对双键伪点、交叉线和长键的影响。
3. 对文字原子，是否应只用 OCR bbox 标记一个文字区域，再通过邻近键线终止位置反推
   化学 anchor，而不是使用 bbox 中心？应如何做可训练匹配？
4. 如何设计集合级或图级损失，让模型优化整张图的顶点集合和拓扑，而不是独立点分类？
   请给出具体目标、匹配方式和解码方法。
5. 是否需要联合训练 Junction 和 Bond，使边证据可以救回漏点、抑制双键内部伪点？
   如何避免联合模型重新走向全部点对的二次复杂度？
6. 请给出优先级最高的 2–3 个实验。每个实验需要说明：最小代码改动、训练数据、
   对照组、预期指标、GO/NO-GO 门槛，以及结果如何区分“思路错误”和“训练不足”。
7. 请同时考虑最终 CPU 部署，不建议依赖超过数亿参数的结构模型。

## Kimi 正式回复（整理归档）

### 总判断

证据链表明，当前问题不在“检测能力不够”，而在“把高召回候选当作独立二分类来做
整张图决策”。当前操作点上的绑定约束是集合级顶点决策；候选生成是次级上限；真实
端点下仍存在的键图错误是下一堵墙；USPTO 上的域差是独立问题。

### 1. 当前首要瓶颈

- 真实端点时 Edge F1 为 99.16%，预测端点中已匹配端点的条件 Edge recall 仍为
  98.70%，说明端点正确后大多数键可以读对。
- vertex exact 从 9.84% 提高到 59.64% 时，skeleton exact 从 7.83% 提高到
  54.62%，顶点改善几乎直接传导为骨架改善。
- Candidate Oracle exact 只有 86.4%，说明约 13.6% 的图片即使 selector 完美，也
  无法从当前候选中恢复完整真值集合。
- 当前 selector 与 oracle 之间仍有约 26.8 个百分点，集合选择是眼前最大的可提升
  部分。
- 真实端点下 skeleton exact 仍只有 78.31%，因此顶点不是唯一问题。顶点改善后，
  键存在性、键型或后续编译产生的残差会成为新瓶颈。

### 2. 顶点优先与 Bond Object 优先

Kimi 建议把中期主路线转向 Bond Object 优先，同时暂时保留顶点分支作为辅助监督：

```text
稀疏 Bond Object proposals
  -> 每个 Bond Object 的两个化学端点
  -> 端点形成 Junction
  -> 与文字区域的连接 anchor 合并
  -> 分子图
```

它给出的理由是：

- 双键应作为一个 Bond Object 预测，平行显示线的内部几何不应直接进入顶点候选。
- X 形交叉应被解释成两条穿过的笔画，若没有键在交点终止，就不应生成 Junction。
- anchor-free 的中心线和端点预测可以支持任意长度的键，避免恢复键长上限。
- 稀疏 Bond proposals 可以减少当前全点对 line-band 读取，对 CPU 部署有利。

它同时指出，Bond Object 优先会引入拥挤区端点合并风险。端点融合不能用固定半径直接
决定，而应采用可训练的端点归属，并约束每条键必须连接两个不同的 Junction。孤立原子
仍需由文字或顶点分支补充。

### 3. 文字原子的连接 anchor

Kimi 同意 OCR bbox 只表示文字区域，不能把 bbox 中心直接当作化学连接点。建议：

1. 从真值图和 Render JSON 自动导出文字区域附近的键终止点。
2. 用文字区域特征作为 query，对附近的键端点做 pointer/attention 匹配。
3. 同时预测端点是否属于该文字对象，以及连接点的坐标偏移。
4. 使用关联分类损失和坐标 Smooth-L1；一个文字对象存在多个连接时采用小集合匹配。
5. 训练时可先使用真值 bbox，推理时再替换为 ChemicalOCR bbox。

### 4. 集合级训练与解码

建议在现有 selector 上先做低成本实验：

- 保留逐候选 BCE，增加 soft-F1。
- 增加顶点数量预测，专门约束多一个或少一个点的错误。
- 从当前解码结果中构造“真集合加一个伪点、少一个真点”等困难子集。
- 训练全局集合打分器，使真集合分数比困难负集合至少高一个 margin。
- 推理不再逐点独立阈值，而是在候选子集 beam 中由全局集合分数重排。

Kimi 还建议增加 Junction-Bond 一致性约束：被选中的键必须有两个选中端点；非孤立
顶点需要至少一条一致的入射键；顶点不应落在某个完整 Bond Object 的内部显示区域。

### 5. Junction 与 Bond 联合训练

建议在稀疏 Junction candidates 与稀疏 Bond proposals 构成的二部图上做 2 到 3 轮
消息传递。强键证据可以抬高漏掉的端点，无法形成一致入射键的伪点会被压低。复杂度
应与候选键数量成正比，而不是重新对所有像素或所有点对做昂贵联合推理。

Kimi 提议用轻量 band 覆盖证据产生高召回键短名单，再运行联合网络。它特别说明，
这个步骤的动机是 CPU 部署和结构化证据，不应恢复固定键长或最近邻删边。

### 6. 三个优先实验

#### 实验一：集合级 selector

- 改动：增加 soft-F1、计数头、困难子集 margin loss 和 beam 全局解码。
- 数据：ChemVision pilot 8,974 train / 498 validation。
- 对照：59.64% role vertex exact / 54.62% strict skeleton exact。
- GO：role vertex exact 不低于 62%，且 strict skeleton exact 不低于 57%。
- NO-GO：充分收敛后两项提升均小于 2 个百分点。
- 诊断：先验证模型能否过拟合 500 张；同时统计真集合是否进入 beam，以及在 beam 中
  的排序。这样区分容量、泛化、候选缺失和解码错误。

#### 实验二：Bond Object proposal 到 Junction

- 改动：预测完整 Bond Object 及其两个化学端点，由端点归属产生 Junction；顶点分支
  保留作辅助任务。
- 数据：相同 pilot，并建立双键、交叉、长键和稠环四个错误切片。
- 对照：实验一的最优顶点优先模型。
- GO：双键切片 vertex exact 至少提高 10 个百分点，整体 skeleton exact 至少提高
  3 个百分点，且稠环端点误合并没有成为主要错误。
- 诊断：分别统计 Bond proposal recall、端点定位误差、端点归属准确率和 Junction
  聚类纯度，不能只看最终 exact。

#### 实验三：文字 anchor 反推

- 改动：增加文字区域到附近键端点的 pointer 头，监督自动从真值生成。
- 对照：bbox 中心和 bbox 边缘最近点两个基线。
- GO：文字切片 incident-edge accuracy 不低于 98%，整体 skeleton exact 至少提高
  2 个百分点。
- NO-GO：文字切片 incident-edge accuracy 低于 95%。

### 7. CPU 部署

- 核心结构模型总参数建议控制在 30M 到 50M，当前问题不是靠增加模型参数解决。
- 全点对 line-band 读取很可能比 backbone 更影响 CPU 延迟，稀疏 Bond proposals
  可将读取量降低一个数量级。
- 集合 beam、Hungarian 匹配和少量端点归属计算适合 CPU。
- 结构模型应预留 ONNX 和 INT8 路径；ChemicalOCR 作为独立可插拔模块处理。
- 建议把核心结构管线的初始部署门槛设为 4 个 CPU 线程每张 2 到 5 秒，不含 OCR。

### Kimi 给出的主路线

1. 短期先做集合级 selector，以现有 62% / 57% 门槛判断是否有效。
2. 中期验证 Bond Object 优先的 Junction 生成，目标是结构性减少双键和交叉伪点，
   同时减少 CPU 上的全点对读取。
3. 并行验证文字 bbox 到键终止点的连接 anchor。
4. 顶点门槛通过后，单独分析真实端点下仍未达到 exact 的 21.69% 图片。
5. 内部门槛通过后再处理 USPTO 域差，不使用 MR-TADF 调参。

## 项目侧判断

### 采纳

1. **瓶颈分解值得采纳。** 当前不是简单的“数据不够”或“模型太小”。应分别测量
   candidate oracle、selector、真实端点下的边图上限和公开域差。
2. **文字 bbox 与化学 anchor 分离值得采纳。** 这是现有几何定义中的明确错误，且
   可以从已有 Render JSON 自动生成监督。
3. **Bond Object 到 Junction 值得做受控 oracle 实验。** 它直接对应我们观察到的
   双键伪点和交叉伪点，也与 ChemSVG 的对象语义一致。
4. **任何新路线都必须使用错误切片和 GO/NO-GO。** 只看总体 F1 会再次掩盖多一个点、
   少一个点以及端点归属错误。

### 保留意见

1. **不能把 `0.979^N` 当作问题原因。** 它最多是独立误差假设下的量级检查。真实
   顶点错误高度相关，双键或文字区域的一次错误会同时制造多个伪点；我们的目标也不是
   靠把单点概率推到 99.9% 解决整图问题。
2. **soft-F1 和 beam 本身不会自动产生集合理解。** 如果集合分数仍是独立 logits
   的求和，beam 只是更昂贵的阈值搜索。实验一必须包含真正使用候选间、键证据和
   图一致性的全局 scorer，并报告 beam oracle。
3. **Bond-first 不会天然解决双键和交叉。** 模型仍需学会把两条平行显示线合并成一个
   化学 Bond Object，并在交叉处保持两条连续笔画。必须先做 oracle 和分层指标，不能
   根据概念图直接替换主线。
4. **真实端点下 78.31% 不能全部称为“边模型错误”。** strict skeleton 的失败还
   可能来自端点角色、坐标匹配、Bond Object 到化学键的编译或评测协议。需要按流水线
   分解后再确定责任模块。
5. **所谓稀疏短名单不能恢复 MolGrapher 式启发式删边。** 任何 band 预筛必须报告
   长键、交叉和拥挤切片的候选召回，并允许高置信视觉证据救回非局部键。

### 建议给专家重点讨论的结论

当前最值得讨论的不是“再训练多少张”，而是化学图的基本预测对象究竟应该是：

```text
A. 先预测 Junction 集合，再在全点对中读取 Bond Object

或

B. 先预测完整 Bond Object，再由其端点归属形成 Junction，
   同时保留文字/孤立原子分支
```

在决定 B 成为主线前，应先做不训练或极少训练的 oracle 分解：使用真值 Bond Object
端点测试 Junction 形成上限；再依次替换为预测端点、预测键类型和预测文字 bbox。只有
当 Bond Object 路线在双键、交叉、长键和稠环四个切片上都比当前候选体系更稳，才值得
进行完整架构迁移。
